Remote files and SSH

Browse and edit files on Amazon S3, Google Cloud Storage, OCI Object Storage, Cloudflare R2, FTP/FTPS and SFTP, and open SSH terminals from your SSH config.

Kiln browses object storage, FTP servers and SFTP hosts in the workspace inspector, next to your terminals, databases and local files. Remote files open in the same editor as local ones, and SSH hosts from your OpenSSH config are ready to pick.

Add a connection

Choose Tools → Remote connections in the titlebar, then add a named connection. The tool opens alongside your terminal task without replacing it.

Type What you provide
Amazon S3, Google Cloud Storage, OCI Object Storage, Cloudflare R2 Authentication, then a bucket
FTP / FTPS Host, port and username
SFTP / SSH A host from SSH Config host, or Enter manually

Saved connection settings contain names and addresses. Passwords and keys go to Kiln's credential store (the macOS Keychain on a Mac). See Credentials.

Object storage

Choose authentication first, then the bucket. Once authentication and any required scope are ready, Kiln loads the list of buckets in the background. If there is only one, it is selected for you.

Provider Authentication and scope
AWS S3 Saved AWS profile, Default AWS authentication, or Enter keys manually. Listing buckets needs permission to list the account's buckets.
Google Cloud Storage Native authentication lists the project you specify. The selected CLI configuration's project is filled in when available.
OCI Object Storage Native authentication needs a compartment OCID. The profile's region and namespace settings stay in effect.
Cloudflare R2 Native authentication uses the account you specify. The list covers the default jurisdiction.
S3-compatible Uses that service's bucket-list API. What you see depends on the service and your credentials.

If your credentials can reach a known bucket but cannot list buckets, use Enter manually for that bucket. A successful bucket list does not prove you can write to it.

Kiln never creates buckets, signs you in or changes your cloud credentials while it looks them up.

AWS profiles

With Saved AWS profile, Kiln reads profiles from ~/.aws/config and ~/.aws/credentials, and follows AWS_CONFIG_FILE and AWS_SHARED_CREDENTIALS_FILE if you set them. Kiln saves the profile name, not a copy of its keys, and never modifies your AWS files. A profile's region fills the region field until you edit it.

For profiles that use SSO, roles or credential_process, install AWS CLI v2 and complete the profile's usual AWS login first. Kiln resolves the credentials through the CLI when it connects. If the selected profile is unavailable or expired, you get an error. Kiln does not fall back to another account.

Endpoint, starting prefix and path-style addressing are under Advanced connection settings.

Reusable authentication

To use the same identity for several buckets, expand Save as authentication profile, give it a name and save. No bucket is needed. Select the profile again later, rename it by saving under a new name, or delete it.

Each saved bucket connection keeps its own copy of the secret it needs, so renaming or deleting a reusable profile does not break existing connections.

FTP and FTPS

Enter the host, port and username. FTPS uses explicit TLS and validates the server certificate.

Warning Plain FTP sends everything unencrypted, including your password. Use it only when your server requires it.

SFTP and SSH hosts

Pick a host from the SSH Config host dropdown. Kiln reads ~/.ssh/config and its static Include files, and fills in the host, username, port and key path. To use another config file, choose it under Advanced connection settings. To connect by hostname or IP address without an SSH alias, choose Enter manually.

Kiln only reads your SSH config. It runs no SSH commands, Match exec, authentication or network connections, so conditional settings are resolved by OpenSSH when you connect.

  • A selected host keeps its alias, jump hosts and other OpenSSH settings.
  • Fields you leave untouched follow your config at connection time.
  • Fields you edit become overrides, shared by SFTP and Open SSH terminal. Clear an override to follow the config again.
  • A key path adds an identity for OpenSSH. It does not restrict the connection to that key.

SSH terminals and host keys

Open SSH terminal opens a terminal to the same host, using the same overrides as SFTP. The SFTP browser uses OpenSSH key or agent authentication and needs a known host key. Kiln never turns off host-key verification.

For a new server:

  1. Open its SSH terminal.
  2. Check and accept the server fingerprint through OpenSSH.
  3. Reconnect the file browser.

Password-only hosts work in the SSH terminal. The SFTP browser needs key or agent authentication that runs without prompts.

Browse and edit

Select a saved connection to browse it in the inspector. The connection shows its bucket or host and the current path.

  • Double-click a folder to enter it, and use the up arrow to go back. The up control is disabled at the starting directory.
  • Use the path field, filter and refresh controls beside the file list. S3 listings show Load more when another page is available.
  • Upload, download, rename, delete and create folders from the toolbar or the context menu.

Open a file to edit it in its own tab in the main workspace, with the same editor as local files. Two remote files with the same name keep separate tabs. Browsing folders never replaces your terminal or the file you are editing.

Action What it does
Save remotely Checks that the remote file still matches the version you opened, then uploads your changes
Keep local copy Saves a copy without writing to the server

Remote editing is limited to 8 MB. Download larger or non-text files and work on them locally. Unsaved remote text is kept with Kiln's saved work, and restoring it never uploads anything on its own. If you change a connection's settings after opening a file, remote saves for that file are blocked and your local draft stays available.

To pick up changed connection settings, choose Reconnect. It reloads the saved profile and credentials and returns to the starting directory. Reconnect is unavailable while you are editing or transferring.

Transfers

Transfers run in the background and keep going while the inspector is hidden. Kiln shows their progress, and you can cancel them.

  • Upload several files with the picker or by dropping them on the file list. They transfer in order, and Kiln asks before replacing existing files.
  • Cancelling stops the rest of the upload queue. The current step may take a moment to finish.
  • Downloads replace the local file only after they complete.
  • Only empty folders can be deleted. There is no hidden recursive delete.
  • After a cancel or a server error, refresh to see the actual remote state.

Wait for transfers to finish, or cancel them, before you close the workspace or quit. A transfer recovered after a restart is a notice to check its result. Kiln never retries it automatically.

S3 limits

  • Uploads and renames support objects up to 5 GiB.
  • Folder prefixes cannot be renamed.
  • Rename is a copy followed by a delete. The source is deleted only after the copy succeeds.

Credentials

Edit a saved connection to replace its credentials.

  • In manual-key mode, empty fields keep the saved keys. Enter the access key and secret key together to replace them.
  • Replacing S3 keys clears the old session token unless you enter a new one under Temporary session token.
  • Switching to a saved profile or default AWS credentials removes the manual keys Kiln stored.
  • FTP connections offer Remove saved credentials in the edit form.
  • Changing the connection type clears the earlier protocol's credentials.

Windows

  • SFTP and SSH use Windows OpenSSH, and C:\… paths in your SSH config work as written.
  • Cloud CLIs installed as .cmd shims are found through PATHEXT, and the gcloud and Wrangler folders follow %APPDATA%.

원격 파일과 SSH

Amazon S3, Google Cloud Storage, OCI Object Storage, Cloudflare R2, FTP/FTPS, SFTP의 파일을 살펴보고 편집하며, SSH 설정에 있는 호스트로 SSH 터미널을 엽니다.

Kiln의 워크스페이스 인스펙터에서는 터미널, 데이터베이스, 로컬 파일과 함께 오브젝트 스토리지, FTP 서버, SFTP 호스트도 살펴볼 수 있습니다. 원격 파일은 로컬 파일과 같은 편집기에서 열리고, OpenSSH 설정에 있는 SSH 호스트는 바로 골라 쓸 수 있습니다.

연결 추가하기

제목 표시줄에서 도구 → 원격 연결을 선택한 뒤, 이름을 붙여 연결을 추가합니다. 이 도구는 터미널 작업을 가리지 않고 그 옆에 열립니다.

유형 입력할 정보
Amazon S3, Google Cloud Storage, OCI Object Storage, Cloudflare R2 인증 정보, 그다음 버킷
FTP / FTPS 호스트, 포트, 사용자 이름
SFTP / SSH SSH Config 호스트에서 고른 호스트, 또는 직접 입력

저장된 연결 설정에는 이름과 주소가 들어 있습니다. 비밀번호와 키는 Kiln의 자격 증명 저장소(Mac에서는 macOS 키체인)에 보관됩니다. 자격 증명을 참고하세요.

오브젝트 스토리지

인증 방식을 먼저 고르고, 그다음 버킷을 고릅니다. 인증과 필요한 범위 설정이 끝나면 Kiln이 백그라운드에서 버킷 목록을 불러옵니다. 버킷이 하나뿐이면 자동으로 선택됩니다.

제공자 인증과 범위
AWS S3 저장된 AWS 프로필, 기본 AWS 인증, 직접 키 입력 중 하나를 고릅니다. 버킷 목록을 불러오려면 계정의 버킷을 나열할 권한이 있어야 합니다.
Google Cloud Storage 네이티브 인증은 지정한 프로젝트의 버킷을 나열합니다. 가능하면 선택한 CLI 구성의 프로젝트가 자동으로 채워집니다.
OCI Object Storage 네이티브 인증에는 컴파트먼트 OCID가 필요합니다. 프로필의 리전과 네임스페이스 설정은 그대로 적용됩니다.
Cloudflare R2 네이티브 인증은 지정한 계정을 사용합니다. 목록에는 기본 관할 구역의 버킷이 나옵니다.
S3 호환(S3-compatible) 해당 서비스의 버킷 목록 API를 사용합니다. 무엇이 보이는지는 서비스와 자격 증명에 따라 다릅니다.

자격 증명으로 특정 버킷에는 접근할 수 있지만 버킷 목록은 불러올 수 없다면, 그 버킷은 직접 입력으로 지정하세요. 버킷 목록을 불러왔다고 해서 그 버킷에 쓸 수 있다는 보장은 없습니다.

Kiln은 버킷을 조회하는 동안 버킷을 만들거나, 로그인을 진행하거나, 클라우드 자격 증명을 바꾸지 않습니다.

AWS 프로필

저장된 AWS 프로필을 선택하면 Kiln은 ~/.aws/config와 ~/.aws/credentials에서 프로필을 읽고, AWS_CONFIG_FILE과 AWS_SHARED_CREDENTIALS_FILE이 설정되어 있으면 그 경로를 따릅니다. Kiln은 키 사본이 아니라 프로필 이름만 저장하며, AWS 파일은 수정하지 않습니다. 리전 필드에는 프로필의 리전이 채워지며, 직접 고치면 그 값을 씁니다.

SSO, 역할, credential_process를 쓰는 프로필이라면 AWS CLI v2를 설치하고, 그 프로필로 평소처럼 AWS 로그인을 먼저 마치세요. Kiln은 연결할 때 CLI를 통해 자격 증명을 가져옵니다. 선택한 프로필을 쓸 수 없거나 만료되었으면 오류가 표시되며, Kiln이 다른 계정으로 대신 연결하지는 않습니다.

엔드포인트, 시작 접두사, path-style 주소 지정은 고급 연결 설정에 있습니다.

인증 재사용하기

여러 버킷에 같은 인증 정보를 쓰려면 인증 프로필로 저장을 펼치고 이름을 붙여 저장합니다. 버킷은 지정하지 않아도 됩니다. 저장한 프로필은 나중에 다시 선택하거나, 새 이름으로 저장해 이름을 바꾸거나, 삭제할 수 있습니다.

저장된 버킷 연결은 필요한 비밀 정보의 사본을 각자 따로 가지고 있으므로, 재사용 프로필의 이름을 바꾸거나 삭제해도 기존 연결은 그대로 동작합니다.

FTP와 FTPS

호스트, 포트, 사용자 이름을 입력합니다. FTPS는 명시적 TLS를 사용하며 서버 인증서를 검증합니다.

주의 일반 FTP는 비밀번호를 포함한 모든 내용을 암호화하지 않고 보냅니다. 서버가 요구할 때만 사용하세요.

SFTP와 SSH 호스트

SSH Config 호스트 드롭다운에서 호스트를 고릅니다. Kiln은 ~/.ssh/config와 거기서 정적으로 Include하는 파일을 읽어 호스트, 사용자 이름, 포트, 키 경로를 채웁니다. 다른 설정 파일을 쓰려면 고급 연결 설정에서 고르세요. SSH 별칭 없이 호스트 이름이나 IP 주소로 연결하려면 직접 입력을 선택합니다.

Kiln은 SSH 설정을 읽기만 합니다. SSH 명령, Match exec, 인증, 네트워크 연결을 실행하지 않으므로, 조건부 설정은 연결할 때 OpenSSH가 해석합니다.

  • 선택한 호스트는 별칭, 점프 호스트, 그 밖의 OpenSSH 설정을 그대로 유지합니다.
  • 건드리지 않은 필드는 연결할 때의 설정 파일 내용을 따릅니다.
  • 직접 고친 필드는 재정의 값이 되며, SFTP와 SSH 터미널 열기에 함께 적용됩니다. 재정의 값을 지우면 다시 설정 파일을 따릅니다.
  • 키 경로를 지정하면 OpenSSH에 인증 키가 하나 추가될 뿐, 그 키로만 연결하도록 제한하지는 않습니다.

SSH 터미널과 호스트 키

SSH 터미널 열기를 선택하면 SFTP와 같은 재정의 값으로 같은 호스트에 터미널을 엽니다. SFTP 브라우저는 OpenSSH 키 인증이나 에이전트 인증을 쓰며, 알려진 호스트 키가 있어야 합니다. Kiln은 호스트 키 검증을 끄지 않습니다.

새 서버라면 다음 순서로 진행하세요.

  1. 해당 서버의 SSH 터미널 열기를 선택합니다.
  2. OpenSSH에서 서버 지문을 확인하고 수락합니다.
  3. 파일 브라우저를 다시 연결합니다.

비밀번호로만 로그인하는 호스트는 SSH 터미널에서 쓸 수 있습니다. SFTP 브라우저를 쓰려면 입력 요청 없이 진행되는 키 인증이나 에이전트 인증이 필요합니다.

살펴보기와 편집

저장된 연결을 선택하면 인스펙터에서 내용을 살펴볼 수 있습니다. 연결에는 버킷이나 호스트, 현재 경로가 표시됩니다.

  • 폴더를 더블클릭해 들어가고, 위쪽 화살표로 상위 폴더로 돌아갑니다. 시작 디렉터리에서는 위로 이동 버튼이 비활성화됩니다.
  • 파일 목록 옆의 경로 입력란, 필터, 새로 고침 버튼을 사용할 수 있습니다. S3 목록에 다음 페이지가 있으면 더 불러오기가 나타납니다.
  • 도구 모음이나 컨텍스트 메뉴에서 업로드, 다운로드, 이름 변경, 삭제, 폴더 만들기를 할 수 있습니다.

파일을 열면 메인 워크스페이스의 별도 탭에서, 로컬 파일과 같은 편집기로 편집합니다. 이름이 같은 원격 파일 두 개는 각각 다른 탭에 열립니다. 폴더를 탐색해도 터미널이나 편집 중인 파일은 바뀌지 않습니다.

동작 하는 일
원격 저장 원격 파일이 열었을 때의 버전과 여전히 같은지 확인한 뒤 변경 사항을 업로드합니다
로컬에 보관 서버에 쓰지 않고 사본을 저장합니다

원격 편집은 8 MB까지 가능합니다. 이보다 크거나 텍스트가 아닌 파일은 내려받아 로컬에서 작업하세요. 저장하지 않은 원격 텍스트는 Kiln의 저장된 작업과 함께 보관되며, 복원할 때 저절로 업로드되지는 않습니다. 파일을 연 뒤 연결 설정을 바꾸면 그 파일은 원격에 저장할 수 없게 되지만, 로컬 초안은 계속 쓸 수 있습니다.

바뀐 연결 설정을 반영하려면 재연결을 선택합니다. 저장된 프로필과 자격 증명을 다시 불러오고 시작 디렉터리로 돌아갑니다. 편집하거나 전송하는 중에는 재연결할 수 없습니다.

전송

전송은 백그라운드에서 실행되며, 인스펙터를 숨겨도 계속됩니다. Kiln에 진행 상황이 표시되며, 전송을 취소할 수도 있습니다.

  • 파일 선택기를 쓰거나 파일 목록에 끌어다 놓아 여러 파일을 한 번에 업로드할 수 있습니다. 파일은 순서대로 전송되며, 기존 파일을 덮어쓰기 전에 확인을 받습니다.
  • 취소하면 업로드 대기열에 남은 파일은 전송되지 않습니다. 진행 중인 단계는 끝나기까지 잠시 걸릴 수 있습니다.
  • 다운로드는 완료된 뒤에야 로컬 파일을 교체합니다.
  • 빈 폴더만 삭제할 수 있습니다. 하위 항목까지 몰래 지우는 재귀 삭제는 없습니다.
  • 취소했거나 서버 오류가 났다면 새로 고쳐서 실제 원격 상태를 확인하세요.

워크스페이스를 닫거나 앱을 종료하기 전에 전송이 끝나기를 기다리거나 전송을 취소하세요. 재시작한 뒤 복구된 전송은 결과를 확인하라는 안내일 뿐이며, Kiln이 자동으로 다시 시도하지 않습니다.

S3 제한 사항

  • 업로드와 이름 변경은 5 GiB 이하의 객체까지 지원합니다.
  • 폴더 접두사는 이름을 바꿀 수 없습니다.
  • 이름 변경은 복사한 뒤 삭제하는 방식입니다. 원본은 복사가 성공해야만 삭제됩니다.

자격 증명

자격 증명을 바꾸려면 저장된 연결을 편집합니다.

  • 직접 키 입력 모드에서 필드를 비워 두면 저장된 키가 그대로 유지됩니다. 키를 바꾸려면 액세스 키와 시크릿 키를 함께 입력하세요.
  • S3 키를 바꾸면, 임시 세션 토큰에 새 값을 입력하지 않는 한 기존 세션 토큰은 지워집니다.
  • 저장된 프로필이나 기본 AWS 인증으로 바꾸면 Kiln에 저장해 둔 직접 입력 키가 삭제됩니다.
  • FTP 연결의 편집 양식에는 저장된 자격증명 제거가 있습니다.
  • 연결 유형을 바꾸면 이전 프로토콜의 자격 증명이 지워집니다.

Windows

  • SFTP와 SSH는 Windows OpenSSH를 사용하며, SSH 설정에 적힌 C:\… 경로도 그대로 동작합니다.
  • .cmd shim으로 설치된 클라우드 CLI는 PATHEXT를 통해 찾고, gcloud와 Wrangler 폴더는 %APPDATA% 기준으로 찾습니다.

ドキュメントツール

リモートファイルと SSH

Amazon S3、Google Cloud Storage、OCI Object Storage、Cloudflare R2、FTP/FTPS、SFTP 上のファイルの閲覧・編集と、SSH config のホストで SSH ターミナルを開く方法を説明します。

Kiln では、オブジェクトストレージ、FTP サーバー、SFTP ホストを、ターミナルやデータベース、ローカルファイルと同じワークスペースインスペクターで閲覧できます。リモートファイルはローカルのファイルと同じエディターで開けます。OpenSSH の config にある SSH ホストは、一覧から選ぶだけで使えます。

接続を追加する

タイトルバーでツール → リモート接続を選び、名前付きの接続を追加します。このツールはターミナルの作業を置き換えず、その横に開きます。

種類 入力するもの
Amazon S3、Google Cloud Storage、OCI Object Storage、Cloudflare R2 認証を設定してからバケット
FTP / FTPS ホスト、ポート、ユーザー名
SFTP / SSH SSH Config のホストから選んだホスト、または手動入力

保存される接続設定に含まれるのは、名前とアドレスです。パスワードと鍵は Kiln の認証情報ストア（Mac では macOS キーチェーン）に保存されます。詳しくは認証情報を参照してください。

オブジェクトストレージ

まず認証を選び、次にバケットを選びます。認証と必要なスコープの準備ができると、Kiln はバックグラウンドでバケットの一覧を読み込みます。バケットが 1 つだけの場合は自動で選択されます。

プロバイダー 認証とスコープ
AWS S3 保存済みAWSプロファイル、既定のAWS認証、またはキーを直接入力。バケットの一覧を取得するには、アカウントのバケットを一覧表示する権限が必要です。
Google Cloud Storage ネイティブ認証では、指定したプロジェクトのバケットを一覧表示します。選択中の CLI 構成のプロジェクトがあれば、自動で入力されます。
OCI Object Storage ネイティブ認証にはコンパートメント OCID が必要です。プロファイルのリージョンとネームスペースの設定はそのまま適用されます。
Cloudflare R2 ネイティブ認証では、指定したアカウントを使います。一覧の対象は既定の管轄区域です。
S3 互換 (S3-compatible) そのサービスのバケット一覧 API を使います。表示される内容はサービスと認証情報によって異なります。

認証情報で特定のバケットにはアクセスできるのに、バケットの一覧は取得できない場合は、手動入力でそのバケットを指定します。バケットの一覧を取得できても、そのバケットに書き込めるとは限りません。

バケットを探す間に、Kiln がバケットを作成したり、ログインしたり、クラウドの認証情報を変更したりすることはありません。

AWS プロファイル

保存済みAWSプロファイルを選ぶと、Kiln は ~/.aws/config と ~/.aws/credentials からプロファイルを読み込みます。AWS_CONFIG_FILE と AWS_SHARED_CREDENTIALS_FILE を設定している場合はそれに従います。Kiln が保存するのはプロファイル名だけで、鍵のコピーは保存しません。AWS のファイルを変更することもありません。リージョン欄には、自分で編集するまでプロファイルのリージョンが入ります。

SSO、ロール、credential_process を使うプロファイルでは、AWS CLI v2 をインストールし、そのプロファイルの通常の AWS ログインを先に完了してください。Kiln は接続時に CLI を通じて認証情報を解決します。選択したプロファイルが使えないか期限切れの場合は、エラーが表示されます。Kiln が別のアカウントに切り替えることはありません。

エンドポイント、開始プレフィックス、パススタイルのアドレス指定は、詳細接続設定にあります。

再利用できる認証

同じ認証を複数のバケットで使うには、認証プロファイルとして保存を展開し、名前を付けて保存します。バケットは必要ありません。後でそのプロファイルを選び直したり、新しい名前で保存して名前を変えたり、削除したりできます。

保存したバケット接続は、必要なシークレットのコピーをそれぞれ持つので、再利用できるプロファイルの名前を変えたり削除したりしても、既存の接続には影響しません。

FTP と FTPS

ホスト、ポート、ユーザー名を入力します。FTPS は明示的な TLS を使い、サーバー証明書を検証します。

警告 通常の FTP は、パスワードを含むすべてのデータを暗号化せずに送信します。サーバーが必要とする場合にだけ使ってください。

SFTP と SSH ホスト

SSH Config のホストのドロップダウンからホストを選びます。Kiln は ~/.ssh/config と、その中の静的な Include ファイルを読み、ホスト、ユーザー名、ポート、鍵のパスを入力します。別の config ファイルを使うには、詳細接続設定で選びます。SSH のエイリアスを使わずにホスト名や IP アドレスで接続するには、手動入力を選びます。

Kiln は SSH の config を読むだけです。SSH コマンド、Match exec、認証、ネットワーク接続は一切実行しないため、条件付きの設定は接続時に OpenSSH が解決します。

  • 選んだホストは、エイリアス、ジャンプホスト、その他の OpenSSH の設定を保持します。
  • 変更しなかったフィールドは、接続時点の config の内容に従います。
  • 編集したフィールドは上書き設定となり、SFTP と SSH ターミナルを開くで共有されます。上書きをクリアすると、再び config に従います。
  • 鍵のパスを指定すると、OpenSSH に ID が追加されます。接続をその鍵だけに限定するものではありません。

SSH ターミナルとホスト鍵

SSH ターミナルを開くは、SFTP と同じ上書き設定を使って、同じホストへのターミナルを開きます。SFTP ブラウザーは OpenSSH の鍵またはエージェントによる認証を使い、既知のホスト鍵が必要です。Kiln がホスト鍵の検証を無効にすることはありません。

新しいサーバーに接続するときは、次の手順に従います。

  1. その SSH ターミナルを開きます。
  2. OpenSSH でサーバーのフィンガープリントを確認し、受け入れます。
  3. ファイルブラウザーを再接続します。

パスワード認証のみのホストは、SSH ターミナルで使えます。SFTP ブラウザーには、入力を求められずに完了する鍵またはエージェントによる認証が必要です。

閲覧と編集

保存済みの接続を選ぶと、インスペクターで閲覧できます。接続には、バケットまたはホストと現在のパスが表示されます。

  • フォルダーをダブルクリックすると中に入り、上矢印で上の階層に戻ります。開始ディレクトリでは、上へ移動するボタンは無効になります。
  • ファイル一覧の横には、パス欄、フィルター、更新ボタンがあります。S3 の一覧では、次のページがあるときにさらに読み込むが表示されます。
  • アップロード、ダウンロード、名前の変更、削除、フォルダーの作成は、ツールバーまたはコンテキストメニューから行います。

ファイルを開くと、メインのワークスペースにある専用のタブで、ローカルのファイルと同じエディターを使って編集できます。同じ名前のリモートファイルが 2 つあっても、タブは別々です。フォルダーを閲覧しても、ターミナルや編集中のファイルが置き換わることはありません。

操作 内容
リモート保存 開いたときのバージョンとリモートのファイルが一致していることを確認してから、変更をアップロードします
ローカルに保管 サーバーに書き込まずにコピーを保存します

リモートでの編集は 8 MB までです。それより大きいファイルやテキスト以外のファイルはダウンロードし、ローカルで作業してください。未保存のリモートのテキストは Kiln の保存済みの作業と一緒に保持され、復元しても勝手にアップロードされることはありません。ファイルを開いた後に接続の設定を変更すると、そのファイルはリモートに保存できなくなりますが、ローカルの下書きは引き続き使えます。

変更した接続設定を反映するには、再接続を選びます。保存済みのプロファイルと認証情報を再読み込みし、開始ディレクトリに戻ります。編集中や転送中は再接続できません。

転送

転送はバックグラウンドで実行され、インスペクターを非表示にしても続きます。Kiln に進行状況が表示され、キャンセルもできます。

  • ファイル選択画面を使うか、ファイル一覧にドロップして、複数のファイルをアップロードできます。ファイルは順番に転送され、既存のファイルを置き換える前に確認が表示されます。
  • キャンセルすると、キューに残っているアップロードは中止されます。処理中のステップが終わるまで、少し時間がかかることがあります。
  • ダウンロードでは、完了した時点で初めてローカルのファイルが置き換わります。
  • 削除できるのは空のフォルダーだけです。中身ごと再帰的に削除するような隠れた動作はありません。
  • キャンセルやサーバーエラーの後は、更新して実際のリモートの状態を確認してください。

ワークスペースを閉じたり終了したりする前に、転送が終わるのを待つか、キャンセルしてください。再起動後に復元された転送は、結果の確認を促す通知として表示されます。Kiln が自動で再試行することはありません。

S3 の制限

  • アップロードと名前の変更は、5 GiB までのオブジェクトに対応しています。
  • フォルダーのプレフィックスは名前を変更できません。
  • 名前の変更は、コピーと削除の組み合わせで行われます。コピーが成功した後にだけ、元のオブジェクトが削除されます。

認証情報

保存済みの接続を編集すると、その認証情報を置き換えられます。

  • 手動キーのモードでは、フィールドを空欄のままにすると、保存済みのキーがそのまま使われます。置き換えるには、アクセスキーとシークレットキーを両方入力してください。
  • S3 のキーを置き換えると、一時セッショントークンに新しい値を入力しない限り、古いセッショントークンはクリアされます。
  • 保存済みプロファイルや既定の AWS 認証情報に切り替えると、Kiln が保存していた手動のキーは削除されます。
  • FTP の接続では、編集フォームに保存済みの認証情報を削除があります。
  • 接続の種類を変更すると、以前のプロトコルの認証情報はクリアされます。

Windows

  • SFTP と SSH は Windows の OpenSSH を使い、SSH config 内の C:\… のパスは書かれたとおりに動作します。
  • .cmd シムとしてインストールされたクラウド CLI も、PATHEXT によって検出されます。gcloud と Wrangler のフォルダーは %APPDATA% を基準にします。

文档工具

远程文件与 SSH

浏览和编辑 Amazon S3、Google Cloud Storage、OCI Object Storage、Cloudflare R2、FTP/FTPS 和 SFTP 上的文件，并直接从 SSH 配置打开 SSH 终端。

在 Kiln 的工作区检查器中，可以浏览对象存储、FTP 服务器和 SFTP 主机，它们与终端、数据库和本地文件并列。远程文件和本地文件在同一个编辑器中打开，OpenSSH 配置里的 SSH 主机可以直接选用。

添加连接

在标题栏中选择工具 → 远程连接，然后添加一个命名连接。该工具在终端任务旁边打开，不会替换终端任务。

类型 需要提供
Amazon S3、Google Cloud Storage、OCI Object Storage、Cloudflare R2 身份验证，然后选择存储桶
FTP / FTPS 主机、端口和用户名
SFTP / SSH 从 SSH Config 主机中选择主机，或选择手动输入

保存的连接设置只包含名称和地址。密码和密钥存放在 Kiln 的凭据存储中（Mac 上是 macOS 钥匙串）。详见凭据。

对象存储

先选择身份验证方式，再选择存储桶。身份验证和所需的范围就绪后，Kiln 会在后台加载存储桶列表。如果只有一个存储桶，会自动选中它。

提供商 身份验证与范围
AWS S3 已保存的 AWS 配置、默认 AWS 认证或手动输入密钥。列出存储桶需要具备列出该账户存储桶的权限。
Google Cloud Storage 原生身份验证会列出你指定的项目。能获取时，会自动填入所选 CLI 配置中的项目。
OCI Object Storage 原生身份验证需要 compartment OCID。配置中的区域和命名空间设置依然有效。
Cloudflare R2 原生身份验证使用你指定的账户。列表涵盖默认管辖区。
S3 兼容服务 (S3-compatible) 使用该服务的存储桶列表 API。能看到哪些内容，取决于该服务和你的凭据。

如果凭据能访问某个已知的存储桶，却无法列出存储桶，请对该存储桶使用手动输入。能列出存储桶，并不代表可以写入。

查找存储桶时，Kiln 绝不会创建存储桶、替你登录或更改你的云凭据。

AWS 配置

使用已保存的 AWS 配置时，Kiln 从 ~/.aws/config 和 ~/.aws/credentials 读取配置；如果设置了 AWS_CONFIG_FILE 和 AWS_SHARED_CREDENTIALS_FILE，也会遵循。Kiln 只保存配置名称，不复制其中的密钥，也绝不会修改你的 AWS 文件。配置中的区域会自动填入区域字段，直到你手动修改。

如果配置使用 SSO、角色或 credential_process，请安装 AWS CLI v2，并先按平常的方式完成该配置的 AWS 登录。Kiln 在连接时通过 CLI 解析凭据。所选配置不可用或已过期时，会显示错误，Kiln 不会改用其他账户。

端点、起始前缀和路径样式寻址位于高级连接设置下。

可复用的身份验证

要让多个存储桶使用同一身份，展开保存为身份验证配置，命名后保存即可，不需要指定存储桶。之后可以再次选用该配置，以新名称另存来重命名，或者删除它。

每个已保存的存储桶连接都各自保存一份所需密钥，因此重命名或删除可复用的配置，不会影响现有连接。

FTP 和 FTPS

输入主机、端口和用户名。FTPS 使用显式 TLS，并验证服务器证书。

警告 普通 FTP 不加密传输任何内容，包括你的密码。仅在服务器要求时使用。

SFTP 和 SSH 主机

从 SSH Config 主机下拉列表中选择主机。Kiln 读取 ~/.ssh/config 及其静态 Include 文件，并填入主机、用户名、端口和密钥路径。要使用其他配置文件，在高级连接设置下选择。要不经 SSH 别名、直接用主机名或 IP 地址连接，选择手动输入。

Kiln 只读取 SSH 配置，不会运行 SSH 命令、Match exec、身份验证或网络连接，因此条件设置会在连接时交由 OpenSSH 解析。

  • 选中的主机保留其别名、跳板主机和其他 OpenSSH 设置。
  • 未改动的字段在连接时以配置文件为准。
  • 编辑过的字段会成为覆盖值，由 SFTP 和打开 SSH 终端共用。清除覆盖值后，即恢复以配置文件为准。
  • 密钥路径会为 OpenSSH 增加一个身份，但不会限定连接只能使用这个密钥。

SSH 终端与主机密钥

打开 SSH 终端会使用与 SFTP 相同的覆盖值，打开一个连接到同一主机的终端。SFTP 浏览器使用 OpenSSH 密钥或 agent 身份验证，并且要求主机密钥已知。Kiln 绝不会关闭主机密钥验证。

连接新服务器时：

  1. 打开它的 SSH 终端。
  2. 通过 OpenSSH 核对并接受服务器指纹。
  3. 让文件浏览器重新连接。

只支持密码登录的主机可以在 SSH 终端中使用。SFTP 浏览器需要无需交互提示就能完成的密钥或 agent 身份验证。

浏览与编辑

选择已保存的连接，即可在检查器中浏览。连接会显示其存储桶或主机，以及当前路径。

  • 双击文件夹进入，点击向上箭头返回。位于起始目录时，向上按钮不可用。
  • 文件列表旁有路径字段、筛选和刷新控件。还有下一页时，S3 列表会显示加载更多。
  • 上传、下载、重命名、删除文件和新建文件夹，都可以通过工具栏或右键菜单完成。

打开文件后，它会在主工作区中以单独的标签页打开，使用与本地文件相同的编辑器。两个同名的远程文件也会各占一个标签页。浏览文件夹绝不会替换终端或正在编辑的文件。

操作 作用
远程保存 先检查远程文件是否仍是你打开时的版本，再上传更改
保留本地副本 保存一份副本，不写入服务器

远程编辑的文件上限为 8 MB。更大的文件或非文本文件，请下载后在本地处理。未保存的远程文本会随 Kiln 保存的工作一起保留，恢复时也不会自行上传任何内容。如果打开文件后更改了连接设置，该文件将无法远程保存，但本地草稿仍然可用。

要让更改后的连接设置生效，选择重新连接。它会重新加载已保存的配置和凭据，并回到起始目录。编辑或传输期间无法重新连接。

传输

传输在后台进行，检查器隐藏时也会继续。Kiln 会显示传输进度，你也可以随时取消。

  • 用文件选择器或把文件拖到文件列表上，可以一次上传多个文件。文件按顺序传输，替换现有文件前 Kiln 会先询问。
  • 取消会停止上传队列中剩余的文件。当前步骤可能需要一点时间才能结束。
  • 下载只有在完成后才会替换本地文件。
  • 只能删除空文件夹，不存在隐式的递归删除。
  • 取消传输或遇到服务器错误后，请刷新以查看远程的实际状态。

关闭工作区或退出前，请等传输完成，或者取消传输。重启后恢复的传输只是一条提醒，提示你检查结果，Kiln 绝不会自动重试。

S3 限制

  • 上传和重命名支持最大 5 GiB 的对象。
  • 无法重命名文件夹前缀。
  • 重命名是先复制再删除，复制成功后才会删除源对象。

凭据

编辑已保存的连接即可替换其凭据。

  • 在手动输入密钥模式下，留空的字段会保留已保存的密钥。要替换，请同时输入访问密钥和私有密钥。
  • 替换 S3 密钥会清除旧的会话令牌，除非在临时会话令牌中输入新的令牌。
  • 切换到已保存的配置或默认 AWS 凭据时，Kiln 会删除之前存储的手动密钥。
  • FTP 连接的编辑表单中提供移除已保存的凭据。
  • 更改连接类型会清除原协议的凭据。

Windows

  • SFTP 和 SSH 使用 Windows OpenSSH，SSH 配置中的 C:\… 路径可以照原样使用。
  • 以 .cmd 包装脚本形式安装的云 CLI 会通过 PATHEXT 找到，gcloud 和 Wrangler 的文件夹遵循 %APPDATA%。
