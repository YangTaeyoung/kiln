DocumentationGet started

AI agent IDE: getting started

Kiln is a terminal-first IDE for agent work that keeps terminals, AI agents, Git, files and databases in one native workspace.

Kiln is a terminal-first IDE for agent work. It brings terminals, AI agents, Git, files and databases into one native app for macOS and Windows, so the whole task stays in view.

Open a single repository, or a parent folder that holds your frontend, backend and shared libraries. Run Claude Code, Codex or Antigravity in a terminal panel, watch which tasks need you, and review the result without leaving the window.

Core concepts

Workspace

A workspace is a named view of a folder. It keeps its own tasks, terminal sessions, split layout and unsent requests. One folder can have several workspaces, for example API review and Documentation, and each one is restored independently when Kiln reopens. Files and Git history belong to the folder, so every workspace for that folder shares them.

The folder can be one repository or a parent directory with several repositories. Your agent works from that shared root, while Git operations target the repository you select. See Workspaces and tasks.

Task

A task is the work running in a workspace's terminal: a shell you use directly, or an agent you start with New Task. The sidebar lists tasks under each workspace and shows their reported state:

State Meaning
Working The agent or command reports that it is working.
Waiting for Input The agent is waiting for your answer.
Done The agent reported that it finished.
Failed The agent or command reported a failure.

When a session does not report its state, Kiln shows it as an open session instead of guessing from terminal output. An idle terminal is not treated as a completed task. Click a task to jump straight to its workspace, tab and split.

Panels and splits

Each terminal lives in a panel. Panel headers have controls to split right, split down and close. Drag a panel's title onto another panel to rearrange the layout; the move keeps the terminal session and its running process. See Splits and pane layout.

Inspector and tools

The right-hand workspace inspector holds Files, Changes, GitHub and a database icon for connections, tables and SQL consoles. The titlebar Tools menu lists files, search, source control, GitHub, databases, remote connections and problems together, and opens each one alongside your current work. In compact windows, Back to Task returns you to the terminal.

Session daemon

A separate local daemon owns your terminals. Closing the Kiln window leaves its shells and agents running, and reopening Kiln brings you back to them. Updates keep running terminals alive too. A system reboot or explicitly stopping the daemon is different from closing the window and can end sessions. See Sessions that outlive the window.

Notifications

Agents and scripts can report activity and send notifications through local terminal escape sequences or the kiln activity and kiln notify commands. These do not send your prompt to another service. The notification center keeps recent notifications and links each one to its session, and reading a notification clears that session's attention state. On Windows, agent notifications also appear as Windows toasts. See Terminal.

What you need

  • macOS 11 or later on Apple Silicon, or Windows 11 on x64 or ARM64.
  • The agent CLIs you plan to use: Claude Code, Codex or Antigravity (agy), plus gh for GitHub. Kiln does not include a subscription to any agent. Install and sign in to the tools you use.

The app is available in English, Korean, Japanese and Simplified Chinese.

문서시작하기

AI 에이전트 IDE 시작하기

Kiln은 에이전트 작업을 위한 터미널 중심 IDE로, 터미널·AI 에이전트·Git·파일·데이터베이스를 네이티브 워크스페이스 하나에 담습니다.

Kiln은 에이전트 작업을 위한 터미널 중심 IDE입니다. 터미널, AI 에이전트, Git, 파일, 데이터베이스를 macOS·Windows용 네이티브 앱 하나에 모아 두므로 작업 전체가 한눈에 들어옵니다.

저장소 하나를 열어도 되고, 프론트엔드·백엔드·공유 라이브러리를 담은 상위 폴더를 열어도 됩니다. 터미널 패널에서 Claude Code, Codex, Antigravity를 실행하고, 내 응답이 필요한 작업을 확인하고, 창을 떠나지 않고 결과를 검토하세요.

핵심 개념

워크스페이스

워크스페이스는 폴더에 이름을 붙여 만든 보기입니다. 작업, 터미널 세션, 분할 레이아웃, 보내지 않은 요청을 워크스페이스마다 따로 관리합니다. 한 폴더에 API 리뷰, 문서처럼 워크스페이스를 여러 개 둘 수 있고, Kiln을 다시 열면 각각 따로 복원됩니다. 파일과 Git 기록은 폴더에 속하므로 같은 폴더의 워크스페이스는 모두 이를 공유합니다.

폴더는 저장소 하나여도 되고, 여러 저장소를 담은 상위 디렉터리여도 됩니다. 에이전트는 이 공유 루트에서 작업하고, Git 작업은 선택한 저장소에 적용됩니다. 자세한 내용은 워크스페이스와 작업을 참고하세요.

작업

작업은 워크스페이스의 터미널에서 돌아가는 일입니다. 직접 쓰는 셸일 수도 있고, 새 작업으로 시작한 에이전트일 수도 있습니다. 사이드바에는 워크스페이스별로 작업이 나열되고, 각 작업이 보고한 상태가 함께 표시됩니다.

상태 의미
작업 중 에이전트나 명령이 작업 중이라고 보고했습니다.
입력 대기 에이전트가 내 답변을 기다리고 있습니다.
완료 에이전트가 작업을 마쳤다고 보고했습니다.
실패 에이전트나 명령이 실패를 보고했습니다.

세션이 상태를 보고하지 않으면 Kiln은 터미널 출력으로 짐작하지 않고 열린 세션으로 표시합니다. 유휴 상태의 터미널을 완료된 작업으로 보지 않습니다. 작업을 클릭하면 해당 워크스페이스, 탭, 분할 화면으로 바로 이동합니다.

패널과 분할 화면

터미널마다 패널이 하나씩 있습니다. 패널 헤더에는 오른쪽으로 나누기, 아래로 나누기, 닫기 버튼이 있습니다. 패널 제목을 다른 패널로 끌어다 놓으면 레이아웃을 바꿀 수 있고, 옮겨도 터미널 세션과 실행 중인 프로세스는 그대로입니다. 자세한 내용은 분할 화면과 패널 레이아웃을 참고하세요.

인스펙터와 도구

오른쪽 워크스페이스 인스펙터에는 파일, 변경, GitHub와 데이터베이스 아이콘이 있습니다. 데이터베이스 아이콘에서는 연결, 테이블, SQL 콘솔을 엽니다. 제목 표시줄의 도구 메뉴에는 파일, 검색, 소스 제어, GitHub, 데이터베이스, 원격 연결, 문제가 한데 모여 있고, 무엇을 고르든 현재 작업 옆에 열립니다. 창이 좁을 때는 작업으로 돌아가기를 눌러 터미널로 돌아옵니다.

세션 데몬

터미널은 별도의 로컬 데몬이 소유합니다. 그래서 Kiln 창을 닫아도 셸과 에이전트는 계속 실행되고, Kiln을 다시 열면 그 세션으로 돌아옵니다. 업데이트할 때도 실행 중인 터미널은 그대로 유지됩니다. 다만 시스템을 재부팅하거나 데몬을 명시적으로 중지하면 창을 닫을 때와 달리 세션이 종료될 수 있습니다. 자세한 내용은 창을 닫아도 유지되는 세션을 참고하세요.

알림

에이전트와 스크립트는 로컬 터미널 이스케이프 시퀀스나 kiln activity, kiln notify 명령으로 활동을 보고하고 알림을 보낼 수 있습니다. 이때 프롬프트가 다른 서비스로 전송되지는 않습니다. 알림 센터는 최근 알림을 보관하고 각 알림을 해당 세션과 연결해 두며, 알림을 읽으면 그 세션의 확인 필요 상태가 풀립니다. Windows에서는 에이전트 알림이 Windows 토스트로도 뜹니다. 자세한 내용은 터미널을 참고하세요.

준비 사항

  • Apple Silicon 기반 macOS 11 이상, 또는 x64·ARM64 기반 Windows 11
  • 사용할 에이전트 CLI(Claude Code, Codex, Antigravity의 agy)와 GitHub용 gh. Kiln에는 어떤 에이전트의 구독도 포함되어 있지 않으니, 쓰려는 도구를 직접 설치하고 로그인하세요.

앱은 영어, 한국어, 일본어, 중국어 간체를 지원합니다.

ドキュメントはじめに

AI エージェント IDE を使い始める

Kiln はエージェント作業のためのターミナルファースト IDE です。ターミナル、AI エージェント、Git、ファイル、データベースを 1 つのネイティブなワークスペースにまとめます。

Kiln はエージェント作業のためのターミナルファースト IDE です。ターミナル、AI エージェント、Git、ファイル、データベースを macOS と Windows 向けの 1 つのネイティブアプリにまとめるので、作業の全体をいつでも見渡せます。

リポジトリを 1 つだけ開くことも、フロントエンド、バックエンド、共有ライブラリをまとめた親フォルダーを開くこともできます。ターミナルパネルで Claude Code、Codex、Antigravity を動かし、対応が必要な作業を把握して、結果のレビューまでウィンドウを離れずに進められます。

基本概念

ワークスペース

ワークスペースは、フォルダーに名前を付けて開くビューです。作業、ターミナルセッション、分割レイアウト、未送信のリクエストはワークスペースごとに保持されます。1 つのフォルダーに API レビューとドキュメントのように複数のワークスペースを作ることができ、Kiln を開き直すとそれぞれが個別に復元されます。ファイルと Git 履歴はフォルダーに属するので、同じフォルダーのワークスペースはすべてこれらを共有します。

フォルダーには、1 つのリポジトリも、複数のリポジトリを含む親ディレクトリも指定できます。エージェントはその共通のルートで作業し、Git 操作は選択したリポジトリに対して実行されます。詳しくはワークスペースと作業を参照してください。

作業

作業とは、ワークスペースのターミナルで動いている処理のことです。直接操作するシェルの場合もあれば、新しい作業で開始したエージェントの場合もあります。サイドバーにはワークスペースごとに作業が並び、各作業が報告した状態が表示されます。

状態 意味
作業中 エージェントまたはコマンドが処理中だと報告しています。
入力待ち エージェントが回答を待っています。
完了 エージェントが完了を報告しました。
失敗 エージェントまたはコマンドが失敗を報告しました。

状態を報告しないセッションは、ターミナルの出力から推測せずに、開いているセッションとして表示します。アイドル状態のターミナルを完了した作業とは見なしません。作業をクリックすると、そのワークスペース、タブ、分割へすぐに移動します。

パネルと分割

ターミナルはそれぞれパネルに表示されます。パネルヘッダーには、右に分割、下に分割、閉じるの各操作があります。パネルのタイトルを別のパネルにドラッグすると、レイアウトを組み替えられます。移動しても、ターミナルセッションと実行中のプロセスはそのまま残ります。詳しくは分割とパネルのレイアウトを参照してください。

インスペクターとツール

ワークスペース右側のインスペクターには、ファイル、変更、GitHub と、接続・テーブル・SQL コンソールを扱うデータベースアイコンがあります。タイトルバーのツールメニューには、ファイル、検索、ソース管理、GitHub、データベース、リモート接続、問題がまとめて並び、選んだものは現在の作業の横に開きます。ウィンドウが狭いときは、作業に戻るでターミナルに戻れます。

セッションデーモン

ターミナルは、独立したローカルデーモンが管理しています。Kiln のウィンドウを閉じてもシェルやエージェントは動き続け、Kiln を開き直せばそのセッションに戻れます。アップデートしても、実行中のターミナルは維持されます。一方、システムの再起動やデーモンの明示的な停止はウィンドウを閉じるのとは違い、セッションが終了することがあります。詳しくはウィンドウを閉じても続くセッションを参照してください。

通知

エージェントやスクリプトは、ローカルのターミナルエスケープシーケンスか、kiln activity コマンドと kiln notify コマンドで、アクティビティを報告したり通知を送ったりできます。どちらの方法でも、プロンプトが外部のサービスに送られることはありません。通知センターには最近の通知が残り、各通知は対応するセッションにひも付いています。通知を読むと、そのセッションの要確認状態が解除されます。Windows では、エージェントの通知が Windows のトースト通知としても表示されます。詳しくはターミナルを参照してください。

必要なもの

  • Apple Silicon 搭載 Mac の macOS 11 以降、または Windows 11（x64 / ARM64）。
  • Claude Code、Codex、Antigravity（agy）のうち、使うエージェントの CLI と、GitHub 用の gh。Kiln にはエージェントのサブスクリプションは含まれていません。使うツールは各自でインストールし、ログインしておいてください。

アプリの表示言語は、英語、韓国語、日本語、簡体字中国語に対応しています。

文档入门

开始使用 AI 智能体 IDE

Kiln 是面向代理工作、以终端为核心的 IDE，终端、AI 代理、Git、文件和数据库都在同一个原生工作区里。

Kiln 是面向代理工作、以终端为核心的 IDE。终端、AI 代理、Git、文件和数据库集中在一个 macOS 和 Windows 原生应用里，整个任务始终在眼前。

打开单个仓库，或者打开一个同时包含前端、后端和共享库的父文件夹。在终端面板里运行 Claude Code、Codex 或 Antigravity，随时看到哪些任务在等你处理，不离开窗口就能审阅结果。

核心概念

工作区

工作区是文件夹的一个命名视图，各自保存任务、终端会话、拆分布局和尚未发送的请求。同一个文件夹可以有多个工作区，比如 API 审查和文档；Kiln 重新打开时会分别恢复每个工作区。文件和 Git 历史属于文件夹，因此同一文件夹下的所有工作区共用它们。

这个文件夹可以是一个仓库，也可以是包含多个仓库的父目录。代理在这个共同的根目录下工作，Git 操作则针对你选中的仓库。详见工作区与任务。

任务

任务就是工作区终端里正在进行的工作：可以是你直接使用的 Shell，也可以是通过新建任务启动的代理。侧边栏按工作区列出任务，并显示它们上报的状态：

状态 含义
处理中 代理或命令上报正在工作。
等待输入 代理在等你回复。
已完成 代理上报已经完成。
失败 代理或命令上报失败。

会话没有上报状态时，Kiln 只把它显示为打开的会话，不会根据终端输出去猜。空闲的终端不算已完成的任务。点击任务，即可直接跳到它所在的工作区、标签页和拆分视图。

面板与拆分视图

每个终端都在一个面板里。面板标题栏上有向右拆分、向下拆分和关闭按钮。把面板标题拖到另一个面板上即可调整布局，移动后终端会话和正在运行的进程都保持不变。详见拆分与面板布局。

检查器与工具

右侧的工作区检查器包含文件、更改、GitHub，以及一个数据库图标，用于管理连接、表和 SQL 控制台。标题栏的工具菜单汇总了文件、搜索、源代码管理、GitHub、数据库、远程连接和问题，每一项都会在当前工作旁边打开。窗口较窄时，点击返回任务回到终端。

会话守护进程

终端由一个独立的本地守护进程托管。关闭 Kiln 窗口后，其中的 Shell 和代理继续运行，重新打开 Kiln 就能回到它们。更新时，正在运行的终端也不会中断。系统重启或手动停止守护进程则不同于关闭窗口，可能会结束会话。详见关闭窗口后保留的会话。

通知

代理和脚本可以通过本地终端转义序列，或者 kiln activity 和 kiln notify 命令上报活动、发送通知。这些方式不会把你的提示词发送给其他服务。通知中心保留最近的通知，每条通知都关联到对应的会话；读过通知后，该会话的待处理状态随即清除。在 Windows 上，代理通知还会以 Windows 弹窗通知的形式出现。详见终端。

准备工作

  • Apple Silicon 上的 macOS 11 或更高版本，或者 x64 / ARM64 上的 Windows 11。
  • 你打算使用的代理 CLI：Claude Code、Codex 或 Antigravity（agy），以及用于 GitHub 的 gh。Kiln 不含任何代理的订阅，请自行安装并登录要用的工具。

应用界面支持英语、韩语、日语和简体中文。
