DocumentationUsing Kiln

Run Claude Code, Codex and Antigravity

Start Claude Code, Codex and Antigravity tasks from a workspace, follow their state, and let Kiln retry Codex turns when the server is overloaded.

Kiln runs Claude Code, Codex and Google's Antigravity CLI (agy) inside workspace panels. You write a request, pick an agent, and follow every task's state from the sidebar without hunting through terminals.

Before you start

The agents are external tools. Install the official CLI for each agent you use and sign in to it. Kiln does not include a subscription to any of them.

  • Claude Code and Codex: install the CLI, then add your accounts in Settings → Accounts. See Accounts.
  • Antigravity: install agy with Google's installer. On macOS, sign in from Settings → Accounts → Antigravity. On Windows, sign in by running agy in a terminal. Kiln looks for agy in your PATH, ~/.local/bin, /opt/homebrew/bin and /usr/local/bin.

On Windows, Claude Code and Codex run as native Windows programs with their homes in %USERPROFILE%\.codex and %USERPROFILE%\.claude.

Start a task

Choose New Task, enter a request, pick an agent and start. The agent selector (Claude Code, Codex or Antigravity) stays directly below the request input. Repository context scrolls separately, so a long summary never pushes the start action out of reach.

For Antigravity you can also use:

Action What it does
New task → Antigravity Starts agy in the current workspace.
New task → Open in folder → Antigravity Asks for a folder first, then starts agy there.
New Antigravity task (command palette, ⌘K) Starts an Antigravity task.

When you choose Antigravity below a request, Kiln passes the request and the repository summary to agy as its initial prompt. The antigravity command opens the Antigravity editor, so Kiln does not treat it as an agent.

Unsent requests are saved with the workspace and restored when Kiln reopens. Closing a workspace asks before discarding them.

Work across several repositories

Open a parent folder, such as ~/dev/projects, when your frontend, backend and shared libraries live in separate Git repositories. Kiln keeps that folder as the agent's working root and can include the discovered repository layout with your request, so one request can cover all of them.

Inspecting a repository in the Git or GitHub tools does not change the task's working directory. Use the repository selector in those tools to target one repository for Git operations. See Workspaces and tasks and Git and GitHub.

Follow task state

Each task row in the sidebar shows the state its agent reports.

State Meaning
Working The agent is working.
Waiting for Input The agent needs your input.
Done The agent finished.
Failed The agent reported a failure.
Session Open No state was reported. Kiln shows the session as open instead of guessing.

Running work appears first, followed by requests waiting for input and then older failures. Click a task to jump to its workspace, tab and split, including a pane hidden by zoom.

How Kiln knows the state

An agent must report its state, or show a running title Kiln recognizes, for Kiln to display it accurately.

  • Kiln recognizes the activity markers in Claude Code and Codex terminal titles, so running activity shows without extra setup.
  • Claude Code's ✳ marker is not treated as completion, because it also appears while a dialog is open.
  • Explicit waiting and failure signals take priority over title markers.
  • An idle terminal is never treated as a completed task, and an unfinished launch command does not mark an idle agent as running.

Scripts and other tools can report state with kiln activity running, waiting, done or failed. See Terminal for activity reporting and notifications.

Indicator colors

Agent Indicator
Claude Code Orange
Codex Blue
Antigravity Antigravity mark in the tab, task list and sidebar
Unidentified session Neutral

Indicators appear in the sidebar, the tab and the panel header. In a split tab, the focused pane wins when states have equal priority. Warnings always take priority.

Notifications and usage limits

The notification center keeps recent notifications and links each one to its session. Reading a notification clears that session's attention state. On Windows, agent notifications appear as Windows toasts.

When Antigravity reports that its quota is reached, Kiln shows a usage-limit notification with the reset time. For Claude Code and Codex, a panel keeps the account it was opened with. When an account reaches its usage limit, switch to another account in Settings → Accounts and open a new panel. See Accounts.

Codex capacity recovery

While Kiln is open, managed Codex panels retry a turn that Codex ended because its server was overloaded. Only that specific Codex error starts a retry. Usage limits, sign-in failures, stream errors, cancelled turns and successful turns are left alone.

  • Retries wait 15, 30, 60, 120 and 240 seconds. The panel shows a countdown and a Cancel auto-retry button.
  • Typing in the panel after the failure cancels the pending retry, including a partly typed prompt.
  • A new request you submit yourself starts a fresh set of retries.
  • Retries keep the same account and model.

If the Codex CLI is still open, Kiln sends one continuation prompt in the same conversation. If the CLI has exited, Kiln resumes the same conversation with its original account and working directory, then sends the prompt. The prompt asks Codex to check the current state before repeating a completed action. It does not replay your original request, and changes made during the failed turn are not rolled back.

Retries apply to Codex panels opened with a saved account whose conversation Kiln has confirmed. Failures from before Kiln started watching a running CLI are left for you to handle.

Codex background-server settings

New Codex panels opened by Kiln run with --no-daemon, independent of Codex's own shared background server. If a Codex session reports Background server has incompatible feature settings, the session's feature flags differ from the ones that server saved. You can choose:

Option Effect
Run without daemon this time Starts this session without restarting the shared Codex server. The CLI equivalent is codex --no-daemon.
Restart with these settings Changes the shared settings. This can interrupt other clients' active or queued work, so check them first.

문서Kiln 사용하기

Claude Code·Codex·Antigravity 함께 실행하기

워크스페이스에서 Claude Code, Codex, Antigravity 작업을 시작하고 상태를 확인하며, 서버 과부하로 중단된 Codex 턴을 Kiln이 다시 시도하게 합니다.

Kiln은 Claude Code, Codex, Google의 Antigravity CLI(agy)를 워크스페이스 패널 안에서 실행합니다. 요청을 쓰고 에이전트를 고르면, 터미널을 일일이 뒤질 필요 없이 사이드바에서 모든 작업의 상태를 확인할 수 있습니다.

시작하기 전에

에이전트는 외부 도구입니다. 사용할 에이전트마다 공식 CLI를 설치하고 로그인하세요. Kiln에는 어떤 에이전트의 구독도 포함되어 있지 않습니다.

  • Claude Code와 Codex: CLI를 설치한 뒤 설정 → 계정에서 계정을 추가합니다. 계정을 참고하세요.
  • Antigravity: Google 설치 프로그램으로 agy를 설치합니다. macOS에서는 설정 → 계정 → Antigravity에서, Windows에서는 터미널에서 agy를 실행해 로그인합니다. Kiln은 PATH, ~/.local/bin, /opt/homebrew/bin, /usr/local/bin에서 agy를 찾습니다.

Windows에서 Claude Code와 Codex는 네이티브 Windows 프로그램으로 실행되며, 홈 디렉터리는 각각 %USERPROFILE%\.codex와 %USERPROFILE%\.claude입니다.

작업 시작하기

새 작업을 선택하고 요청을 입력한 뒤 에이전트를 골라 시작합니다. 에이전트 선택기(Claude Code, Codex, Antigravity)는 요청 입력란 바로 아래에 고정되어 있습니다. 저장소 컨텍스트는 따로 스크롤되므로, 요약이 길어도 시작 버튼이 화면 밖으로 밀려나지 않습니다.

Antigravity는 다음 방법으로도 시작할 수 있습니다.

동작 하는 일
새 작업 → Antigravity 현재 워크스페이스에서 agy를 시작합니다.
새 작업 → 폴더에서 열기 → Antigravity 먼저 폴더를 고르게 한 뒤 그 폴더에서 agy를 시작합니다.
Antigravity로 새 작업 (명령 팔레트, ⌘K) Antigravity 작업을 시작합니다.

요청 아래에서 Antigravity를 고르면 Kiln은 요청과 저장소 요약을 agy의 첫 프롬프트로 넘깁니다. antigravity 명령은 Antigravity 편집기를 여는 명령이므로 Kiln은 이를 에이전트로 다루지 않습니다.

보내지 않은 요청은 워크스페이스와 함께 저장되고, Kiln을 다시 열면 복원됩니다. 워크스페이스를 닫을 때는 요청을 버리기 전에 확인을 받습니다.

여러 저장소 함께 다루기

프론트엔드, 백엔드, 공유 라이브러리가 각각 다른 Git 저장소에 있다면 ~/dev/projects 같은 상위 폴더를 여세요. Kiln은 이 폴더를 에이전트의 작업 루트로 유지하고 찾아낸 저장소 구성을 요청에 함께 넣을 수 있으므로, 요청 하나로 모든 저장소를 다룰 수 있습니다.

Git이나 GitHub 도구에서 저장소를 살펴봐도 작업이 실행되는 디렉터리는 바뀌지 않습니다. Git 작업을 적용할 저장소는 해당 도구의 저장소 선택기에서 고릅니다. 워크스페이스와 작업과 Git과 GitHub를 참고하세요.

작업 상태 확인하기

사이드바의 각 작업 행에는 에이전트가 보고한 상태가 표시됩니다.

상태 의미
작업 중 에이전트가 작업하고 있습니다.
입력 대기 에이전트가 내 입력을 기다립니다.
완료 에이전트가 작업을 마쳤습니다.
실패 에이전트가 실패를 보고했습니다.
세션 열림 보고된 상태가 없습니다. Kiln은 짐작하지 않고 세션이 열려 있다고만 표시합니다.

실행 중인 작업이 맨 위에 오고, 입력을 기다리는 요청, 이전에 실패한 작업 순으로 이어집니다. 작업을 클릭하면 해당 워크스페이스, 탭, 분할 화면으로 이동하며, 확대 때문에 가려진 패널도 다시 보입니다.

Kiln이 상태를 파악하는 방법

Kiln이 상태를 정확히 표시하려면 에이전트가 상태를 보고하거나 Kiln이 인식하는 실행 중 제목을 띄워야 합니다.

  • Kiln은 Claude Code와 Codex의 터미널 제목에 나오는 활동 표시를 인식하므로, 따로 설정하지 않아도 실행 중 활동이 표시됩니다.
  • Claude Code의 ✳ 표시는 대화상자가 열려 있을 때도 나타나므로 완료로 보지 않습니다.
  • 명시적인 대기·실패 신호가 있으면 제목 표시보다 우선합니다.
  • 유휴 상태의 터미널을 완료된 작업으로 보는 일은 없으며, 끝나지 않은 실행 명령 때문에 유휴 에이전트가 실행 중으로 표시되지도 않습니다.

스크립트나 다른 도구는 kiln activity running, waiting, done, failed로 상태를 보고할 수 있습니다. 활동 보고와 알림은 터미널을 참고하세요.

표시 색상

에이전트 표시
Claude Code 주황색
Codex 파란색
Antigravity 탭, 작업 목록, 사이드바에 Antigravity 마크
식별되지 않은 세션 중립색

표시는 사이드바, 탭, 패널 헤더에 나타납니다. 분할된 탭에서 상태의 우선순위가 같으면 포커스된 패널의 상태를 따릅니다. 경고는 언제나 우선합니다.

알림과 사용량 한도

알림 센터는 최근 알림을 보관하고 각 알림을 해당 세션과 연결해 둡니다. 알림을 읽으면 그 세션의 확인 필요 상태가 풀립니다. Windows에서는 에이전트 알림이 Windows 토스트로 뜹니다.

Antigravity가 할당량에 도달했다고 보고하면 Kiln은 초기화 시각과 함께 사용량 한도 알림을 띄웁니다. Claude Code와 Codex 패널은 처음 열 때 쓴 계정을 계속 씁니다. 계정이 사용량 한도에 도달하면 설정 → 계정에서 다른 계정으로 전환하고 새 패널을 여세요. 계정을 참고하세요.

Codex 용량 초과 복구

Kiln이 열려 있는 동안, Kiln이 관리하는 Codex 패널은 서버 과부하로 Codex가 중단한 턴을 다시 시도합니다. 재시도는 이 Codex 오류에서만 시작되며, 사용량 한도, 로그인 실패, 스트림 오류, 취소된 턴, 성공한 턴에는 관여하지 않습니다.

  • 재시도 간격은 15, 30, 60, 120, 240초입니다. 패널에는 카운트다운과 자동 재시도 취소 버튼이 표시됩니다.
  • 실패한 뒤 패널에 입력하면 대기 중인 재시도가 취소됩니다. 프롬프트를 일부만 입력해도 마찬가지입니다.
  • 직접 새 요청을 보내면 재시도가 처음부터 다시 시작됩니다.
  • 재시도할 때도 같은 계정과 모델을 씁니다.

Codex CLI가 아직 열려 있으면 Kiln은 같은 대화에 이어 가기 프롬프트를 한 번 보냅니다. CLI가 이미 종료되었다면 원래 계정과 작업 디렉터리로 같은 대화를 재개한 뒤 프롬프트를 보냅니다. 이 프롬프트는 이미 끝낸 동작을 반복하기 전에 현재 상태부터 확인하라고 Codex에 요청합니다. 원래 요청을 다시 보내지 않으며, 실패한 턴에서 생긴 변경도 되돌리지 않습니다.

재시도는 저장된 계정으로 연 Codex 패널 가운데 Kiln이 대화를 확인한 패널에만 적용됩니다. Kiln이 실행 중인 CLI를 지켜보기 전에 일어난 실패는 직접 처리해야 합니다.

Codex 백그라운드 서버 설정

Kiln이 여는 새 Codex 패널은 --no-daemon으로 실행되므로 Codex 자체의 공유 백그라운드 서버와 별개로 동작합니다. Codex 세션에 Background server has incompatible feature settings가 표시되면, 그 세션의 기능 플래그가 서버에 저장된 값과 다르다는 뜻입니다. 이때는 다음 중 하나를 고를 수 있습니다.

옵션 효과
Run without daemon this time 공유 Codex 서버를 재시작하지 않고 이 세션을 시작합니다. CLI의 codex --no-daemon과 같습니다.
Restart with these settings 공유 설정을 바꿉니다. 다른 클라이언트에서 진행 중이거나 대기 중인 작업이 중단될 수 있으니 먼저 확인하세요.

ドキュメントKiln を使う

Claude Code・Codex・Antigravity の実行

ワークスペースから Claude Code、Codex、Antigravity の作業を開始して状態を確認する方法と、サーバーの混雑時に Kiln が Codex のターンを再試行する仕組みを説明します。

Kiln は、Claude Code、Codex、Google の Antigravity CLI（agy）をワークスペースのパネルで実行します。リクエストを書いてエージェントを選ぶだけで、ターミナルを探し回らなくても、すべての作業の状態をサイドバーで確認できます。

始める前に

エージェントは外部のツールです。使うエージェントごとに公式の CLI をインストールし、ログインしておいてください。Kiln にはどのエージェントのサブスクリプションも含まれていません。

  • Claude Code と Codex: CLI をインストールしてから、設定 → アカウントでアカウントを追加します。詳しくはアカウントを参照してください。
  • Antigravity: Google のインストーラーで agy をインストールします。macOS では設定 → アカウント → Antigravity からログインします。Windows では、ターミナルで agy を実行してログインします。Kiln は agy を PATH、~/.local/bin、/opt/homebrew/bin、/usr/local/bin から探します。

Windows では、Claude Code と Codex はネイティブの Windows プログラムとして動作し、ホームディレクトリは %USERPROFILE%\.codex と %USERPROFILE%\.claude です。

作業を開始する

新しい作業を選んでリクエストを入力し、エージェントを選んで開始します。エージェントの選択欄（Claude Code、Codex、Antigravity）は、常にリクエスト入力欄のすぐ下にあります。リポジトリのコンテキストは別にスクロールするので、概要が長くても開始ボタンが画面の外に押し出されることはありません。

Antigravity では、次の方法も使えます。

操作 内容
新しい作業 → Antigravity 現在のワークスペースで agy を起動します。
新しい作業 → フォルダーで開く → Antigravity 先にフォルダーを選ぶよう求め、そのフォルダーで agy を起動します。
Antigravity の新規タスク（コマンドパレット、⌘K） Antigravity の作業を開始します。

リクエストの下で Antigravity を選ぶと、Kiln はリクエストとリポジトリの概要を最初のプロンプトとして agy に渡します。antigravity コマンドは Antigravity のエディターを開くものなので、Kiln はエージェントとして扱いません。

未送信のリクエストはワークスペースと一緒に保存され、Kiln を再び開くと復元されます。ワークスペースを閉じるときは、破棄する前に確認が表示されます。

複数のリポジトリにまたがって作業する

フロントエンド、バックエンド、共有ライブラリが別々の Git リポジトリにある場合は、~/dev/projects のような親フォルダーを開きます。Kiln はそのフォルダーをエージェントの作業ルートとして保ち、検出したリポジトリ構成をリクエストに含めることができるため、1 つのリクエストですべてのリポジトリを扱えます。

Git や GitHub のツールでリポジトリを確認しても、作業ディレクトリは変わりません。Git 操作の対象を 1 つのリポジトリにするには、それらのツールにあるリポジトリセレクターを使います。詳しくはワークスペースと作業と Git と GitHub を参照してください。

作業の状態を確認する

サイドバーの各作業の行には、エージェントが報告した状態が表示されます。

状態 意味
作業中 エージェントが作業しています。
入力待ち エージェントが入力を求めています。
完了 エージェントが作業を終えました。
失敗 エージェントが失敗を報告しました。
セッション開始済み 状態が報告されていません。Kiln は推測せず、開いているセッションとして表示します。

並び順は、実行中の作業、入力待ちのリクエスト、以前に失敗した作業の順です。作業をクリックすると、そのワークスペース、タブ、分割に移動します。拡大表示で隠れているパネルも表示されます。

Kiln が状態を知る仕組み

Kiln が状態を正確に表示するには、エージェントが状態を報告するか、Kiln が認識できる実行中のタイトルを表示する必要があります。

  • Kiln は Claude Code と Codex のターミナルタイトルにあるアクティビティマーカーを認識するため、追加の設定なしで実行中のアクティビティが表示されます。
  • Claude Code の ✳ マーカーはダイアログが開いている間にも表示されるため、完了とは見なしません。
  • 明示的な入力待ちと失敗のシグナルは、タイトルのマーカーより優先されます。
  • アイドル状態のターミナルが完了した作業として扱われることはなく、終了していない起動コマンドによって、アイドル状態のエージェントが実行中と表示されることもありません。

スクリプトやその他のツールは、kiln activity running、waiting、done、failed で状態を報告できます。アクティビティの報告と通知についてはターミナルを参照してください。

インジケーターの色

エージェント インジケーター
Claude Code オレンジ
Codex 青
Antigravity タブ、作業一覧、サイドバーに Antigravity のマーク
識別できないセッション 無彩色

インジケーターは、サイドバー、タブ、パネルヘッダーに表示されます。分割したタブで状態の優先度が同じときは、フォーカスのあるパネルの状態が表示されます。警告は常に優先されます。

通知と使用量の上限

通知センターには最近の通知が残り、各通知は対応するセッションにひも付いています。通知を読むと、そのセッションの要確認状態が解除されます。Windows では、エージェントの通知が Windows のトースト通知として表示されます。

Antigravity がクォータの上限に達したと報告すると、Kiln はリセット時刻を添えて使用量上限の通知を表示します。Claude Code と Codex では、パネルは開いたときのアカウントを使い続けます。アカウントが使用量の上限に達したら、設定 → アカウントで別のアカウントに切り替え、新しいパネルを開いてください。詳しくはアカウントを参照してください。

Codex の混雑時の自動復旧

Kiln が開いている間、Kiln が管理する Codex のパネルでは、サーバーの混雑が原因で Codex が終了したターンを再試行します。再試行が始まるのは、この特定の Codex エラーのときだけです。使用量の上限、ログインの失敗、ストリームのエラー、キャンセルされたターン、成功したターンは再試行の対象外です。

  • 再試行までの待ち時間は 15、30、60、120、240 秒です。パネルにはカウントダウンと自動再試行をキャンセルボタンが表示されます。
  • 失敗の後にパネルで何か入力すると、入力途中のプロンプトであっても、保留中の再試行はキャンセルされます。
  • 自分で新しいリクエストを送信した場合、再試行は改めて 1 回目から数えられます。
  • 再試行では同じアカウントとモデルを使います。

Codex CLI がまだ開いている場合、Kiln は同じ会話に続行用のプロンプトを 1 回送ります。CLI が終了している場合は、元のアカウントと作業ディレクトリで同じ会話を再開してから、そのプロンプトを送ります。このプロンプトは、完了済みの操作を繰り返す前に現在の状態を確認するよう Codex に求めるものです。元のリクエストを再送することはなく、失敗したターンの間に行われた変更が元に戻されることもありません。

再試行の対象は、保存済みのアカウントで開いた Codex のパネルのうち、Kiln が会話を確認できたものです。実行中の CLI を Kiln が監視し始める前に起きた失敗は、自分で対処してください。

Codex のバックグラウンドサーバーの設定

Kiln が新しく開く Codex のパネルは --no-daemon で実行されるので、Codex 本体の共有バックグラウンドサーバーからは独立しています。Codex のセッションが Background server has incompatible feature settings（バックグラウンドサーバーの機能設定に互換性がありません）と報告した場合は、そのセッションの機能フラグが、サーバーに保存されている設定と食い違っています。次のいずれかを選べます。

オプション 効果
Run without daemon this time（今回はデーモンなしで実行） 共有の Codex サーバーを再起動せずに、このセッションを開始します。CLI では codex --no-daemon に相当します。
Restart with these settings（この設定で再起動） 共有の設定を変更します。ほかのクライアントの実行中または待機中の処理が中断される場合があるため、先に確認してください。

次のステップ

  • アカウントでは、ログイン、アカウントの切り替え、使用量の確認について説明しています。
  • 会話とアップデートでは、別の CLI で会話を続ける方法と、アップデート後に再起動する方法を説明しています。

文档使用 Kiln

运行 Claude Code、Codex 和 Antigravity

在工作区中启动 Claude Code、Codex 和 Antigravity 任务，跟踪任务状态，并在服务器过载时由 Kiln 重试 Codex 回合。

Kiln 在工作区面板中运行 Claude Code、Codex 和 Google 的 Antigravity CLI（agy）。写好请求、选好代理，每个任务的状态都能在侧边栏看到，不必在一个个终端之间翻找。

开始之前

这些代理都是外部工具。请为要用的每个代理安装官方 CLI 并登录。Kiln 不含其中任何一个的订阅。

  • Claude Code 和 Codex：安装 CLI，然后在设置 → 账户中添加账户。详见账户。
  • Antigravity：用 Google 提供的安装程序安装 agy。在 macOS 上，从设置 → 账户 → Antigravity 登录；在 Windows 上，在终端中运行 agy 登录。Kiln 会在 PATH、~/.local/bin、/opt/homebrew/bin 和 /usr/local/bin 中查找 agy。

在 Windows 上，Claude Code 和 Codex 以原生 Windows 程序运行，主目录分别是 %USERPROFILE%\.codex 和 %USERPROFILE%\.claude。

启动任务

选择新建任务，输入请求，选择代理并启动。代理选择器（Claude Code、Codex 或 Antigravity）固定在请求输入框正下方。仓库上下文单独滚动，摘要再长也不会把启动按钮挤出视野。

Antigravity 还有以下入口：

操作 作用
新建任务 → Antigravity 在当前工作区中启动 agy。
新建任务 → 在文件夹中打开 → Antigravity 先选择文件夹，再在该文件夹中启动 agy。
新建 Antigravity 任务（命令面板，⌘K） 启动一个 Antigravity 任务。

在请求下方选择 Antigravity 时，Kiln 会把请求和仓库摘要作为初始提示词传给 agy。antigravity 命令打开的是 Antigravity 编辑器，因此 Kiln 不把它当作代理。

未发送的请求随工作区一起保存，Kiln 重新打开时会恢复。关闭工作区时，丢弃这些请求前会先询问。

跨多个仓库工作

如果前端、后端和共享库分属不同的 Git 仓库，就打开它们的父文件夹，例如 ~/dev/projects。Kiln 把这个文件夹作为代理的工作根目录，还可以把扫描到的仓库结构随请求一起附上，一个请求就能覆盖所有仓库。

在 Git 或 GitHub 工具中查看某个仓库，不会改变任务的工作目录。要让 Git 操作针对某个仓库，请使用这些工具中的仓库选择器。详见工作区与任务和 Git 与 GitHub。

跟踪任务状态

侧边栏中的每一行任务都显示其代理上报的状态。

状态 含义
处理中 代理正在工作。
等待输入 代理需要你输入。
已完成 代理已完成。
失败 代理上报失败。
会话已打开 没有上报任何状态。Kiln 只把会话显示为打开，不做猜测。

运行中的工作排在最前，其次是等待输入的请求，再往后是较早的失败。点击任务即可跳到它所在的工作区、标签页和拆分视图，即使该面板因缩放而被隐藏。

Kiln 如何获知状态

代理必须上报自己的状态，或者显示 Kiln 能识别的运行中标题，Kiln 才能准确显示状态。

  • Kiln 能识别 Claude Code 和 Codex 终端标题中的活动标记，无需额外设置就能显示运行中的活动。
  • Claude Code 的 ✳ 标记不算作完成，因为对话框打开时它也会出现。
  • 显式的等待和失败信号优先于标题标记。
  • 空闲的终端绝不会被当作已完成的任务；启动命令尚未结束，也不会让空闲的代理显示为运行中。

脚本和其他工具可以用 kiln activity running、waiting、done 或 failed 上报状态。活动上报和通知详见终端。

指示器颜色

代理 指示器
Claude Code 橙色
Codex 蓝色
Antigravity 标签页、任务列表和侧边栏中显示 Antigravity 标志
无法识别的会话 中性色

指示器出现在侧边栏、标签页和面板标题栏中。在有拆分视图的标签页里，各状态优先级相同时，以获得焦点的面板为准。警告始终优先。

通知与用量限制

通知中心保留最近的通知，每条通知都关联到对应的会话。读过通知后，该会话的待处理状态随即清除。在 Windows 上，代理通知以 Windows 弹窗通知的形式出现。

Antigravity 上报配额已用完时，Kiln 会显示一条用量限制通知，并注明重置时间。对于 Claude Code 和 Codex，面板始终使用打开时的账户。某个账户达到用量限制后，请在设置 → 账户中切换到其他账户，再新开一个面板。详见账户。

Codex 容量恢复

Kiln 打开期间，如果 Codex 因服务器过载而结束了某个回合，由 Kiln 管理的 Codex 面板会重试该回合。只有这一种 Codex 错误会触发重试。用量限制、登录失败、流错误、已取消的回合和成功的回合都不会处理。

  • 重试间隔依次为 15、30、60、120 和 240 秒。面板上会显示倒计时和取消自动重试按钮。
  • 失败后在面板中输入任何内容，都会取消待执行的重试，输入到一半的提示词也算。
  • 你自己提交新请求时，会重新开始一轮重试。
  • 重试沿用同一个账户和模型。

如果 Codex CLI 仍然开着，Kiln 会在同一对话中发送一条继续提示词。如果 CLI 已经退出，Kiln 会用原来的账户和工作目录恢复同一对话，再发送这条提示词。提示词会要求 Codex 先检查当前状态，再决定是否重复已完成的操作。它不会重放你的原始请求，失败回合中做出的更改也不会回滚。

重试只适用于用已保存账户打开、且 Kiln 已确认其对话的 Codex 面板。Kiln 开始监视运行中的 CLI 之前发生的失败，需要你自行处理。

Codex 后台服务器设置

Kiln 新开的 Codex 面板以 --no-daemon 运行，与 Codex 自己的共享后台服务器相互独立。如果某个 Codex 会话提示 Background server has incompatible feature settings，说明该会话的功能标志与服务器保存的不一致。可以选择：

选项 效果
Run without daemon this time 不重启共享的 Codex 服务器，直接启动本次会话。对应的 CLI 命令是 codex --no-daemon。
Restart with these settings 更改共享设置。这可能会中断其他客户端正在进行或排队的工作，请先确认。

后续步骤

  • 账户：登录、切换账户和查看用量。
  • 对话与更新：在另一个 CLI 中继续对话，更新后重启。
