DocumentationUsing Kiln

Run Claude Code, Codex and Antigravity

Run Claude Code, Codex and Antigravity in native conversations or terminals, with provider settings, commands, permissions and durable drafts.

Kiln runs Claude Code, Codex and Google's Antigravity CLI (agy) inside workspace panels. You write a request, pick an agent, and follow every task's state from the sidebar without hunting through terminals.

Before you start

The agents are external tools. Install the official CLI for each agent you use and sign in to it. Kiln does not include a subscription to any of them.

  • Claude Code and Codex: install the CLI, then add your accounts in Settings → Accounts. See Accounts.
  • Antigravity: install agy with Google's installer. On macOS, sign in from Settings → Accounts → Antigravity. On Windows, sign in by running agy in a terminal. Kiln looks for agy in your PATH, ~/.local/bin, /opt/homebrew/bin and /usr/local/bin.

On Windows, Claude Code and Codex run as native Windows programs with their homes in %USERPROFILE%\.codex and %USERPROFILE%\.claude.

Start a task

Choose New Task, enter a request, pick an agent and start. The agent selector (Claude Code, Codex or Antigravity) stays directly below the request input. Repository context scrolls separately, so a long summary never pushes the start action out of reach.

For Antigravity you can also use:

Action What it does
New task → Antigravity Starts agy in the current workspace.
New task → Open in folder → Antigravity Asks for a folder first, then starts agy there.
New Antigravity task (command palette, ⌘K) Starts an Antigravity task.

When you choose Antigravity below a request, Kiln passes the request and the repository summary to agy as its initial prompt. The antigravity command opens the Antigravity editor, so Kiln does not treat it as an agent.

Unsent requests are saved with the workspace and restored when Kiln reopens. Closing a workspace asks before discarding them.

The right and down split buttons let you choose a terminal or an agent for the new panel. Keyboard split shortcuts still open a terminal directly.

Native conversation or terminal

In New Task and the right/down split menu, choose Conversation GUI or Terminal before choosing an agent. New agent launches default to Conversation GUI. Save your preference in Settings → Behavior → New agent presentation. Ordinary terminals, SSH and existing terminal tasks keep their current presentation.

The conversation shows streamed Markdown, expandable tool input/output and file diffs. Answer inline permission or question cards; both allow and deny work. The header pins the starting account and shows the confirmed effective model/mode. Composer choices contain only models and modes advertised by the provider. Existing native MCP and permission settings are preserved.

Press Enter or Send to submit; Shift+Enter adds a line. Korean IME preedit and commit do not submit. Use Attach image to select several files at once, paste an image while the message editor has focus, or drop files onto the intended conversation pane. Each draft accepts up to eight images (PNG, JPEG, GIF, WebP; 20 MiB each). Text paste still inserts text. Check the thumbnails and use each image’s × action to remove it before sending. Remove missing or invalid restored attachments before sending. Stop interrupts the current turn.

Closing Kiln saves drafts while the daemon keeps the worker alive. Closing a pane ends its session and asks before discarding drafts. Locally queued sends wait for journal confirmation: reopening never resends them. An unconfirmed send offers Recover as draft; check history before intentionally sending again. Failed or disconnected sessions retain history and offer Restart same conversation. Earlier/latest message controls navigate a bounded display window without deleting history.

Approval cards show the command, folder, affected paths, reason and requested access with localized titles. Transport IDs and schemas stay out of the decision. After full history replay, a restored send absent from the journal and mailbox offers explicit recovery even if the worker is Ready; it is never resent automatically.

Claude approvals include the actual MCP/tool arguments, including domain identifiers; long previews are bounded and labeled partial. Codex transport parameters and schemas stay filtered. Recovery also waits for a queue observation that follows any final publication by the old client.

The activity strip above the composer distinguishes preparing a response, running tools, waiting for input and response completion. It stays visible while you read older messages. Claude’s native shell, Monitor and other background tasks show their reported descriptions, states, progress summaries and available durations; expand a task for details. Ambient watchers remain listed without treating them as an unfinished response. Other providers show their reported running tools. When you scroll up or open earlier history, choose ↓ Jump to latest to return to the latest messages without changing your draft.

Use View output · Refresh in a shell or Monitor task to read its latest output without sending an AI prompt. A partial tail, empty output and unavailable output are labeled separately.

Switch the same conversation

Idle GUI-to-TUI checks resolve declared MCP helper commands using the conversation’s saved environment and working folder, including a helper-specific PATH override. A connected MCP service by itself is not a running model task.

Pane titles and automatic page names use a shortened first confirmed request. Manually named pages keep their names; editing a draft does not rename an established conversation.

The GUI | TUI joined tabs sit inside each agent pane at the top right, below its close button. Replies show the agent icon beside its name. Expanded tool details provide a readable, scrollable code area with syntax highlighting for recognized file languages and shell commands, plus a copy action. Unknown output remains plain text.

Use the agent pane’s GUI | TUI tabs to continue the same confirmed conversation with its original account and working folder. A new Claude Code conversation can also open in the terminal before its first message, without trying to resume a history file that does not exist yet. You can request TUI while work is running. Kiln keeps the work in GUI and switches automatically after the response, approvals and queued work finish and ownership checks pass. Select GUI to cancel a pending switch. This is a deferred native handoff, not an immediate move of a running model request between processes. A native TUI still needs to exit normally before its GUI writer starts; selecting TUI cancels that return request. If a background task remains or Kiln cannot verify process ownership, it refuses the switch and leaves that work running. The terminal starts only after the previous agent has finished exiting; a refusal explains what blocks the switch.

With a supported Claude Code mod active, select GUI to return automatically once the native prompt is idle and empty. Work, approvals, typed drafts and reported shell/Monitor task badges defer the return. Select TUI to cancel a pending return. Kiln uses Claude’s native exit action and waits for the process to finish before reconnecting the same conversation. Newly appended user/assistant text is imported; images appear as attachment notices. Earlier history mismatches preserve the retained GUI history and show an error.

Interactive claude, codex and agy commands started through Kiln’s registered shell functions can also use the joined GUI | TUI tabs. Kiln connects the pane only after verifying the exact live host binding for that terminal. The original PTY, parent shell, command arguments and selected account profile are retained. This applies to the functions supplied by Kiln’s zsh or PowerShell integration; the registered commands depend on the shell.

For Codex, Antigravity, older workers and Claude installations where the mod is unavailable or disabled, select GUI and exit the CLI normally, for example with /exit or Ctrl+D where supported. The banner distinguishes automatic return from this fallback. Updating the app preserves existing workers; the automatic bridge applies to native launches started by the updated worker. Exiting the initial TUI without requesting GUI returns to the original shell.

Management, print and remote commands, pipelines, redirected input/output, and user aliases or custom functions that bypass Kiln’s integration keep their native execution path. Bash and fish do not receive automatic agent wrappers. Commands in terminals outside Kiln are not automatically tracked.

For an older terminal-launched agent, GUI import requires an exactly tracked native conversation. Exit that CLI first. Kiln waits for the terminal daemon to confirm that the old terminal process exited, then opens the recorded conversation with its original account environment and working folder. A disconnected terminal or an unknown conversation does not establish a safe import boundary.

Work across several repositories

Open a parent folder, such as ~/dev/projects, when your frontend, backend and shared libraries live in separate Git repositories. Kiln keeps that folder as the agent's working root and can include the discovered repository layout with your request, so one request can cover all of them.

Inspecting a repository in the Git or GitHub tools does not change the task's working directory. Use the repository selector in those tools to target one repository for Git operations. See Workspaces and tasks and Git and GitHub.

Follow task state

Each task row in the sidebar shows the state its agent reports.

State Meaning
Working The agent is working.
Waiting for Input The agent needs your input.
Done The agent finished.
Failed The agent reported a failure.
Session Open No state was reported. Kiln shows the session as open instead of guessing.

Running work appears first, followed by requests waiting for input and then older failures. Click a task to jump to its workspace, tab and split, including a pane hidden by zoom.

How Kiln knows the state

An agent must report its state, or show a running title Kiln recognizes, for Kiln to display it accurately.

  • Kiln recognizes the activity markers in Claude Code and Codex terminal titles, so running activity shows without extra setup.
  • Claude Code's ✳ marker is not treated as completion, because it also appears while a dialog is open.
  • Explicit waiting and failure signals take priority over title markers.
  • An idle terminal is never treated as a completed task, and an unfinished launch command does not mark an idle agent as running.

Scripts and other tools can report state with kiln activity running, waiting, done or failed. See Terminal for activity reporting and notifications.

Notifications and usage limits

The notification center keeps recent notifications and links each one to its session. Reading a notification clears that session's attention state. On Windows, agent notifications appear as Windows toasts.

When Antigravity reports that its quota is reached, Kiln shows a usage-limit notification with the reset time. For Claude Code and Codex, a panel keeps the account it was opened with. When an account reaches its usage limit, switch to another account in Settings → Accounts and open a new panel. See Accounts.

Codex capacity recovery

While Kiln is open, managed Codex panels retry a turn that Codex ended because its server was overloaded. Only that specific Codex error starts a retry. Usage limits, sign-in failures, stream errors, cancelled turns and successful turns are left alone.

  • Retries wait 15, 30, 60, 120 and 240 seconds. The panel shows a countdown and a Cancel auto-retry button.
  • Typing in the panel after the failure cancels the pending retry, including a partly typed prompt.
  • A new request you submit yourself starts a fresh set of retries.
  • Retries keep the same account and model.

If the Codex CLI is still open, Kiln sends one continuation prompt in the same conversation. If the CLI has exited, Kiln resumes the same conversation with its original account and working directory, then sends the prompt. The prompt asks Codex to check the current state before repeating a completed action. It does not replay your original request, and changes made during the failed turn are not rolled back.

Retries apply to Codex panels opened with a saved account whose conversation Kiln has confirmed. Failures from before Kiln started watching a running CLI are left for you to handle.

Codex background-server settings

New Codex panels opened by Kiln run with --no-daemon, independent of Codex's own shared background server. If a Codex session reports Background server has incompatible feature settings, the session's feature flags differ from the ones that server saved. You can choose:

Option Effect
Run without daemon this time Starts this session without restarting the shared Codex server. The CLI equivalent is codex --no-daemon.
Restart with these settings Changes the shared settings. This can interrupt other clients' active or queued work, so check them first.

In newly opened Kiln Zsh terminals, plain codex, codex resume … and codex fork … also use --no-daemon, so a shared server reporting Server is draining; retry after reconnecting does not block those launches. Explicit --remote connections, existing aliases/functions, other command forms and other shells keep their normal behavior. Use command codex … to bypass the wrapper or add --no-daemon yourself for a local session. Reopen existing shells to load this integration. Kiln does not restart the shared server or change its update settings.

Native session settings and commands

You can send a follow-up with Send or Enter while a response is running; Stop remains a separate button. Claude accepts streaming follow-ups and Codex steers the current turn. Antigravity holds one follow-up until its current prompt finishes. A pending receipt is kept separate from an accepted message and is never automatically resent.

Model, effort and mode controls remain available during a response. Claude applies live changes at the native boundary; Codex composer selections update the next turn, while its explicit active-turn action changes supported settings of the current turn. Settings still wait for native confirmation. Workspace activity rows show the conversation title instead of the provider name, while preserving custom page titles.

In a conversation GUI, use Session settings for searchable provider controls and Commands and skills to find native commands. A compact two-line message editor sits above one toolbar: attach an image, choose the model and mode, open Reasoning settings, or use the round Send/Stop control. Narrow panes keep the model beside Conversation options, which contains the remaining controls. Choices show readable model names and localized mode/effort labels while preserving the provider’s actual values. A missing catalog remains different from an empty one.

Open Reasoning settings, or Conversation options in a narrow pane, to choose an offered reasoning level with an explanation of each choice. Claude’s independent Ultracode switch has a purple indicator when enabled. The header shows the confirmed effective model and mode.

Claude Code, Codex and Antigravity share localized setting names and visible explanations for built-in choices. In Korean, approval policies use readable names such as “필요할 때 승인 요청” (ask when needed). The same presentation covers startup options, active-turn settings, sandbox controls and granular approvals. Provider-defined names and native values remain intact.

Model comparison puts the current model first, with cards showing one model name, a concise summary, default reasoning effort and supported inputs. Choose Use this model to request a change; the provider confirms its application. Expand details for supported levels and the provider’s original description.

Illustrations rendered from synthetic catalogs with the native UI; not an authenticated model response.

A changed setting shows its requested and native values separately. Send and conflicting settings wait for native confirmation; Stop remains available. A transport acknowledgment alone does not confirm that a setting took effect. Rejected or unconfirmed changes stay visible and are never automatically retried.

Commands and skills has a search icon, a clear action and a bounded scrolling list. Names align to the left; expand a row to read its full description and details. Search covers names, descriptions and aliases. Terminal-only commands and skills that cannot be invoked in the GUI stay out of the list. Selecting an entry only inserts an editable draft, preserving existing text and images; Codex skills also retain their native input until explicit Send.

Typing / opens a scrolling completion list with short descriptions; Codex skills also complete from $. Use Up/Down to select, Tab or Enter to insert, and Esc to dismiss. Completion does not send the message. Recognized command/skill tokens are visually distinct from ordinary text. Refresh the catalog after native skills change.

Session settings shows controls that can actually be edited in the GUI, grouped by response, working style, context and permissions. Read-only native inventories and unavailable controls are omitted. Change history, reset actions and reference information stay behind details controls. Start a separate terminal from New task when you need the CLI interface.

New conversation settings opens a separate conversation with the currently selected account and explicit startup options. It preserves the current session and draft, and does not replay a prompt. Native actions such as review, goals and queued tasks run only from their explicit action buttons. Current-turn settings target the reported running turn and do not change work already captured by the provider.

Tool headers use the app language, including questions and known MCP operations. Expand a card or hover its header to inspect the original tool name; arguments, output, questions and diffs keep their original content. Language changes relabel existing history. Unknown operations use an external-tool label. Extension preparation and retained cache versions do not prove that the native provider loaded an extension.

Type @ in the message to search files and folders in the current workspace. Use the arrow keys to choose, Tab to browse a folder, Enter to insert, and Esc to dismiss. Paths with spaces and non-Latin names are quoted. Selection only edits the draft; sending remains explicit. Claude keeps its native @ reference syntax, Codex uses the same path-as-text contract as its TUI, and Antigravity receives the selected full path. Provider permissions and native context handling still apply.

Native next-prompt suggestions

When Claude Code emits a native next-prompt suggestion, it appears as faint text in the empty GUI message box. Tab copies it into your draft; Enter or Send submits it. Esc hides that suggestion. Typing, attachments and input-method composition take priority. Suggestions follow Claude’s settings and availability and need not appear after every response. Kiln does not invent replacement suggestions.

Personal extensions and account scope

New launches prepare supported personal Claude/Codex skills and self-contained plugin assets for the selected private profile. Claude also supports portable legacy commands, agents, output styles and workflow bundles. Native project precedence remains in effect; shared Codex HOME skills and Antigravity assets remain native. Existing account sign-in/bootstrap behavior is preserved. Source author files remain unchanged, and private profile edits/deletions survive later imports. Status polling and resuming a worker do not refresh these imports.

Extension prepared means import preparation succeeded. Existing extension retained means a prior cache version remains for readers. Neither means enabled, loaded or executed. Native discovery and execution need their own result. Portable supported plugin declarations can retain bundled hooks/MCP/LSP configuration without running it during preparation. Credential-bearing configuration, account-linked connectors, unsupported formats, external paths, routines and scheduler state need native setup or produce a visible diagnostic. Kiln does not copy the entire configuration or account history. See native plugin loading.

Claude Code·Codex·Antigravity 함께 실행하기

Claude Code·Codex·Antigravity를 대화 GUI나 터미널에서 실행하고 제공자 설정·명령·권한과 저장된 초안을 다룹니다.

Kiln은 Claude Code, Codex, Google의 Antigravity CLI(agy)를 워크스페이스 패널 안에서 실행합니다. 요청을 쓰고 에이전트를 고르면, 터미널을 일일이 뒤질 필요 없이 사이드바에서 모든 작업의 상태를 확인할 수 있습니다.

시작하기 전에

에이전트는 외부 도구입니다. 사용할 에이전트마다 공식 CLI를 설치하고 로그인하세요. Kiln에는 어떤 에이전트의 구독도 포함되어 있지 않습니다.

  • Claude Code와 Codex: CLI를 설치한 뒤 설정 → 계정에서 계정을 추가합니다. 계정을 참고하세요.
  • Antigravity: Google 설치 프로그램으로 agy를 설치합니다. macOS에서는 설정 → 계정 → Antigravity에서, Windows에서는 터미널에서 agy를 실행해 로그인합니다. Kiln은 PATH, ~/.local/bin, /opt/homebrew/bin, /usr/local/bin에서 agy를 찾습니다.

Windows에서 Claude Code와 Codex는 네이티브 Windows 프로그램으로 실행되며, 홈 디렉터리는 각각 %USERPROFILE%\.codex와 %USERPROFILE%\.claude입니다.

작업 시작하기

새 작업을 선택하고 요청을 입력한 뒤 에이전트를 골라 시작합니다. 에이전트 선택기(Claude Code, Codex, Antigravity)는 요청 입력란 바로 아래에 고정되어 있습니다. 저장소 컨텍스트는 따로 스크롤되므로, 요약이 길어도 시작 버튼이 화면 밖으로 밀려나지 않습니다.

Antigravity는 다음 방법으로도 시작할 수 있습니다.

동작 하는 일
새 작업 → Antigravity 현재 워크스페이스에서 agy를 시작합니다.
새 작업 → 폴더에서 열기 → Antigravity 먼저 폴더를 고르게 한 뒤 그 폴더에서 agy를 시작합니다.
Antigravity로 새 작업 (명령 팔레트, ⌘K) Antigravity 작업을 시작합니다.

요청 아래에서 Antigravity를 고르면 Kiln은 요청과 저장소 요약을 agy의 첫 프롬프트로 넘깁니다. antigravity 명령은 Antigravity 편집기를 여는 명령이므로 Kiln은 이를 에이전트로 다루지 않습니다.

보내지 않은 요청은 워크스페이스와 함께 저장되고, Kiln을 다시 열면 복원됩니다. 워크스페이스를 닫을 때는 요청을 버리기 전에 확인을 받습니다.

패널 상단의 오른쪽·아래쪽 분할 버튼에서 새 패널에 열 터미널이나 에이전트를 고를 수 있습니다. 분할 단축키는 터미널을 바로 엽니다.

대화 화면 또는 터미널

새 작업과 오른쪽/아래 분할 메뉴에서 에이전트를 고르기 전에 대화 GUI 또는 터미널을 선택하세요. 새 에이전트는 대화 GUI로 시작합니다. 설정 → 동작 → 새 에이전트 표시 방식에서 기본값을 바꿀 수 있습니다. 일반 터미널, SSH, 기존 터미널 작업은 현재 표시 방식을 유지합니다.

대화 화면에서 스트리밍 Markdown, 펼칠 수 있는 도구 입력·출력과 파일 diff를 확인하세요. 권한 요청과 질문에 화면 안에서 답할 수 있으며 허용과 거부가 모두 가능합니다. 머리글에는 시작 당시 계정과 실제 적용이 확인된 모델·모드가 표시됩니다. 입력창에는 제공자가 알린 모델·모드만 나타나며 기존 MCP와 권한 설정을 유지합니다.

Enter 또는 보내기로 전송하고 Shift+Enter로 줄바꿈하세요. 한글 조합과 확정 입력은 전송하지 않습니다. 이미지 첨부에서 여러 파일을 한 번에 선택하거나, 메시지 입력창에 커서를 둔 상태에서 이미지를 붙여넣거나, 첨부할 대화 패널에 파일을 놓으세요. 초안 하나에 최대 8개(PNG, JPEG, GIF, WebP, 각각 20 MiB)를 첨부할 수 있습니다. 텍스트를 붙여넣으면 그대로 입력됩니다. 썸네일로 이미지를 확인하고 각 이미지의 × 버튼으로 전송 전에 제거할 수 있습니다. 복원된 첨부가 없거나 잘못되었다면 제거 후 전송하세요. 중지는 현재 작업을 중단합니다.

Kiln을 닫으면 초안을 저장하고 데몬이 작업 프로세스를 유지합니다. 패널을 닫으면 세션이 끝나며 초안을 버리기 전에 확인합니다. 로컬 전송 대기는 저널 확인 전까지 보관하고 다시 열어도 재전송하지 않습니다. 전송 미확인 시 초안으로 복구할 수 있으며 다시 보내기 전에 기록을 확인하세요. 실패·연결 끊김 상태에서도 기록을 유지하고 같은 대화로 재시작할 수 있습니다. 이전·최근 메시지 버튼은 기록을 삭제하지 않고 표시 범위만 이동합니다.

승인 카드에는 번역된 제목과 함께 명령·작업 폴더·대상 경로·이유·요청 권한을 표시하고 전송 ID와 스키마는 노출하지 않습니다. 기록 복원이 완료된 뒤에도 저널과 전송함에 없는 이전 요청은 에이전트가 준비 상태여도 직접 초안으로 복구할 수 있으며 자동 재전송하지 않습니다.

입력창 위 상태 표시에서 응답 작성·도구 실행·입력 대기·응답 완료를 구분할 수 있습니다. 위쪽 기록을 읽는 동안에도 계속 표시됩니다. Claude가 보고한 셸·Monitor·기타 백그라운드 작업의 설명과 상태, 진행 요약, 제공된 실행 시간을 확인하고 각 작업을 펼쳐 상세 내역을 볼 수 있습니다. 상시 감시 작업은 목록에 유지하되 응답이 계속 작성 중인 것으로 표시하지 않습니다. 다른 AI도 보고된 실행 중 도구를 보여 줍니다. 위로 스크롤하거나 이전 기록을 열면 ↓ 최신 메시지로 이동으로 초안을 유지하며 최신 내역으로 돌아올 수 있습니다.

셸·Monitor 상세의 출력 보기 · 새로고침은 AI에게 새 요청을 보내지 않고 최근 출력을 읽습니다. 출력 일부만 표시되는 경우, 아직 출력이 없는 경우, CLI가 출력을 제공하지 않는 경우를 구분합니다.

같은 대화에서 화면 전환하기

유휴 상태의 GUI→TUI 전환 검사에서는 대화에 저장된 환경 변수와 작업 폴더로 MCP 실행 파일을 확인합니다. MCP별 PATH 재정의도 반영합니다. MCP 서비스가 연결되어 있다는 사실만으로 AI가 작업 중인 것은 아닙니다.

창 제목과 자동 작업 탭 이름은 처음 전송한 요청을 짧게 표시합니다. 직접 지정한 작업 이름은 유지되며, 초안을 편집해도 기존 대화 제목은 바뀌지 않습니다.

각 에이전트 창 안의 우측 상단, 닫기 버튼 아래에 붙어 있는 GUI | TUI 탭으로 전환합니다. 응답 작성자 이름 옆에는 에이전트 아이콘이 표시됩니다. 도구 내역을 펼치면 파일 언어와 셸 명령어에 맞는 구문 강조, 읽기 편한 스크롤 영역과 복사 기능을 사용할 수 있습니다. 언어를 식별하지 못한 출력은 일반 텍스트로 표시합니다.

에이전트 패널의 GUI | TUI 탭으로 기존 계정과 작업 폴더를 유지하며 같은 대화를 이어갈 수 있습니다. 새 Claude Code 대화는 첫 메시지를 보내기 전에도 터미널로 열 수 있으며, 아직 없는 기록 파일을 재개하려 하지 않습니다. 작업 중에도 TUI 전환을 요청할 수 있습니다. 현재 작업은 GUI에서 계속 실행되고 응답·승인·대기 작업이 끝나고 소유권 확인을 통과하면 자동으로 전환합니다. GUI를 선택하면 전환 예약을 취소합니다. 실행 중인 모델 요청을 다른 프로세스로 즉시 이동하는 방식은 아닙니다. 네이티브 TUI에서 GUI로 돌아올 때는 GUI 실행 주체를 시작하기 전에 CLI가 정상 종료되어야 하며, TUI를 선택하면 복귀 요청을 취소합니다. 백그라운드 작업이 남아 있거나 프로세스 소유권을 확인할 수 없으면 전환을 거부하고 해당 작업을 계속 실행합니다. 이전 에이전트의 종료가 끝난 뒤에만 터미널을 열며, 전환이 막힌 이유를 안내합니다.

지원되는 Claude Code 모드가 연결되어 있으면 GUI를 선택하는 것만으로 입력창이 유휴 상태이고 비어 있을 때 자동 복귀합니다. 실행 중 작업·승인·작성 중인 초안·보고된 셸/Monitor 작업 표시가 있으면 복귀를 보류합니다. TUI를 선택하면 예약을 취소합니다. Claude 자체의 정상 종료 기능을 사용하며 종료를 확인한 뒤 같은 대화를 다시 연결합니다. 추가된 사용자·에이전트 텍스트를 가져오고 이미지는 첨부 안내로 표시합니다. 이전 기록이 달라졌다면 보관한 GUI 기록을 유지하고 불일치를 알립니다.

Kiln에 등록된 셸 함수로 실행한 대화형 claude, codex, agy 명령에서도 같은 GUI | TUI 탭을 사용할 수 있습니다. Kiln은 해당 터미널에 연결된 실행 중 호스트가 정확히 확인된 뒤에만 패널을 연결합니다. 원래 PTY와 부모 셸, 명령 인수, 선택한 계정 프로필을 유지합니다. Kiln의 zsh 또는 PowerShell 연동이 제공하는 함수에 적용되며, 등록되는 명령은 셸에 따라 다릅니다.

Codex·Antigravity·이전 작업 프로세스나 Claude 모드가 지원되지 않거나 비활성화된 환경에서는 GUI를 선택한 뒤 CLI를 정상 종료하세요. 해당 CLI가 지원하면 /exit 또는 Ctrl+D를 사용할 수 있습니다. 안내 문구로 자동 복귀와 수동 종료를 구분합니다. 앱 업데이트는 기존 작업 프로세스를 유지하며, 자동 복귀 연결은 업데이트한 작업 프로세스에서 새로 연 네이티브 실행에 적용됩니다. 처음 연 TUI에서 GUI를 요청하지 않고 종료하면 원래 셸로 돌아갑니다.

관리·출력 전용·원격 명령, 파이프라인, 입력·출력 리다이렉션, Kiln 연동을 거치지 않는 사용자 별칭이나 함수는 기존 네이티브 실행 경로를 유지합니다. Bash와 fish에는 에이전트 래퍼를 자동 등록하지 않습니다. Kiln 밖의 터미널에서 실행한 명령은 자동 추적하지 않습니다.

이전에 터미널로 시작한 에이전트는 정확한 네이티브 대화가 추적된 경우에만 GUI로 가져올 수 있습니다. 먼저 해당 CLI를 종료하세요. 터미널 데몬이 기존 프로세스의 종료를 확인한 뒤, 기록된 계정 환경과 작업 폴더로 같은 대화를 엽니다. 연결이 끊겼거나 대화를 식별하지 못했다는 사실만으로 가져오기를 시작하지 않습니다.

Codex 용량 초과 복구

Kiln이 열려 있는 동안, Kiln이 관리하는 Codex 패널은 서버 과부하로 Codex가 중단한 턴을 다시 시도합니다. 재시도는 이 Codex 오류에서만 시작되며, 사용량 한도, 로그인 실패, 스트림 오류, 취소된 턴, 성공한 턴에는 관여하지 않습니다.

  • 재시도 간격은 15, 30, 60, 120, 240초입니다. 패널에는 카운트다운과 자동 재시도 취소 버튼이 표시됩니다.
  • 실패한 뒤 패널에 입력하면 대기 중인 재시도가 취소됩니다. 프롬프트를 일부만 입력해도 마찬가지입니다.
  • 직접 새 요청을 보내면 재시도가 처음부터 다시 시작됩니다.
  • 재시도할 때도 같은 계정과 모델을 씁니다.

Codex CLI가 아직 열려 있으면 Kiln은 같은 대화에 이어 가기 프롬프트를 한 번 보냅니다. CLI가 이미 종료되었다면 원래 계정과 작업 디렉터리로 같은 대화를 재개한 뒤 프롬프트를 보냅니다. 이 프롬프트는 이미 끝낸 동작을 반복하기 전에 현재 상태부터 확인하라고 Codex에 요청합니다. 원래 요청을 다시 보내지 않으며, 실패한 턴에서 생긴 변경도 되돌리지 않습니다.

재시도는 저장된 계정으로 연 Codex 패널 가운데 Kiln이 대화를 확인한 패널에만 적용됩니다. Kiln이 실행 중인 CLI를 지켜보기 전에 일어난 실패는 직접 처리해야 합니다.

Kiln이 여는 새 Codex 패널은 --no-daemon으로 실행되므로 Codex 자체의 공유 백그라운드 서버와 별개로 동작합니다. Codex 세션에 Background server has incompatible feature settings가 표시되면, 그 세션의 기능 플래그가 서버에 저장된 값과 다르다는 뜻입니다. 이때는 다음 중 하나를 고를 수 있습니다.

옵션 효과
Run without daemon this time 공유 Codex 서버를 재시작하지 않고 이 세션을 시작합니다. CLI의 codex --no-daemon과 같습니다.
Restart with these settings 공유 설정을 바꿉니다. 다른 클라이언트에서 진행 중이거나 대기 중인 작업이 중단될 수 있으니 먼저 확인하세요.

새로 연 Kiln Zsh 터미널에서 직접 입력하는 codex, codex resume …, codex fork …에도 --no-daemon이 적용됩니다. 따라서 공유 서버가 Server is draining; retry after reconnecting을 반환해도 이 명령들은 독립적으로 시작합니다. 명시적인 --remote 연결, 기존 별칭·함수, 그 밖의 명령 형식과 다른 셸은 기존 방식대로 동작합니다. 래퍼를 건너뛰려면 command codex …를 사용하고, 로컬 세션을 직접 실행할 때는 --no-daemon을 붙이세요. 기존 셸은 다시 열어야 적용됩니다. Kiln은 공유 서버를 재시작하거나 업데이트 설정을 바꾸지 않습니다.

네이티브 대화 설정과 명령

응답 처리 중에도 보내기 버튼이나 Enter로 후속 메시지를 보낼 수 있으며, 중지 버튼은 별도로 유지됩니다. Claude는 스트리밍 후속 입력을 받고 Codex는 현재 턴에 입력을 추가합니다. Antigravity는 현재 요청이 끝날 때까지 후속 메시지 하나를 보관합니다. 전송 확인 대기와 수신 완료를 구분하며 자동으로 다시 보내지 않습니다.

응답 처리 중에도 모델·추론 강도·모드를 선택할 수 있습니다. Claude는 네이티브 적용 시점에 변경하고, Codex 입력창의 선택은 다음 턴에 적용합니다. Codex의 명시적인 현재 턴 설정 작업은 지원되는 설정을 현재 턴에 적용합니다. 설정은 네이티브 확인을 기다립니다. 워크스페이스 내역은 제공자 이름 대신 대화 제목을 표시하며 사용자가 지정한 페이지 제목을 유지합니다.

대화 GUI의 대화 설정에서 공급자별 설정을 검색하고 명령 및 스킬에서 네이티브 명령을 찾으세요. 두 줄 입력창 아래 한 줄 도구 모음에서 이미지를 첨부하고 모델·모드를 고르며 사고 설정을 열거나 원형 보내기·중지 버튼을 사용할 수 있습니다. 좁은 패널에는 모델과 대화 옵션을 표시하고 나머지 설정은 대화 옵션에 담습니다. 모델 이름은 읽기 쉽게, 모드·추론 강도는 앱 언어로 표시하되 공급자에게 전달하는 값은 유지합니다. 아직 받지 못한 목록과 빈 목록도 구분합니다.

사고 설정이나 좁은 패널의 대화 옵션에서 각 단계의 설명을 읽고 추론 강도를 선택할 수 있습니다. Claude의 Ultracode는 독립된 스위치이며, 켜지면 보라색으로 표시합니다. 헤더는 적용이 확인된 모델과 모드를 보여 줍니다.

Claude Code, Codex, Antigravity의 설정과 기본 선택지는 앱 언어로 이름과 동작 설명을 함께 표시합니다. 한국어에서는 승인 정책도 ‘필요할 때 승인 요청’처럼 표시합니다. 새 대화 설정, 현재 턴 설정, 샌드박스와 세부 승인 항목에도 같은 기준을 적용합니다. 제공자나 사용자가 정한 고유 이름과 실제 전송 값은 유지됩니다.

모델 비교는 현재 모델을 먼저 보여 주고, 모델 이름·특징·기본 추론 강도·지원 입력을 카드로 정리합니다. ‘이 모델 사용’으로 바로 선택할 수 있으며, 선택 결과는 제공자 확인 후 적용됩니다. 상세 정보에서 지원 단계와 제공자 설명 원문을 확인할 수 있습니다.

네이티브 UI에 예시 목록을 넣어 렌더링한 화면입니다. 실제 계정의 모델 응답이 아닙니다.

설정을 변경하면 요청값과 네이티브 값을 따로 표시합니다. 네이티브 확인을 기다리는 동안 전송과 충돌하는 설정 변경을 막고 중지는 계속 사용할 수 있습니다. 전송 수락만으로 설정 적용을 확정하지 않습니다. 거부되거나 미확인된 변경은 표시하며 자동 재시도하지 않습니다.

명령 및 스킬에는 검색 아이콘, 검색 초기화와 높이가 제한된 스크롤 목록이 있습니다. 이름을 왼쪽에 정렬하며 행을 펼치면 전체 설명과 세부 정보를 읽을 수 있습니다. 이름·설명·별칭을 검색하고, GUI에서 실행할 수 없는 터미널 전용 항목과 스킬은 숨깁니다. 항목을 선택하면 기존 내용과 이미지를 유지한 채 편집 가능한 초안에만 삽입합니다. Codex 스킬의 네이티브 입력도 명시적으로 보낼 때까지 보관합니다.

/를 입력하면 짧은 설명이 있는 자동완성 목록이 열립니다. Codex 스킬은 $로도 완성할 수 있습니다. 위·아래 방향키로 고르고 Tab이나 Enter로 삽입하며 Esc로 닫습니다. 자동완성으로 메시지가 전송되지는 않습니다. 인식된 명령·스킬은 일반 문장과 구분해 표시합니다. 네이티브 스킬이 바뀌면 목록을 새로 고치세요.

대화 설정에는 GUI에서 실제로 바꿀 수 있는 항목을 응답·작업 방식·컨텍스트·권한별로 묶어 표시합니다. 읽기 전용 목록과 사용할 수 없는 설정은 노출하지 않습니다. 변경 기록·기본값 복원·참고 정보는 세부 정보에서 확인합니다. CLI 화면이 필요하면 새 작업에서 별도 터미널을 여세요.

새 대화 설정은 현재 선택한 계정과 지정한 시작 옵션으로 별도 대화를 엽니다. 현재 세션과 초안은 유지되며 프롬프트를 재실행하지 않습니다. 검토·목표·대기 작업 같은 네이티브 작업은 명시적인 실행 버튼으로만 시작합니다. 현재 턴 설정은 확인된 실행 중 턴의 이후 작업에 적용되며 이미 시작한 작업을 바꾸지 않습니다.

질문과 알려진 MCP 작업을 포함한 도구 제목은 앱 언어를 따릅니다. 카드를 펼치거나 제목에 마우스를 올리면 원래 도구 이름을 확인할 수 있으며 인수·출력·질문·변경 내용은 원문을 유지합니다. 언어 변경은 이전 기록의 제목에도 반영됩니다. 알 수 없는 작업은 외부 도구로 표시합니다. 확장 준비나 이전 캐시 보존 상태는 네이티브 로드 완료를 뜻하지 않습니다.

메시지에서 @를 입력하면 현재 작업 폴더의 파일과 폴더를 검색합니다. 방향키로 고르고 Tab으로 폴더를 탐색하며 Enter로 삽입하고 Esc로 닫습니다. 공백이나 한글이 있는 경로도 따옴표로 보존합니다. 선택은 초안만 바꾸며 전송은 별도 동작입니다. Claude에는 네이티브 @ 참조 형식, Codex에는 정식 TUI와 같은 경로 텍스트, Antigravity에는 선택한 전체 경로를 전달합니다. 공급자의 권한과 컨텍스트 처리 규칙은 그대로 적용됩니다.

ドキュメントKiln を使う

Claude Code・Codex・Antigravity の実行

Claude Code・Codex・Antigravity を会話 GUI またはターミナルで実行し、設定・コマンド・権限・保存される下書きを操作します。

Kiln は、Claude Code、Codex、Google の Antigravity CLI（agy）をワークスペースのパネルで実行します。リクエストを書いてエージェントを選ぶだけで、ターミナルを探し回らなくても、すべての作業の状態をサイドバーで確認できます。

始める前に

エージェントは外部のツールです。使うエージェントごとに公式の CLI をインストールし、ログインしておいてください。Kiln にはどのエージェントのサブスクリプションも含まれていません。

  • Claude Code と Codex: CLI をインストールしてから、設定 → アカウントでアカウントを追加します。詳しくはアカウントを参照してください。
  • Antigravity: Google のインストーラーで agy をインストールします。macOS では設定 → アカウント → Antigravity からログインします。Windows では、ターミナルで agy を実行してログインします。Kiln は agy を PATH、~/.local/bin、/opt/homebrew/bin、/usr/local/bin から探します。

Windows では、Claude Code と Codex はネイティブの Windows プログラムとして動作し、ホームディレクトリは %USERPROFILE%\.codex と %USERPROFILE%\.claude です。

作業を開始する

新しい作業を選んでリクエストを入力し、エージェントを選んで開始します。エージェントの選択欄（Claude Code、Codex、Antigravity）は、常にリクエスト入力欄のすぐ下にあります。リポジトリのコンテキストは別にスクロールするので、概要が長くても開始ボタンが画面の外に押し出されることはありません。

Antigravity では、次の方法も使えます。

操作 内容
新しい作業 → Antigravity 現在のワークスペースで agy を起動します。
新しい作業 → フォルダーで開く → Antigravity 先にフォルダーを選ぶよう求め、そのフォルダーで agy を起動します。
Antigravity の新規タスク（コマンドパレット、⌘K） Antigravity の作業を開始します。

リクエストの下で Antigravity を選ぶと、Kiln はリクエストとリポジトリの概要を最初のプロンプトとして agy に渡します。antigravity コマンドは Antigravity のエディターを開くものなので、Kiln はエージェントとして扱いません。

未送信のリクエストはワークスペースと一緒に保存され、Kiln を再び開くと復元されます。ワークスペースを閉じるときは、破棄する前に確認が表示されます。

パネル上部の右分割・下分割ボタンから、新しいパネルで開くターミナルやエージェントを選べます。分割のショートカットはターミナルを直接開きます。

会話画面またはターミナル

新規タスクと右/下分割メニューで、エージェントを選ぶ前に 会話 GUI または ターミナルを選択します。新しいエージェントは会話 GUI が既定です。設定 → 動作 → 新規エージェントの表示で変更できます。通常のターミナル、SSH、既存のターミナルタスクは現在の表示を維持します。

会話画面にはストリーミング Markdown、展開できるツール入出力とファイル diff が表示されます。権限要求や質問に画面内で回答でき、許可と拒否の両方を選べます。ヘッダーは起動時のアカウントを固定し、適用が確認されたモデルとモードを示します。入力欄にはプロバイダーが公開したモデルとモードだけが表示され、既存の MCP と権限設定は維持されます。

Enter または 送信 で送信し、Shift+Enter で改行します。IME の変換中や確定操作では送信されません。画像を添付 で複数のファイルを一度に選ぶか、メッセージ入力欄にフォーカスを置いて画像を貼り付けるか、添付先の会話ペインにファイルをドロップしてください。下書きごとに最大 8 枚（PNG、JPEG、GIF、WebP、各 20 MiB）を添付できます。テキストの貼り付けは通常どおり入力されます。サムネイルで画像を確認し、各画像の × ボタンで送信前に削除できます。復元された添付が見つからない場合や無効な場合は、削除してから送信してください。停止 は現在のターンを中断します。

Kiln を閉じると下書きが保存され、デーモンはワーカーを維持します。パネルを閉じるとセッションが終了し、下書きの破棄前に確認します。ローカル送信はジャーナルの確認を待ち、再表示しても再送しません。未確認の送信は 下書きに戻すで復元できます。意図的に再送する前に履歴を確認してください。失敗や切断時も履歴は残り、同じ会話で再起動できます。以前/最新のメッセージ操作は履歴を削除せず、表示範囲を移動します。

承認カードには翻訳済みの見出しとコマンド、作業フォルダー、対象パス、理由、要求権限を表示し、通信 ID やスキーマは表示しません。履歴の読み込み後、ジャーナルと送信待ち一覧に存在しない以前の送信は、ワーカーが準備完了でも明示的に下書きへ戻せます。自動再送はしません。

Claude の承認カードには業務 ID を含む実際の MCP・ツール引数を表示します。長い入力は一部のみの表示と明示し、Codex の通信パラメーターやスキーマは引き続き表示しません。下書きの復元は、以前のクライアントによる最後の送信書き込みを反映した確認を待ちます。

入力欄の上の状態表示で、応答作成・ツール実行・入力待ち・応答完了を区別できます。過去のメッセージを読んでいる間も表示されます。Claude が報告したシェル・Monitor・その他のバックグラウンドタスクの説明、状態、進捗、提供された実行時間を確認でき、各タスクを開くと詳細が表示されます。常駐の監視タスクは、応答作成中とは区別して一覧に残ります。他の AI でも報告された実行中のツールを表示します。上へスクロールしたときや過去の履歴を開いたときは、↓ 最新メッセージへで下書きを保ったまま最新の履歴へ戻れます。

シェル・Monitor の詳細の 出力を表示 · 更新 は、AI に新しい要求を送らずに最新の出力を読み取ります。末尾のみの表示、出力なし、取得不可を区別します。

同じ会話の表示を切り替える

待機中の GUI→TUI 切り替えでは、会話に保存された環境変数と作業フォルダーで MCP コマンドを確認します。MCP 固有の PATH 設定も反映します。MCP サービスの接続自体は、モデルの処理中を意味しません。

作業中もTUIへの切り替えを要求できます。現在の作業はGUIで続行し、応答・承認・待機作業が終わり所有権の確認に成功すると自動で切り替えます。GUIを選ぶと予約を取り消せます。実行中のモデル要求を別プロセスに即座に移す方式ではありません。ネイティブTUIからGUIに戻る場合は、GUIの実行主体を開始する前にCLIの正常終了が必要です。TUIを選ぶと復帰要求を取り消せます。

パネルのタイトルと自動作業名には、最初に送信したリクエストを短く表示します。手動で付けた名前は維持され、下書きの編集で既存の会話名は変わりません。

各エージェントの表示領域の右上、閉じるボタンの下にある一体型の GUI | TUI タブで切り替えます。返信には名前とエージェントのアイコンを表示します。ツールの詳細を開くと、判別できるファイル言語とシェルコマンドの構文強調、読みやすいスクロール領域、コピー機能を利用できます。判別できない出力は通常のテキストで表示します。

エージェントペインの GUI | TUI タブで、元のアカウントと作業フォルダーを保ちながら同じ確認済みの会話を続けられます。新しい Claude Code の会話は最初のメッセージを送る前でもターミナルで開けます。まだ存在しない履歴ファイルを再開しようとはしません。切り替え要求は作業中も受け付け、応答・承認・送信待ちが終了してから実行します。バックグラウンドタスクが残っている場合やプロセスの所有権を確認できない場合は、切り替えを拒否してその処理を維持します。前のエージェントの終了を確認してからターミナルを開き、切り替えられない場合は理由を表示します。

対応する Claude Code の mod が接続されていれば、GUI を選ぶと、ネイティブ入力欄が待機中で空になった時点で自動復帰します。実行中の処理、承認、入力中の下書き、報告された shell/Monitor の表示がある間は復帰を保留します。TUI で予約を取り消せます。Claude 自身の正常終了機能を使い、終了を確認してから同じ会話を再接続します。追加されたユーザーとアシスタントのテキストを取り込み、画像は添付の案内として表示します。以前の履歴に不一致があれば GUI 履歴を保持して通知します。

Kiln が登録したシェル関数から起動した対話型の claude、codex、agy コマンドでも、同じ GUI | TUI タブを使えます。Kiln は、そのターミナルに対応する稼働中ホストの正確な関連付けを確認してからペインを接続します。元の PTY、親シェル、コマンド引数、選択したアカウントプロファイルを維持します。Kiln の zsh または PowerShell 連携が提供する関数が対象で、登録されるコマンドはシェルによって異なります。

Codex、Antigravity、古いワーカー、mod が使えないか無効な Claude では、GUI を選んでから CLI を正常終了してください。対応していれば /exit または Ctrl+D を使えます。案内は自動復帰と手動終了を区別します。アプリの更新は既存のワーカーを維持します。自動復帰の接続は更新済みワーカーから新しく開くネイティブ実行に適用されます。最初の TUI で GUI を要求せず終了すると元のシェルに戻ります。

管理用・出力専用・リモートのコマンド、パイプライン、入出力のリダイレクト、Kiln 連携を経由しないユーザーのエイリアスや関数は、通常のネイティブ実行を続けます。Bash と fish にはエージェントのラッパーを自動登録しません。Kiln 外のターミナルで実行したコマンドは自動追跡しません。

以前ターミナルから起動したエージェントを GUI に取り込むには、正確なネイティブ会話が追跡されている必要があります。まずその CLI を終了してください。ターミナルデーモンが元のプロセスの終了を確認してから、記録されたアカウント環境と作業フォルダーで同じ会話を開きます。切断や会話の識別失敗だけでは、取り込みを開始しません。

複数のリポジトリにまたがって作業する

フロントエンド、バックエンド、共有ライブラリが別々の Git リポジトリにある場合は、~/dev/projects のような親フォルダーを開きます。Kiln はそのフォルダーをエージェントの作業ルートとして保ち、検出したリポジトリ構成をリクエストに含めることができるため、1 つのリクエストですべてのリポジトリを扱えます。

Git や GitHub のツールでリポジトリを確認しても、作業ディレクトリは変わりません。Git 操作の対象を 1 つのリポジトリにするには、それらのツールにあるリポジトリセレクターを使います。詳しくはワークスペースと作業と Git と GitHub を参照してください。

作業の状態を確認する

サイドバーの各作業の行には、エージェントが報告した状態が表示されます。

状態 意味
作業中 エージェントが作業しています。
入力待ち エージェントが入力を求めています。
完了 エージェントが作業を終えました。
失敗 エージェントが失敗を報告しました。
セッション開始済み 状態が報告されていません。Kiln は推測せず、開いているセッションとして表示します。

並び順は、実行中の作業、入力待ちのリクエスト、以前に失敗した作業の順です。作業をクリックすると、そのワークスペース、タブ、分割に移動します。拡大表示で隠れているパネルも表示されます。

Kiln が状態を知る仕組み

Kiln が状態を正確に表示するには、エージェントが状態を報告するか、Kiln が認識できる実行中のタイトルを表示する必要があります。

  • Kiln は Claude Code と Codex のターミナルタイトルにあるアクティビティマーカーを認識するため、追加の設定なしで実行中のアクティビティが表示されます。
  • Claude Code の ✳ マーカーはダイアログが開いている間にも表示されるため、完了とは見なしません。
  • 明示的な入力待ちと失敗のシグナルは、タイトルのマーカーより優先されます。
  • アイドル状態のターミナルが完了した作業として扱われることはなく、終了していない起動コマンドによって、アイドル状態のエージェントが実行中と表示されることもありません。

スクリプトやその他のツールは、kiln activity running、waiting、done、failed で状態を報告できます。アクティビティの報告と通知についてはターミナルを参照してください。

通知と使用量の上限

通知センターには最近の通知が残り、各通知は対応するセッションにひも付いています。通知を読むと、そのセッションの要確認状態が解除されます。Windows では、エージェントの通知が Windows のトースト通知として表示されます。

Antigravity がクォータの上限に達したと報告すると、Kiln はリセット時刻を添えて使用量上限の通知を表示します。Claude Code と Codex では、パネルは開いたときのアカウントを使い続けます。アカウントが使用量の上限に達したら、設定 → アカウントで別のアカウントに切り替え、新しいパネルを開いてください。詳しくはアカウントを参照してください。

Codex の混雑時の自動復旧

Kiln が開いている間、Kiln が管理する Codex のパネルでは、サーバーの混雑が原因で Codex が終了したターンを再試行します。再試行が始まるのは、この特定の Codex エラーのときだけです。使用量の上限、ログインの失敗、ストリームのエラー、キャンセルされたターン、成功したターンは再試行の対象外です。

  • 再試行までの待ち時間は 15、30、60、120、240 秒です。パネルにはカウントダウンと自動再試行をキャンセルボタンが表示されます。
  • 失敗の後にパネルで何か入力すると、入力途中のプロンプトであっても、保留中の再試行はキャンセルされます。
  • 自分で新しいリクエストを送信した場合、再試行は改めて 1 回目から数えられます。
  • 再試行では同じアカウントとモデルを使います。

Codex CLI がまだ開いている場合、Kiln は同じ会話に続行用のプロンプトを 1 回送ります。CLI が終了している場合は、元のアカウントと作業ディレクトリで同じ会話を再開してから、そのプロンプトを送ります。このプロンプトは、完了済みの操作を繰り返す前に現在の状態を確認するよう Codex に求めるものです。元のリクエストを再送することはなく、失敗したターンの間に行われた変更が元に戻されることもありません。

再試行の対象は、保存済みのアカウントで開いた Codex のパネルのうち、Kiln が会話を確認できたものです。実行中の CLI を Kiln が監視し始める前に起きた失敗は、自分で対処してください。

Codex のバックグラウンドサーバーの設定

Kiln が新しく開く Codex のパネルは --no-daemon で実行されるので、Codex 本体の共有バックグラウンドサーバーからは独立しています。Codex のセッションが Background server has incompatible feature settings（バックグラウンドサーバーの機能設定に互換性がありません）と報告した場合は、そのセッションの機能フラグが、サーバーに保存されている設定と食い違っています。次のいずれかを選べます。

オプション 効果
Run without daemon this time（今回はデーモンなしで実行） 共有の Codex サーバーを再起動せずに、このセッションを開始します。CLI では codex --no-daemon に相当します。
Restart with these settings（この設定で再起動） 共有の設定を変更します。ほかのクライアントの実行中または待機中の処理が中断される場合があるため、先に確認してください。

新しく開いた Kiln の Zsh ターミナルでは、直接入力する codex、codex resume …、codex fork … にも --no-daemon が適用されます。共有サーバーが Server is draining; retry after reconnecting を返しても、これらのコマンドは独立して起動します。明示的な --remote 接続、既存のエイリアスや関数、その他のコマンド形式とシェルは従来どおりに動作します。ラッパーを使わない場合は command codex … を、ローカルセッションを直接実行する場合は --no-daemon を使用してください。既存のシェルには開き直した後で適用されます。Kiln は共有サーバーを再起動したり、更新設定を変更したりしません。

ネイティブの会話設定とコマンド

応答中も送信ボタンまたはEnterで追加メッセージを送信できます。停止ボタンは別に表示されます。Claudeはストリーミング追加入力を受け取り、Codexは現在のターンに入力を追加します。Antigravityは現在の要求が完了するまで追加メッセージを1件保持します。受領確認待ちと受領済みを区別し、自動再送しません。

応答中もモデル・推論強度・モードを選択できます。Claudeはネイティブの適用タイミングで変更します。Codexの入力欄の選択は次のターンに適用され、明示的な現在のターン設定アクションは対応する設定を現在のターンに適用します。設定はネイティブの確認を待ちます。ワークスペースの履歴にはプロバイダー名ではなく会話タイトルを表示し、独自のページタイトルは保持します。

会話 GUI の セッション設定でプロバイダーの設定を検索し、コマンドとスキルでネイティブのコマンドを探せます。コンパクトな 2 行の入力欄の下に、画像添付、モデル・モード、推論設定、丸い送信・停止ボタンを 1 行にまとめています。狭いパネルではモデルと 会話オプションを表示し、残りの設定を会話オプションにまとめます。モデル名は読みやすく、モードと推論の強度はアプリの言語で表示し、プロバイダーへ送る値は保持します。未取得の一覧と空の一覧も区別します。

推論設定や狭いパネルの対話オプションで、各ステップの説明を読み、推論の強さを選択できます。ClaudeのUltracodeは独立したスイッチであり、オンにすると紫色で表示されます。ヘッダーには、適用が確認されたモデルとモードが表示されます。

Claude Code、Codex、Antigravityの設定およびデフォルトの選択肢では、アプリの言語で名前と動作の説明が併記されます。韓国語では、承認ポリシーも「必要なときに承認をリクエスト」のように表示されます。新しいダイアログ設定、現在のターン設定、サンドボックス、および詳細な承認項目にも、同じ基準が適用されます。プロバイダーやユーザーが設定した固有の名前と実際の送信値は維持されます。

モデルの比較では、まず現在のモデルが表示され、モデル名・特徴・基本推論強度・対応入力がカード形式でまとめられています。「このモデルを使用」を選択するとすぐに利用でき、選択結果はプロバイダーの確認後に適用されます。詳細情報では、対応レベルとプロバイダーの説明原文を確認できます。

ネイティブ UI にサンプル一覧を表示した画像です。実際のアカウントのモデル応答ではありません。

設定を変更すると、要求した値とネイティブ値を別々に表示します。ネイティブの確認待ちの間は送信と競合する設定変更を止め、停止は引き続き使えます。送信の受理だけでは設定の適用を確定しません。拒否・未確認の変更は表示を維持し、自動で再試行しません。

コマンドとスキルには検索アイコン、検索のクリア、高さを制限したスクロール一覧があります。名前は左揃えで、行を展開すると説明全文と詳細を読めます。名前・説明・別名を検索し、GUI から実行できないターミナル専用項目やスキルは表示しません。選択すると既存の本文と画像を保持して、編集可能な下書きにだけ挿入します。Codex スキルのネイティブ入力も、明示的に送信するまで保持します。

/ を入力すると短い説明付きの補完一覧が開き、Codex スキルは $ からも補完できます。上下キーで選択、Tab または Enter で挿入、Esc で閉じます。補完操作ではメッセージを送信しません。認識したコマンド・スキルは通常の文章と区別して表示します。ネイティブスキルを変更したら一覧を更新してください。

セッション設定には GUI で実際に変更できる項目だけを、応答・作業方法・コンテキスト・権限別に表示します。読み取り専用の一覧と利用できない設定は表示しません。変更履歴・初期値への復元・参考情報は詳細から確認できます。CLI が必要な場合は 新しいタスクから別のターミナルを開いてください。

新しい会話の設定は、現在選択中のアカウントと明示した起動オプションで別の会話を開きます。現在のセッションと下書きを保持し、プロンプトを再実行しません。レビュー・目標・待機タスクなどのネイティブ操作は、明示的な実行ボタンからのみ開始します。現在のターン設定は、確認された実行中ターンの以降の処理に適用し、開始済みの処理は変更しません。

質問や既知の MCP 操作を含むツールの見出しはアプリの言語で表示します。カードを展開するか見出しにポインターを合わせると元のツール名を確認でき、引数・出力・質問・差分は原文のままです。言語変更は既存の履歴の見出しにも反映されます。不明な操作は外部ツールとして表示します。拡張の準備や古いキャッシュの保持は、ネイティブの読み込み完了を意味しません。

メッセージに @ を入力すると、現在の作業フォルダーのファイルとフォルダーを検索できます。矢印キーで選び、Tab でフォルダーを参照し、Enter で挿入、Esc で閉じます。空白や日本語を含むパスも引用符で保持します。選択は下書きだけを変更し、送信は明示操作です。Claude はネイティブの @ 参照形式、Codex は正式 TUI と同じパステキスト、Antigravity は選択したフルパスを受け取ります。プロバイダーの権限とコンテキスト処理ルールは引き続き適用されます。

这些代理都是外部工具。请为要用的每个代理安装官方 CLI 并登录。Kiln 不含其中任何一个的订阅。

按 Enter 或发送提交，按 Shift+Enter 换行。输入法组合与确认输入不会提交。使用附加图片一次选择多个文件，或在消息输入框获得焦点时粘贴图片，也可以将文件拖放到目标对话面板。每份草稿最多可附加 8 张图片（PNG、JPEG、GIF、WebP，每张 20 MiB）。粘贴文本仍会正常输入文字。通过缩略图检查图片，并使用每张图片的 × 按钮在发送前移除。恢复的附件缺失或无效时，请先移除再发送。停止会中断当前轮次。

切换同一对话的显示方式

空闲时从 GUI 切换到 TUI，会使用会话保存的环境变量和工作目录验证 MCP 命令，并遵循 MCP 自身的 PATH 设置。MCP 服务保持连接并不表示模型正在执行任务。

工作进行中也可请求切换到TUI。当前工作继续在GUI中运行，回复、审批和排队工作结束并通过所有权检查后自动切换。选择GUI可取消切换请求。这不是将正在执行的模型请求立即移至另一个进程。原生TUI返回GUI时，CLI仍须正常退出后才会启动GUI执行方；选择TUI可取消返回请求。

窗口标题和自动任务名称使用首次已发送请求的简短内容。手动命名的任务保留原名，编辑草稿不会改变已有对话标题。

每个代理窗口内容区域的右上角、关闭按钮下方都有连在一起的 GUI | TUI 标签。回复的代理名称旁会显示对应图标。展开工具详情后，可查看易读的滚动代码区域，支持已识别文件语言和 shell 命令的语法高亮，并可复制内容。无法识别的输出保持纯文本。

使用代理面板的 GUI | TUI 标签，在原账户和工作文件夹中继续同一个已确认的对话。新建的 Claude Code 对话也可以在发送第一条消息前打开终端，不会尝试恢复尚不存在的历史文件。工作进行中可请求切换，实际切换将在响应、审批和排队任务完成后执行。如果仍有后台任务，或 Kiln 无法验证进程归属，就会拒绝切换并保留这些任务运行。只有前一个代理退出完成后才会打开终端；无法切换时会说明原因。

支持的 Claude Code mod 连接后，选择 GUI 即可在原生输入栏空闲且为空时自动返回。正在执行的任务、审批、未发送的草稿和报告的 shell/Monitor 标记会延后返回。选择 TUI 可取消预约。Kiln 使用 Claude 自身的正常退出功能，确认退出后再连接同一对话。新增的用户和助手文本会被导入，图片显示为附件提示。早期记录不一致时保留 GUI 历史并提示错误。

通过 Kiln 注册的 shell 函数启动的交互式 claude、codex 和 agy 命令，也可以使用相同的 GUI | TUI 标签。Kiln 只会在确认该终端对应的准确、仍在运行的主机绑定后连接面板。原 PTY、父 shell、命令参数和所选账户配置均会保留。此功能适用于 Kiln 的 zsh 或 PowerShell 集成所提供的函数，注册的命令因 shell 而异。

对于 Codex、Antigravity、旧工作进程，以及 mod 不可用或禁用的 Claude，请选择 GUI 后正常退出 CLI。支持时可使用 /exit 或 Ctrl+D。提示会区分自动返回和手动退出。更新应用会保留现有工作进程；自动返回连接适用于更新后的工作进程新启动的原生执行。首次 TUI 未请求 GUI 就退出时返回原 shell。

管理、仅输出和远程命令、管道、输入输出重定向，以及绕过 Kiln 集成的用户别名或自定义函数，仍沿用原生执行方式。Bash 和 fish 不会自动注册代理包装函数。Kiln 外部终端中执行的命令不会被自动跟踪。

对于以前从终端启动的代理，只有准确跟踪到原生对话后才能导入 GUI。请先退出该 CLI。终端守护进程确认原进程已退出后，Kiln 才使用记录的账户环境和工作文件夹打开同一对话。终端断开或无法识别对话，并不能作为开始导入的依据。

跨多个仓库工作

如果前端、后端和共享库分属不同的 Git 仓库，就打开它们的父文件夹，例如 ~/dev/projects。Kiln 把这个文件夹作为代理的工作根目录，还可以把扫描到的仓库结构随请求一起附上，一个请求就能覆盖所有仓库。

在 Git 或 GitHub 工具中查看某个仓库，不会改变任务的工作目录。要让 Git 操作针对某个仓库，请使用这些工具中的仓库选择器。详见工作区与任务和 Git 与 GitHub。

Kiln 如何获知状态

代理必须上报自己的状态，或者显示 Kiln 能识别的运行中标题，Kiln 才能准确显示状态。

  • Kiln 能识别 Claude Code 和 Codex 终端标题中的活动标记，无需额外设置就能显示运行中的活动。
  • Claude Code 的 ✳ 标记不算作完成，因为对话框打开时它也会出现。
  • 显式的等待和失败信号优先于标题标记。
  • 空闲的终端绝不会被当作已完成的任务；启动命令尚未结束，也不会让空闲的代理显示为运行中。

脚本和其他工具可以用 kiln activity running、waiting、done 或 failed 上报状态。活动上报和通知详见终端。

通知与用量限制

通知中心保留最近的通知，每条通知都关联到对应的会话。读过通知后，该会话的待处理状态随即清除。在 Windows 上，代理通知以 Windows 弹窗通知的形式出现。

Antigravity 上报配额已用完时，Kiln 会显示一条用量限制通知，并注明重置时间。对于 Claude Code 和 Codex，面板始终使用打开时的账户。某个账户达到用量限制后，请在设置 → 账户中切换到其他账户，再新开一个面板。详见账户。

Codex 容量恢复

Kiln 打开期间，如果 Codex 因服务器过载而结束了某个回合，由 Kiln 管理的 Codex 面板会重试该回合。只有这一种 Codex 错误会触发重试。用量限制、登录失败、流错误、已取消的回合和成功的回合都不会处理。

  • 重试间隔依次为 15、30、60、120 和 240 秒。面板上会显示倒计时和取消自动重试按钮。
  • 失败后在面板中输入任何内容，都会取消待执行的重试，输入到一半的提示词也算。
  • 你自己提交新请求时，会重新开始一轮重试。
  • 重试沿用同一个账户和模型。

如果 Codex CLI 仍然开着，Kiln 会在同一对话中发送一条继续提示词。如果 CLI 已经退出，Kiln 会用原来的账户和工作目录恢复同一对话，再发送这条提示词。提示词会要求 Codex 先检查当前状态，再决定是否重复已完成的操作。它不会重放你的原始请求，失败回合中做出的更改也不会回滚。

重试只适用于用已保存账户打开、且 Kiln 已确认其对话的 Codex 面板。Kiln 开始监视运行中的 CLI 之前发生的失败，需要你自行处理。

Codex 后台服务器设置

Kiln 新开的 Codex 面板以 --no-daemon 运行，与 Codex 自己的共享后台服务器相互独立。如果某个 Codex 会话提示 Background server has incompatible feature settings，说明该会话的功能标志与服务器保存的不一致。可以选择：

选项 效果
Run without daemon this time 不重启共享的 Codex 服务器，直接启动本次会话。对应的 CLI 命令是 codex --no-daemon。
Restart with these settings 更改共享设置。这可能会中断其他客户端正在进行或排队的工作，请先确认。

在新打开的 Kiln Zsh 终端中，直接输入的 codex、codex resume … 和 codex fork … 也使用 --no-daemon。即使共享服务器返回 Server is draining; retry after reconnecting，这些命令仍可独立启动。显式 --remote 连接、已有别名或函数、其他命令形式和其他 shell 保持原有行为。使用 command codex … 可绕过包装函数，也可以自行添加 --no-daemon 来启动本地会话。已有 shell 需要重新打开才能加载此集成。Kiln 不会重启共享服务器或更改其更新设置。

原生会话设置与命令

回复进行中也可通过发送按钮或Enter发送后续消息，停止按钮保持独立。Claude接收流式后续输入，Codex向当前轮次追加输入。Antigravity会保存一条后续消息，直到当前请求结束。发送确认等待与已接收状态分开显示，不会自动重发。

回复进行中仍可选择模型、推理强度和模式。Claude按原生应用时机更新；Codex输入区的选择用于下一轮，明确的当前轮设置操作可修改当前轮支持的设置。设置仍需等待原生确认。工作区活动列表显示对话标题而不是提供方名称，并保留自定义页面标题。

在对话 GUI 中，使用会话设置搜索提供方设置，使用命令与技能查找原生命令。紧凑的两行输入框下方是一行工具栏，可附加图片、选择模型和模式、打开推理设置，并使用圆形发送或停止按钮。较窄的面板只保留模型和对话选项，其余控件收在对话选项中。模型名称便于阅读，模式和推理强度使用应用语言显示，同时保留传给提供方的实际值。尚未收到的目录与空目录也会明确区分。

在推理设置或窄面板的对话选项中，您可以阅读各步骤的说明并选择推理强度。Claude的Ultracode是一个独立开关，开启时会显示为紫色。标题栏会显示已确认适用的模型和模式。

Claude Code、Codex 和 Antigravity 的设置及基本选项会以应用语言显示名称和操作说明。在韩语中，授权策略也会显示为“在需要时请求授权”等形式。新对话设置、当前回合设置、沙盒以及详细授权项目均采用相同标准。提供方或用户设定的专属名称及实际传输值将予以保留。

模型比较功能会先显示当前模型，并将模型名称、特点、基本推理强度及支持的输入以卡片形式整理呈现。用户可通过“使用此模型”直接进行选择，选择结果将在提供商确认后生效。在详细信息中，可查看支持阶段及提供商的原文说明。

这些图片由原生界面使用示例列表渲染，并非实际账户的模型响应。

更改设置后，请求值和原生值分开显示。等待原生确认时，发送和有冲突的设置操作会暂停，停止按钮仍可使用。传输确认不代表设置已经生效。被拒绝或未确认的更改保持可见，不会自动重试。

命令与技能提供搜索图标、清空搜索操作和限制高度的滚动列表。名称左对齐，展开一行可阅读完整说明和详细信息。可搜索名称、说明和别名，仅限终端的项目以及无法在 GUI 中调用的技能不会显示。选择项目只会插入可编辑草稿，并保留已有文字和图片。Codex 技能的原生输入也会保留到明确发送时。

输入 / 可打开带简短说明的补全列表；Codex 技能也可从 $ 补全。用上下方向键选择，按 Tab 或 Enter 插入，按 Esc 关闭。补全不会发送消息。已识别的命令和技能与普通文字分别显示。原生技能变化后请刷新目录。

会话设置只显示可在 GUI 中实际修改的项目，并按回复、工作方式、上下文和权限分组。只读列表和不可用设置不再显示。更改记录、恢复默认值和参考信息可从详情中查看。需要 CLI 界面时，请从新建任务打开单独的终端。

新对话设置使用当前选定账户和明确指定的启动选项打开独立对话。当前会话与草稿保持不变，也不会重放提示。审查、目标和排队任务等原生操作只会通过明确的执行按钮启动。当前轮次设置作用于已确认的运行中轮次的后续工作，不会更改已开始的工作。

包括提问和已知 MCP 操作在内的工具标题使用应用语言。展开卡片或将鼠标悬停在标题上可查看原始工具名；参数、输出、问题和差异内容保持原文。切换语言也会更新已有历史记录的标题。未知操作显示为外部工具。扩展准备或保留旧缓存的状态不代表已完成原生加载。

在消息中输入 @，即可搜索当前工作目录中的文件和文件夹。使用方向键选择、Tab 浏览文件夹、Enter 插入、Esc 关闭。包含空格或中文的路径也会用引号保留。选择只会修改草稿，发送仍需明确操作。Claude 保留原生 @ 引用格式，Codex 使用与正式 TUI 相同的路径文本，Antigravity 接收所选完整路径。提供方的权限与上下文处理规则仍然适用。

下一条输入建议

Claude Code 发出下一条输入建议时，会在 GUI 的空消息框中显示浅色文字。按 Tab 填入草稿，再按 Enter 或发送提交。Esc 隐藏该条建议。已有输入、附件和输入法组合优先。建议遵循 Claude 的设置和可用性，并非每次回复后都会出现。Kiln 不会自行编造替代建议。

个人扩展与账户范围

新启动时，会为所选私有配置准备受支持的个人 Claude·Codex 技能及自包含插件资源。Claude 还支持可移植的旧版命令、智能体、回复样式及工作流包。项目优先级遵循原生规则；共享 Codex HOME 技能与 Antigravity 资源仍由原生管理。现有账户登录·初始化行为保持不变。原始作者文件不会被修改，后续导入仍保留私有配置中的编辑·删除。状态轮询和恢复工作进程不会重新导入这些资源。

扩展已准备表示导入准备成功；已保留现有扩展表示为仍在使用的进程保留了旧缓存版本。它们都不表示已启用、已加载或已执行，原生发现和执行需要各自的结果。受支持的可移植插件声明能保留包内 hooks·MCP·LSP 配置，准备过程不会运行它们。含凭据的配置、账户关联连接器、不支持的格式、外部路径、例程及调度器状态需要原生设置，或显示诊断。Kiln 不会复制整个配置或账户历史。请参阅原生插件加载。
