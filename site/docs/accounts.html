DocumentationUsing Kiln

Accounts

Save several Claude Code, Codex and Antigravity accounts, sign in through your browser, switch between them and keep usage up to date.

Kiln keeps a profile for each agent account you use, so you can move between personal and work subscriptions without logging out. Open Settings → Accounts to manage Claude Code and Codex subscription accounts, and Antigravity Google accounts on macOS.

Install the official CLI for each agent first. Kiln uses that CLI to sign in and never implements its own OAuth provider or bypasses a provider's account policies.

Add an account

  1. Choose Add Account on the agent's card.
  2. Give the profile a name, such as Personal or Work.
  3. Choose Sign in with browser and complete authentication in your browser.

Kiln waits in the background and saves the profile as soon as the CLI reports a successful sign-in. You do not need to open a terminal or run a login command. While the account settings are open you can follow progress, reopen the sign-in page or cancel. An attempt expires after five minutes.

If the browser callback is unavailable, Claude Code may show a sign-in code instead. Kiln then shows a masked field where you paste that code.

Warning Paste only the sign-in code into that field. Never enter your password or an API key there.

Already signed in with the official CLI? Choose Save Current Login to import that login as a profile.

Choose which account to use

Signing in saves a profile without touching the account your existing CLI sessions use.

  • Choose Apply beside a newly signed-in profile to use it for new sessions.
  • Choose Switch on an existing profile to make it the active one.
  • Rename a profile from its row's menu.

Every saved account keeps its own configuration for the panels Kiln opens, so all of them stay signed in at once. Running agent sessions keep the account they started with. After switching, open a new agent panel to use the new account. A CLI you typed into an ordinary shell keeps using that shell's configuration, and Kiln never restarts it or replaces its credentials.

Kiln does not rotate a running panel to another account when it reaches a usage limit. Choose another account here and open a new panel instead.

Sign in again

Use this when a profile's login needs repairing. You keep the profile instead of deleting and recreating it.

  1. Open the account row's menu and choose Sign in again.
  2. Check the account name and email shown, then choose Sign in with browser.
  3. Sign in with the same account and choose Apply when it completes.

Kiln keeps the profile's name, its place in the list and its conversation history, and does not restart a running terminal. If you pick a different account in the browser, the attempt is rejected. Cancelled and failed attempts also leave the profile intact.

New credentials wait until you choose Apply, so a browser sign-in never silently replaces the login your sessions use. A running CLI that cached its previous login may need to be resumed after you apply the new one.

Sign-in required

When the local credential store confirms that a profile's credentials are gone, its row shows Login Required with a Sign in again button. Kiln checks this in the background while account settings are open and when you refresh.

This is a local check, not proof that the account is valid online. Network failures and an expired access token are not treated as a logout, because the CLI refreshes tokens itself. If a provider rejects a login while local credentials still exist, use Sign in again from the row menu.

Usage updates

Kiln checks every saved Claude Code and Codex account in the background when the app starts and then every five minutes, including inactive profiles. Keep Kiln open. The account settings do not need to stay visible.

  • Each card shows the time of the last successful check and keeps the last known bars when a check fails.
  • The refresh button requests another check, subject to the provider's rate limits.
  • Codex usage windows are labeled only when their reported length matches five hours or seven days.

These checks are read-only. Kiln does not send a model prompt or use reset credits.

Situation What Kiln does
Provider rate limiting Waits as long as the provider asks (between one minute and one day), or five minutes when it does not say. This also delays manual checks.
Rejected credential (401) Pauses checks for that credential for an hour. A newly refreshed token can be checked without waiting.
Other failures Tries again on the next cycle. You can also retry manually.
Unrecognized response Shows usage as unavailable instead of inventing values.

An expired or revoked token can block usage checks while a running CLI still works. If the failure persists, choose Sign in again in that profile's menu.

Antigravity accounts

Note Antigravity accounts are new in Kiln 0.2.12 and available on macOS only. On Windows, sign in by running agy in a terminal.

Save several Google accounts for the Antigravity CLI (agy) and choose which one new tasks use.

  1. Open Settings → Accounts → Antigravity and choose Add Account. Kiln starts the installed CLI's Google sign-in in a temporary private terminal.
  2. Complete the login in your browser. If it displays a code, paste it into Sign-in code and choose Confirm or press Enter. Whitespace introduced by copied line wrapping is removed. Kiln shows Verifying the sign-in code and prevents duplicate submissions while checking it. A rejected or expired code ends the attempt with an error; restart sign-in to obtain a new code. After authentication succeeds, choose Apply.
  3. Repeat for another account, then choose Switch to use it for new tasks.

Running tasks keep their original account. The row menu offers rename, delete and sign in again with the same Google account. Save Current Login imports the ordinary CLI's Google login.

Each account has its own private home and macOS keychain, which also keep its Antigravity preferences, settings and conversations separate. Kiln never replaces the ordinary CLI's login or changes your default keychain. The account home does not include files from your usual home, such as shell, Git or SSH configuration. Your workspace files remain available.

Applied accounts show used percentages and reset times for each model group reported by the official CLI. Usage is checked on startup and every five minutes; you can also refresh manually. These read-only checks require agy 1.1.11 or later and do not start an agent turn or spend model quota. Stale or failed checks hide the percentages. Automatic rotation is not included. When agy reaches its quota, Kiln shows the reset time in a notification. Sign-in uses Google OAuth; Google Cloud project setup is not automated.

New Kiln zsh terminals also use the selected account when you type agy, preserving the arguments and current folder. Open a new terminal after updating. With a custom shell, choose New Task → Antigravity. Kiln keeps its own shell integration active when Kiro is installed, so its selected-account routing also works in those new terminals.

Conversations from these accounts take part in conversation sync, and restarting in the same conversation keeps the original account. See Conversations and updates.

Where credentials are stored

On macOS, Kiln stores saved credentials in the Keychain and never resets or replaces it. On Windows, saved credentials are private files protected with your Windows user key. The account list contains only profile names and metadata, never access or refresh tokens. Sign-in links and codes are not written to settings or logs.

Troubleshooting

  • Sign-in fails: check your browser and network connection, then try again.
  • CLI not found: a missing CLI is reported on the account card. Install the official CLI for that agent.

To update the CLIs themselves, see Conversations and updates.

문서Kiln 사용하기

계정

Claude Code, Codex, Antigravity 계정을 여러 개 저장하고, 브라우저로 로그인하고, 계정을 전환하고, 사용량을 최신 상태로 확인합니다.

Kiln은 사용하는 에이전트 계정마다 프로필을 따로 저장하므로, 로그아웃하지 않고도 개인 구독과 회사 구독을 오갈 수 있습니다. 설정 → 계정에서 Claude Code·Codex 구독 계정과, macOS에서는 Antigravity Google 계정까지 관리합니다.

먼저 에이전트마다 공식 CLI를 설치하세요. Kiln은 그 CLI를 통해 로그인하며, 자체 OAuth 제공자를 구현하거나 제공자의 계정 정책을 우회하지 않습니다.

계정 추가하기

  1. 에이전트 카드에서 새 계정 추가를 선택합니다.
  2. 개인이나 회사처럼 프로필 이름을 정합니다.
  3. 브라우저에서 로그인을 선택하고 브라우저에서 인증을 마칩니다.

Kiln은 백그라운드에서 기다리다가 CLI가 로그인 성공을 알리면 바로 프로필을 저장합니다. 터미널을 열거나 로그인 명령을 실행할 필요는 없습니다. 계정 설정을 열어 두면 진행 상황을 보거나, 로그인 페이지를 다시 열거나, 취소할 수 있습니다. 로그인 시도는 5분이 지나면 만료됩니다.

브라우저 콜백을 쓸 수 없으면 Claude Code가 대신 로그인 코드를 보여 줄 수 있습니다. 이때 Kiln에 가려진 입력란이 나타나며, 여기에 코드를 붙여 넣으면 됩니다.

주의 이 입력란에는 로그인 코드만 붙여 넣으세요. 비밀번호나 API 키는 절대 입력하지 마세요.

공식 CLI로 이미 로그인해 두었다면 현재 로그인한 계정 저장을 선택해 그 로그인을 프로필로 가져오세요.

사용할 계정 고르기

로그인하면 프로필만 저장되고, 기존 CLI 세션이 쓰는 계정은 그대로입니다.

  • 새로 로그인한 프로필 옆의 적용을 선택하면 새 세션부터 그 프로필을 씁니다.
  • 기존 프로필에서 전환을 선택하면 그 프로필이 활성 프로필이 됩니다.
  • 프로필 이름은 해당 행의 메뉴에서 바꿉니다.

저장된 계정마다 Kiln이 여는 패널용 설정을 따로 두므로, 모든 계정이 동시에 로그인 상태를 유지합니다. 실행 중인 에이전트 세션은 시작할 때의 계정을 계속 씁니다. 전환한 계정을 쓰려면 새 에이전트 패널을 여세요. 일반 셸에서 직접 실행한 CLI는 그 셸의 설정을 계속 쓰며, Kiln은 이 CLI를 재시작하거나 자격 증명을 바꾸지 않습니다.

실행 중인 패널이 사용량 한도에 도달해도 Kiln이 다른 계정으로 바꿔 주지는 않습니다. 이 화면에서 다른 계정을 고르고 새 패널을 여세요.

다시 로그인하기

프로필의 로그인을 복구해야 할 때 씁니다. 프로필을 지우고 다시 만들 필요 없이 그대로 유지됩니다.

  1. 계정 행의 메뉴를 열고 다시 로그인을 선택합니다.
  2. 표시된 계정 이름과 이메일을 확인한 뒤 브라우저에서 로그인을 선택합니다.
  3. 같은 계정으로 로그인하고, 완료되면 적용을 선택합니다.

프로필 이름, 목록에서의 위치, 대화 기록은 그대로 유지되고, 실행 중인 터미널도 재시작되지 않습니다. 브라우저에서 다른 계정을 고르면 로그인 시도가 거부됩니다. 시도를 취소하거나 시도가 실패해도 프로필은 그대로입니다.

새 자격 증명은 적용을 선택해야 반영되므로, 브라우저 로그인이 세션에서 쓰는 로그인을 모르는 사이에 바꾸는 일은 없습니다. 실행 중인 CLI가 이전 로그인을 캐시해 두었다면, 새 로그인을 적용한 뒤 그 CLI를 재개해야 할 수 있습니다.

로그인 필요

로컬 자격 증명 저장소에서 프로필의 자격 증명이 사라졌다고 확인되면 해당 행에 로그인 필요와 다시 로그인 버튼이 표시됩니다. Kiln은 계정 설정이 열려 있는 동안과 새로 고침할 때 백그라운드에서 이를 확인합니다.

이 확인은 로컬에서만 이루어지므로, 계정이 온라인에서도 유효하다는 보장은 아닙니다. 토큰은 CLI가 스스로 갱신하므로, 네트워크 오류나 만료된 액세스 토큰은 로그아웃으로 보지 않습니다. 로컬 자격 증명은 남아 있는데 제공자가 로그인을 거부한다면 행 메뉴에서 다시 로그인을 사용하세요.

사용량 업데이트

Kiln은 앱이 시작될 때, 그리고 그 뒤로 5분마다 저장된 모든 Claude Code·Codex 계정의 사용량을 백그라운드에서 확인합니다. 비활성 프로필도 포함됩니다. Kiln을 열어 두기만 하면 되고, 계정 설정 화면을 띄워 둘 필요는 없습니다.

  • 각 카드에는 마지막으로 확인에 성공한 시각이 표시되며, 확인에 실패하면 마지막으로 받은 막대가 그대로 남습니다.
  • 새로 고침 버튼을 누르면 제공자의 요청 한도 안에서 다시 확인합니다.
  • Codex 사용량 구간에는 보고된 길이가 5시간이나 7일과 일치할 때만 이름이 붙습니다.

이 확인은 읽기 전용입니다. Kiln은 모델 프롬프트를 보내지 않고 초기화 크레딧도 쓰지 않습니다.

상황 Kiln의 동작
제공자의 요청 한도 제한 제공자가 요청한 시간(1분~1일)만큼, 따로 알려 주지 않으면 5분 동안 기다립니다. 직접 확인할 때도 이만큼 늦어집니다.
자격 증명 거부(401) 해당 자격 증명의 확인을 1시간 동안 멈춥니다. 새로 갱신된 토큰은 기다리지 않고 확인할 수 있습니다.
그 밖의 실패 다음 주기에 다시 시도합니다. 직접 다시 시도할 수도 있습니다.
인식할 수 없는 응답 값을 지어내지 않고 사용량을 확인할 수 없다고 표시합니다.

토큰이 만료되거나 취소되면, 실행 중인 CLI는 여전히 잘 동작하는데 사용량 확인만 막힐 수 있습니다. 실패가 계속되면 해당 프로필 메뉴에서 다시 로그인을 선택하세요.

Antigravity 계정

참고 Antigravity 계정은 Kiln 0.2.12에서 새로 추가되었으며 macOS에서만 쓸 수 있습니다. Windows에서는 터미널에서 agy를 실행해 로그인하세요.

Antigravity CLI(agy)용 Google 계정을 여러 개 저장해 두고, 새 작업에 쓸 계정을 고를 수 있습니다.

  1. 설정 → 계정 → Antigravity를 열고 새 계정 추가를 선택합니다. Kiln이 임시 비공개 터미널에서, 설치된 CLI의 Google 로그인을 시작합니다.
  2. 브라우저에서 로그인합니다. 코드가 표시되면 로그인 코드에 붙여넣고 확인을 누르거나 Enter를 누릅니다. 복사 과정에서 생긴 줄바꿈과 공백은 제거됩니다. 확인하는 동안 로그인 코드를 확인하고 있습니다가 표시되고 중복 제출은 차단됩니다. 코드가 거절되거나 만료되면 오류와 함께 시도가 종료됩니다. 로그인을 다시 시작해 새 코드를 받으세요. 인증이 완료되면 적용을 선택합니다.
  3. 다른 계정도 같은 방법으로 추가하고, 새 작업에서 그 계정을 쓰려면 전환을 선택합니다.

실행 중인 작업은 원래 계정을 계속 씁니다. 행 메뉴에서 이름 변경, 삭제, 같은 Google 계정으로 다시 로그인을 할 수 있습니다. 현재 로그인한 계정 저장을 선택하면 일반 CLI의 Google 로그인을 가져옵니다.

계정마다 비공개 홈과 macOS 키체인이 따로 있으므로, Antigravity 환경설정, 설정, 대화도 계정별로 분리됩니다. Kiln은 일반 CLI의 로그인을 바꾸거나 기본 키체인을 변경하지 않습니다. 계정 홈에는 셸, Git, SSH 설정처럼 평소 홈 디렉터리에 있는 파일이 들어 있지 않습니다. 워크스페이스 파일은 그대로 쓸 수 있습니다.

적용한 계정에는 공식 CLI가 알려 주는 모델 그룹별 사용 비율과 초기화 시각이 표시됩니다. 앱 시작 시와 5분마다 확인하며 직접 새로 고칠 수도 있습니다. 이 읽기 전용 확인에는 agy 1.1.11 이상이 필요하며 에이전트 턴을 시작하거나 모델 할당량을 소비하지 않습니다. 오래되었거나 실패한 결과의 비율은 숨깁니다. 자동 전환은 제공하지 않습니다. agy가 할당량에 도달하면 초기화 시각과 함께 알림을 띄웁니다. 로그인에는 Google OAuth를 쓰며 Google Cloud 프로젝트 설정은 자동으로 해 주지 않습니다.

새 Kiln zsh 터미널에서 agy를 입력해도 선택한 계정을 사용하며 인수와 현재 폴더를 유지합니다. 업데이트 후에는 새 터미널을 여세요. 다른 셸에서는 새 작업 → Antigravity를 선택하세요. Kiro가 설치되어 있어도 Kiln의 셸 연동을 유지하므로 새 터미널에서 선택한 계정이 사용됩니다.

이 계정들의 대화도 대화 동기화에 포함되며, 같은 대화로 재시작해도 원래 계정이 유지됩니다. 대화와 업데이트를 참고하세요.

자격 증명 저장 위치

macOS에서 Kiln은 저장된 자격 증명을 키체인에 보관하며, 키체인을 초기화하거나 교체하지 않습니다. Windows에서는 저장된 자격 증명을 Windows 사용자 키로 보호되는 비공개 파일에 보관합니다. 계정 목록에는 프로필 이름과 메타데이터만 들어 있고, 액세스 토큰이나 리프레시 토큰은 들어 있지 않습니다. 로그인 링크와 코드는 설정이나 로그에 남기지 않습니다.

문제 해결

  • 로그인이 실패할 때: 브라우저와 네트워크 연결을 확인한 뒤 다시 시도하세요.
  • CLI를 찾을 수 없을 때: CLI가 없으면 계정 카드에 표시됩니다. 해당 에이전트의 공식 CLI를 설치하세요.

CLI 자체를 업데이트하는 방법은 대화와 업데이트를 참고하세요.

ドキュメントKiln を使う

アカウント

Claude Code、Codex、Antigravity のアカウントを複数保存し、ブラウザーでのログイン、アカウントの切り替え、使用量の更新を行う方法を説明します。

Kiln はエージェントのアカウントごとにプロファイルを保持するので、ログアウトしなくても個人用と仕事用のサブスクリプションを切り替えて使えます。設定 → アカウントでは、Claude Code と Codex のサブスクリプションアカウントと、macOS では Antigravity の Google アカウントを管理できます。

まず、各エージェントの公式 CLI をインストールしてください。ログインはその CLI を通じて行います。Kiln が独自の OAuth プロバイダーを実装したり、プロバイダーのアカウントポリシーを回避したりすることはありません。

アカウントを追加する

  1. エージェントのカードでアカウントを追加を選びます。
  2. プロファイルに個人用や仕事用などの名前を付けます。
  3. ブラウザーでログインを選び、ブラウザーで認証を完了します。

Kiln はバックグラウンドで待機し、CLI がログインの成功を報告するとすぐにプロファイルを保存します。ターミナルを開いたり、ログインコマンドを実行したりする必要はありません。アカウントの設定を開いている間は、進行状況の確認、ログインページの再表示、キャンセルができます。ログインの試行は 5 分で期限切れになります。

ブラウザーのコールバックが使えない場合、Claude Code が代わりにログインコードを表示することがあります。そのときは、コードを貼り付けるための伏せ字の入力欄が Kiln に表示されます。

警告 この入力欄にはログインコードだけを貼り付けてください。パスワードや API キーは絶対に入力しないでください。

公式 CLI ですでにログインしている場合は、現在のログインを保存を選ぶと、そのログインをプロファイルとして取り込めます。

使うアカウントを選ぶ

ログインするとプロファイルが保存されますが、既存の CLI セッションが使っているアカウントには影響しません。

  • 新しくログインしたプロファイルの横にある適用を選ぶと、新しいセッションでそのプロファイルが使われます。
  • 既存のプロファイルで切り替えを選ぶと、そのプロファイルが使用中になります。
  • プロファイルの名前は、その行のメニューから変更できます。

保存したアカウントは、Kiln が開くパネル用の構成をそれぞれ個別に持つので、すべてのアカウントで同時にログイン状態を保てます。実行中のエージェントセッションは、開始時のアカウントを使い続けます。切り替えた後に新しいアカウントを使うには、エージェントのパネルを新しく開いてください。通常のシェルでコマンドを入力して起動した CLI はそのシェルの構成を使い続けます。Kiln がその CLI を再起動したり、認証情報を置き換えたりすることはありません。

実行中のパネルが使用量の上限に達しても、Kiln が別のアカウントに自動で切り替えることはありません。ここで別のアカウントを選び、新しいパネルを開いてください。

再ログインする

プロファイルのログインを直したいときに使います。プロファイルを削除して作り直す必要はありません。

  1. アカウントの行のメニューを開き、再ログインを選びます。
  2. 表示されたアカウント名とメールアドレスを確認し、ブラウザーでログインを選びます。
  3. 同じアカウントでログインし、完了したら適用を選びます。

プロファイルの名前、一覧内の位置、会話の履歴はそのまま残り、実行中のターミナルも再起動されません。ブラウザーで別のアカウントを選ぶと、そのログインは拒否されます。キャンセルしたり失敗したりした場合も、プロファイルは元のままです。

新しい認証情報は適用を選ぶまで保留されるため、ブラウザーでのログインによって、セッションが使っているログインが知らないうちに置き換わることはありません。以前のログインをキャッシュしている実行中の CLI は、新しいログインを適用した後に再開が必要な場合があります。

ログインが必要

プロファイルの認証情報がローカルの認証情報ストアから失われていることが確認されると、その行にログインが必要と再ログインボタンが表示されます。この確認は、アカウントの設定を開いている間と更新したときに、バックグラウンドで行われます。

これはローカルでの確認なので、オンラインでアカウントが有効であることまでは保証しません。トークンは CLI 自身が更新するため、ネットワークの障害やアクセストークンの期限切れはログアウトとは見なしません。ローカルの認証情報が残っているのにプロバイダーがログインを拒否する場合は、行のメニューから再ログインを使ってください。

使用量の更新

Kiln は、保存済みのすべての Claude Code と Codex のアカウントを、使用中でないプロファイルも含めて、アプリの起動時とその後 5 分ごとにバックグラウンドで確認します。Kiln を開いたままにしておいてください。アカウントの設定を表示し続ける必要はありません。

  • 各カードには最後に確認が成功した時刻が表示され、確認に失敗した場合は最後に取得したバーが残ります。
  • 更新ボタンを押すと、プロバイダーのレート制限の範囲内で再度確認します。
  • Codex の使用量の期間は、報告された長さが 5 時間または 7 日に一致する場合にだけラベルが付きます。

これらの確認は読み取り専用です。Kiln がモデルにプロンプトを送ったり、リセット用のクレジットを使ったりすることはありません。

状況 Kiln の動作
プロバイダーのレート制限 プロバイダーが指定する時間（1 分から 1 日の間）、指定がなければ 5 分待ちます。手動の確認もこの間は待たされます。
認証情報の拒否（401） その認証情報の確認を 1 時間停止します。新しく更新されたトークンは待たずに確認できます。
その他の失敗 次の周期で再試行します。手動で再試行することもできます。
認識できない応答 値を推測で埋めず、使用量を取得不可として表示します。

トークンが期限切れになったり失効したりすると、実行中の CLI は動いていても、使用量を確認できなくなることがあります。失敗が続く場合は、そのプロファイルのメニューで再ログインを選んでください。

Antigravity アカウント

注意 Antigravity アカウントは Kiln 0.2.12 で追加された機能で、macOS でのみ利用できます。Windows では、ターミナルで agy を実行してログインします。

Antigravity CLI（agy）用に Google アカウントを複数保存し、新しい作業で使うアカウントを選べます。

  1. 設定 → アカウント → Antigravity を開き、アカウントを追加を選びます。Kiln が一時的な専用ターミナルで、インストール済み CLI の Google ログインを開始します。
  2. ブラウザーでログインします。コードが表示された場合は、ログインコードに貼り付けて確認または Enter を押します。コピー時に混入した改行や空白は除去されます。確認中はログインコードを確認していますと表示され、重複送信はできません。コードが拒否された場合や期限切れの場合は、エラーを表示して試行を終了します。ログインをやり直して新しいコードを取得してください。認証が完了したら適用を選びます。
  3. 別のアカウントも同じ手順で追加し、新しい作業でそのアカウントを使うときは切り替えを選びます。

実行中の作業は元のアカウントを使い続けます。行のメニューからは、名前の変更、削除、同じ Google アカウントでの再ログインができます。現在のログインを保存を選ぶと、通常の CLI の Google ログインを取り込めます。

各アカウントは専用のホームと macOS キーチェーンを持ち、Antigravity の環境設定、設定、会話もアカウントごとに分かれます。Kiln が通常の CLI のログインを置き換えたり、既定のキーチェーンを変更したりすることはありません。アカウントのホームには、シェル、Git、SSH の設定など、普段のホームにあるファイルは含まれません。ワークスペースのファイルは引き続き使えます。

適用したアカウントには、公式 CLI が返すモデルグループごとの使用率とリセット時刻が表示されます。起動時と5分ごとに確認し、手動更新もできます。この読み取り専用の確認には agy 1.1.11 以降が必要で、エージェントのターンを開始せず、モデルの割り当ても消費しません。古い結果や失敗した結果の使用率は表示しません。自動切り替えは提供していません。割り当てに達するとリセット時刻を通知します。認証には Google OAuth を使用し、Google Cloud プロジェクトの設定は自動化していません。

新しい Kiln の zsh ターミナルで agy を入力した場合も、選択したアカウントを使用し、引数と現在のフォルダーを維持します。更新後は新しいターミナルを開いてください。カスタムシェルでは 新しいタスク → Antigravity を選びます。 Kiro がインストールされていても Kiln のシェル連携を維持するため、新しいターミナルで選択したアカウントを使用できます。

これらのアカウントの会話も会話の同期の対象になり、同じ会話で再起動しても元のアカウントが保たれます。詳しくは会話とアップデートを参照してください。

認証情報の保存場所

macOS では、保存した認証情報はキーチェーンに格納されます。Kiln がキーチェーンをリセットしたり置き換えたりすることはありません。Windows では、Windows のユーザーキーで保護された非公開のファイルに保存されます。アカウントの一覧にはプロファイル名とメタデータだけが含まれ、アクセストークンやリフレッシュトークンは含まれません。ログイン用のリンクやコードは、設定にもログにも書き込まれません。

トラブルシューティング

  • ログインに失敗する: ブラウザーとネットワーク接続を確認してから、もう一度試してください。
  • CLI が見つからない: CLI が見つからないことは、アカウントのカードに表示されます。そのエージェントの公式 CLI をインストールしてください。

CLI 自体をアップデートするには、会話とアップデートを参照してください。

文档使用 Kiln

账户

保存多个 Claude Code、Codex 和 Antigravity 账户，通过浏览器登录，在账户之间切换，并让用量信息保持最新。

Kiln 为你使用的每个代理账户各保存一份配置，在个人订阅和工作订阅之间切换时无需退出登录。打开设置 → 账户，即可管理 Claude Code 和 Codex 的订阅账户，以及 macOS 上 Antigravity 使用的 Google 账户。

请先为每个代理安装官方 CLI。Kiln 通过该 CLI 登录，从不自行实现 OAuth 提供方，也不会绕过提供方的账户政策。

添加账户

  1. 在代理卡片上选择添加账户。
  2. 为配置命名，例如个人或工作。
  3. 选择通过浏览器登录，在浏览器中完成身份验证。

Kiln 在后台等待，CLI 一报告登录成功就保存这份配置。不需要打开终端，也不需要运行登录命令。账户设置打开期间，可以查看进度、重新打开登录页面或取消登录。每次登录尝试五分钟后失效。

如果浏览器回调不可用，Claude Code 可能会改为显示登录代码。这时 Kiln 会显示一个掩码输入框，把代码粘贴进去即可。

警告 这个输入框只用来粘贴登录代码，切勿在其中输入密码或 API 密钥。

已经用官方 CLI 登录过？选择保存当前登录账户，即可把这次登录导入为一份配置。

选择要用的账户

登录只会保存配置，不会改动现有 CLI 会话正在使用的账户。

  • 在新登录的配置旁选择应用，新会话就会使用它。
  • 在已有配置上选择切换，将其设为当前账户。
  • 在配置所在行的菜单中可以重命名配置。

对于 Kiln 打开的面板，每个已保存的账户都有各自独立的配置，因此所有账户可以同时保持登录。正在运行的代理会话继续使用启动时的账户；切换后，新开一个代理面板才会用上新账户。在普通 Shell 中手动运行的 CLI 继续使用该 Shell 的配置，Kiln 绝不会重启它，也不会替换它的凭据。

运行中的面板达到用量限制时，Kiln 不会把它轮换到其他账户。请在这里改选其他账户，再新开一个面板。

重新登录

某份配置的登录需要修复时，用这个功能即可保留配置，不必删掉重建。

  1. 打开该账户行的菜单，选择重新登录。
  2. 核对显示的账户名称和电子邮件，然后选择通过浏览器登录。
  3. 用同一个账户登录，完成后选择应用。

Kiln 会保留配置的名称、在列表中的位置和对话历史，也不会重启正在运行的终端。如果在浏览器中选了其他账户，本次尝试会被拒绝。取消或失败的尝试同样不会影响这份配置。

新凭据要等你选择应用后才生效，因此浏览器登录绝不会在你不知情时替换会话正在使用的登录信息。正在运行的 CLI 如果缓存了旧的登录信息，应用新登录后可能需要恢复会话。

需要重新登录

本地凭据存储确认某份配置的凭据已经不存在时，该行会显示需要重新登录，并提供重新登录按钮。账户设置打开期间以及你手动刷新时，Kiln 会在后台做这项检查。

这只是本地检查，不能证明账户在线上仍然有效。网络故障和访问令牌过期都不算退出登录，因为 CLI 会自行刷新令牌。如果提供方拒绝了登录，而本地凭据仍在，请从该行菜单中选择重新登录。

用量更新

应用启动时，以及之后每隔五分钟，Kiln 会在后台检查每个已保存的 Claude Code 和 Codex 账户，未在使用的配置也包括在内。只要 Kiln 保持打开即可，账户设置不必一直显示。

  • 每张卡片显示上次成功检查的时间；检查失败时，保留上次已知的用量条。
  • 刷新按钮会请求再检查一次，但受提供方速率限制约束。
  • 只有上报的时长恰好是五小时或七天时，Codex 的用量窗口才会显示对应标签。

这些检查是只读的。Kiln 不会发送模型提示词，也不会消耗重置额度。

情况 Kiln 的处理
提供方限速 按提供方要求的时长等待（一分钟到一天之间）；提供方未说明时等待五分钟。手动检查也会顺延。
凭据被拒绝（401） 暂停检查该凭据一小时。刚刷新的令牌可以立即检查，无需等待。
其他失败 在下一个周期重试，也可以手动重试。
无法识别的响应 将用量显示为不可用，不会编造数值。

令牌过期或被撤销时，用量检查可能无法进行，但正在运行的 CLI 仍能正常工作。如果一直失败，请在该配置的菜单中选择重新登录。

Antigravity 账户

注意 Antigravity 账户是 Kiln 0.2.12 新增的功能，仅限 macOS。在 Windows 上，请在终端中运行 agy 登录。

可以为 Antigravity CLI（agy）保存多个 Google 账户，并选择新任务使用哪一个。

  1. 打开设置 → 账户 → Antigravity，选择添加账户。Kiln 会在一个临时的私有终端中启动已安装 CLI 的 Google 登录流程。
  2. 在浏览器中登录。如果显示代码，请将其粘贴到登录代码，然后选择确认或按 Enter。复制时混入的换行和空格会被移除。验证时会显示正在验证登录代码，并阻止重复提交。代码被拒绝或过期时，本次尝试会结束并显示错误；请重新开始登录以获取新代码。认证成功后，选择应用。
  3. 对其他账户重复以上步骤，再选择切换，让新任务使用该账户。

正在运行的任务继续使用原来的账户。行菜单提供重命名、删除，以及用同一个 Google 账户重新登录。保存当前登录账户会导入普通 CLI 的 Google 登录。

每个账户都有自己的私有主目录和 macOS 钥匙串，Antigravity 的偏好设置、设置和对话也都按账户分开保存。Kiln 绝不会替换普通 CLI 的登录，也不会改动你的默认钥匙串。账户主目录里没有你平时主目录中的文件，例如 Shell、Git 或 SSH 配置，但工作区文件仍然可以访问。

已应用的账户会显示官方 CLI 返回的各模型组已用比例和重置时间。应用启动时及之后每五分钟检查，也可手动刷新。这种只读检查需要 agy 1.1.11 或更高版本，不会启动代理回合或消耗模型配额。过期或失败的结果不会显示百分比。不提供自动切换。达到配额时，Kiln 会通知重置时间。登录使用 Google OAuth，不会自动设置 Google Cloud 项目。

在新的 Kiln zsh 终端中输入 agy 也会使用所选账户，并保留参数和当前目录。更新后请打开新终端。使用自定义 shell 时，请选择新建任务 → Antigravity。 即使安装了 Kiro，Kiln 也会保留自己的 shell 集成，因此新终端仍会使用所选账户。

这些账户的对话同样参与对话同步，在同一对话中重启时也会沿用原来的账户。详见对话与更新。

凭据存储位置

在 macOS 上，Kiln 把已保存的凭据存放在钥匙串中，绝不会重置或替换钥匙串。在 Windows 上，已保存的凭据是私有文件，由你的 Windows 用户密钥保护。账户列表只包含配置名称和元数据，从不包含访问令牌或刷新令牌。登录链接和代码不会写入设置或日志。

故障排除

  • 登录失败：检查浏览器和网络连接，然后重试。
  • 找不到 CLI：账户卡片上会提示缺少 CLI。请为该代理安装官方 CLI。

要更新 CLI 本身，详见对话与更新。
