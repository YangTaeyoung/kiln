DocumentationTools

Git and GitHub

Browse commit history, open diffs, and squash, cherry-pick, drop or reword commits in the repository you select.

Kiln puts commit history, diffs and pull requests in the workspace inspector, next to your terminals. Every Git operation runs against the repository you select, so you can rewrite history safely even when a workspace spans several repositories.

Automatic repository status checks pause in inactive workspaces. The last results stay visible, and checks resume when you return to the workspace.

Open Git tools

The right-hand workspace inspector includes Changes and GitHub. You can also open source control and GitHub from the titlebar Tools menu, which opens them alongside your current work without replacing your terminal task.

GitHub features use the GitHub CLI. Install gh and sign in with it before you use them. See Install and update.

Choose a repository

A workspace can point at a single repository or at a parent folder such as ~/dev/projects that contains several. In a multi-repository workspace, use the repository selector inside the Git and GitHub tools to choose the repository you want to work on.

Selecting a repository only changes where Git operations apply. The task's working directory stays at the workspace folder, and an agent is not moved into the repository you inspect. See Workspaces and tasks.

Warning In a multi-repository workspace, confirm the selected repository before you change history.

Browse history and diffs

Open Changes and select a repository to see its Commit history. The list is interactive right away. There is no separate edit mode.

Action How
Select a commit Click it
Select a range Drag across rows, or Shift-click
Open a commit's diff Double-click the commit
Show commit actions Right-click a commit or a selection
Browse another branch Use the branch filter
Open a larger view Click the expand icon

The branch filter lets you browse another branch without checking it out. The expand icon opens the same history, with the same interactions, in a larger tab. In the multi-repository overview, the history icon beside each repository opens that larger view directly.

Press ⇧⌘L to open history. In a single-repository workspace it opens the history directly. With several repositories it opens the repository overview so you can pick one first.

Note Shortcuts on this page use macOS keys. On Windows, app shortcuts read ⌘ as Ctrl+Shift, so ⇧⌘ becomes Ctrl+Shift+Alt.

Edit a commit message

  1. Right-click a commit on the current branch.
  2. Choose Edit message.
  3. Edit the message in the confirmation dialog and apply it.

If the commit is already published, the remote history needs updating too. Read the warning in the dialog before you continue.

Squash commits

  1. Drag across commit rows, or Shift-click, to select a range.
  2. Choose Squash from the selection actions or the context menu.
  3. Review the target branch and the commits, then edit the combined message.
  4. Review any shared-history warning and confirm.

Squashing works on consecutive commits in a supported linear segment of the current branch.

Tip Option-drag (Alt-drag on Windows) keeps its own behavior: it reorders commits instead of selecting a range.

Cherry-pick from another branch

  1. Choose the source branch in the history filter.
  2. Select the commits you want.
  3. Choose Cherry-pick.

Kiln applies the selected changes as new commits on your current branch. The filter only changes what you are browsing. It never checks out the source branch.

Drop commits

Select one or more commits and choose Drop commits. Kiln removes their changes from the current branch by rewriting history. This is different from a revert, which adds a new commit. Review the affected range before you confirm.

Shared history and recovery

Squash, drop and cherry-pick follow the same safety steps.

  • Checks first. Before running, Kiln checks the worktree, branch, HEAD and remote state.
  • Backup ref. Kiln stores the original HEAD in a backup ref. You can find the backup information in the result details.
  • Shared-history warning. The review warns you when the affected commits are part of the remote default branch, or when Kiln cannot tell.
  • Guarded push. When you squash or drop published commits, Kiln offers to push automatically using --force-with-lease with an explicit expectation. If the remote changed in the meantime, the push refuses to overwrite it.
  • Server rules still apply. Branch protection on the server stays in force. Kiln does not bypass it.

Conflicts

A conflict stops the operation and offers actions to continue, skip or abort. Nothing is pushed while the operation is stopped.

Failed pushes

If the local rewrite finishes but the push fails afterwards, Kiln shows the two results separately: the local rewrite completed, and the remote update did not. The backup information stays available in the result details.

Pull requests

Open GitHub in the inspector to review pull requests for the selected repository without leaving your workspace. As with Git history, use the repository selector in a multi-repository workspace.

문서도구

Git과 GitHub

선택한 저장소에서 커밋 기록을 살펴보고, diff를 열고, 커밋을 스쿼시·체리픽·삭제하거나 메시지를 고칩니다.

Kiln은 커밋 기록, diff, 풀 리퀘스트를 터미널 옆 워크스페이스 인스펙터에 보여 줍니다. 모든 Git 작업은 선택한 저장소에서 실행되므로, 워크스페이스가 여러 저장소에 걸쳐 있어도 기록을 안전하게 다시 쓸 수 있습니다.

비활성 워크스페이스에서는 저장소 상태 자동 확인을 잠시 멈춥니다. 마지막으로 확인한 결과는 계속 표시하며, 해당 워크스페이스로 돌아오면 확인을 재개합니다.

Git 도구 열기

오른쪽 워크스페이스 인스펙터에 변경과 GitHub가 있습니다. 제목 표시줄의 도구 메뉴에서도 소스 제어와 GitHub를 열 수 있으며, 이때 터미널 작업은 그대로 두고 현재 작업 옆에 열립니다.

GitHub 기능은 GitHub CLI를 사용합니다. 쓰기 전에 gh를 설치하고 로그인하세요. 설치와 업데이트를 참고하세요.

저장소 선택하기

워크스페이스는 저장소 하나를 가리킬 수도 있고, ~/dev/projects처럼 여러 저장소를 담은 상위 폴더를 가리킬 수도 있습니다. 저장소가 여러 개인 워크스페이스에서는 Git·GitHub 도구 안의 저장소 선택기로 작업할 저장소를 고르세요.

저장소를 선택해도 바뀌는 것은 Git 작업이 적용되는 위치뿐입니다. 작업이 실행되는 디렉터리는 워크스페이스 폴더 그대로이고, 에이전트도 내가 살펴보는 저장소로 옮겨 가지 않습니다. 워크스페이스와 작업을 참고하세요.

주의 저장소가 여러 개인 워크스페이스에서는 기록을 바꾸기 전에 어떤 저장소가 선택되어 있는지 확인하세요.

기록과 diff 살펴보기

변경을 열고 저장소를 선택하면 커밋 기록이 나타납니다. 목록은 바로 조작할 수 있으며, 따로 편집 모드로 들어갈 필요가 없습니다.

동작 방법
커밋 선택 클릭
범위 선택 여러 행에 걸쳐 드래그하거나 Shift-클릭
커밋의 diff 열기 커밋을 더블클릭
커밋 동작 보기 커밋이나 선택 영역을 우클릭
다른 브랜치 살펴보기 브랜치 필터 사용
큰 화면으로 열기 확장 아이콘 클릭

브랜치 필터를 쓰면 체크아웃하지 않고도 다른 브랜치를 살펴볼 수 있습니다. 확장 아이콘을 누르면 같은 기록이 더 큰 탭에서 열리며, 조작 방법도 똑같습니다. 여러 저장소 개요에서는 저장소마다 옆에 있는 기록 아이콘으로 큰 화면을 바로 열 수 있습니다.

⇧⌘L을 누르면 기록이 열립니다. 저장소가 하나인 워크스페이스에서는 기록이 바로 열리고, 저장소가 여러 개면 먼저 저장소를 고를 수 있도록 저장소 개요가 열립니다.

참고 이 페이지의 단축키는 macOS 키 기준입니다. Windows에서는 앱 단축키의 ⌘가 Ctrl+Shift이므로 ⇧⌘는 Ctrl+Shift+Alt가 됩니다.

커밋 메시지 고치기

  1. 현재 브랜치의 커밋을 우클릭합니다.
  2. 메시지 수정을 선택합니다.
  3. 확인 대화상자에서 메시지를 고친 뒤 적용합니다.

이미 게시한 커밋이라면 원격 기록도 갱신해야 합니다. 계속하기 전에 대화상자의 경고를 읽어 보세요.

커밋 스쿼시하기

  1. 여러 커밋 행에 걸쳐 드래그하거나 Shift-클릭해 범위를 선택합니다.
  2. 선택 동작이나 컨텍스트 메뉴에서 스쿼시를 선택합니다.
  3. 대상 브랜치와 커밋을 검토한 뒤, 합쳐질 메시지를 편집합니다.
  4. 공유 기록 경고가 나오면 내용을 검토하고 확인합니다.

스쿼시는 현재 브랜치 중 지원되는 선형 구간에 있는 연속된 커밋에 쓸 수 있습니다.

팁 Option-드래그(Windows에서는 Alt-드래그)는 원래 동작대로 범위를 선택하지 않고 커밋 순서를 바꿉니다.

다른 브랜치에서 체리픽하기

  1. 기록 필터에서 원본 브랜치를 선택합니다.
  2. 가져올 커밋을 선택합니다.
  3. 체리픽을 선택합니다.

Kiln은 선택한 변경을 현재 브랜치에 새 커밋으로 적용합니다. 필터는 살펴보는 대상만 바꿀 뿐, 원본 브랜치를 체크아웃하지 않습니다.

커밋 삭제하기

커밋을 하나 이상 선택하고 커밋 삭제를 선택합니다. Kiln은 기록을 다시 써서 현재 브랜치에서 해당 변경을 없앱니다. 새 커밋을 추가하는 revert와는 다릅니다. 확인하기 전에 영향을 받는 범위를 검토하세요.

공유 기록과 복구

스쿼시, 커밋 삭제, 체리픽은 모두 같은 안전 절차를 따릅니다.

  • 사전 확인. 실행하기 전에 worktree, 브랜치, HEAD, 원격 상태를 확인합니다.
  • 백업 ref. 원래 HEAD를 백업 ref에 저장합니다. 백업 정보는 결과 세부 정보에서 볼 수 있습니다.
  • 공유 기록 경고. 영향을 받는 커밋이 원격 기본 브랜치에 포함되어 있거나 포함 여부를 판단할 수 없으면 검토 단계에서 경고합니다.
  • 보호된 push. 게시된 커밋을 스쿼시하거나 삭제하면, 명시적인 기대값과 함께 --force-with-lease로 자동 push하도록 제안합니다. 그사이 원격이 바뀌었다면 push가 덮어쓰기를 거부합니다.
  • 서버 규칙 유지. 서버의 브랜치 보호 규칙은 계속 적용되며, Kiln은 이를 우회하지 않습니다.

충돌

충돌이 생기면 작업이 멈추고 계속, 건너뛰기, 중단 중에서 고를 수 있습니다. 작업이 멈춰 있는 동안에는 아무것도 push되지 않습니다.

push 실패

로컬 재작성은 끝났는데 그 뒤 push가 실패하면, Kiln은 로컬 재작성은 완료되었고 원격 갱신은 완료되지 않았다고 두 결과를 따로 보여 줍니다. 백업 정보는 결과 세부 정보에서 계속 확인할 수 있습니다.

풀 리퀘스트

인스펙터에서 GitHub를 열면 워크스페이스를 벗어나지 않고 선택한 저장소의 풀 리퀘스트를 검토할 수 있습니다. 저장소가 여러 개인 워크스페이스에서는 Git 기록과 마찬가지로 저장소 선택기를 사용하세요.

ドキュメントツール

Git と GitHub

選択したリポジトリでコミット履歴と diff を確認し、コミットのスカッシュ、チェリーピック、削除、メッセージの修正を行う方法を説明します。

Kiln では、コミット履歴、diff、プルリクエストを、ターミナルの横のワークスペースインスペクターで扱えます。Git の操作はすべて選択したリポジトリに対して実行されるので、複数のリポジトリにまたがるワークスペースでも安全に履歴を書き換えられます。

非アクティブなワークスペースでは、リポジトリ状態の自動確認を一時停止します。最後の結果は表示されたままで、そのワークスペースに戻ると確認を再開します。

Git ツールを開く

右側のワークスペースインスペクターには変更と GitHub があります。タイトルバーのツールメニューからもソース管理と GitHub を開けます。この場合、ターミナルの作業を置き換えずに、現在の作業の横に開きます。

GitHub の機能には GitHub CLI を使います。使う前に gh をインストールし、ログインしておいてください。詳しくはインストールとアップデートを参照してください。

リポジトリを選ぶ

ワークスペースのフォルダーには、1 つのリポジトリも、~/dev/projects のように複数のリポジトリを含む親フォルダーも指定できます。複数リポジトリのワークスペースでは、Git と GitHub のツールにあるリポジトリセレクターで、作業したいリポジトリを選びます。

リポジトリを選んで変わるのは、Git 操作の適用先だけです。作業ディレクトリはワークスペースのフォルダーのままで、確認中のリポジトリにエージェントが移動することもありません。詳しくはワークスペースと作業を参照してください。

警告 複数リポジトリのワークスペースでは、履歴を変更する前に選択中のリポジトリを確認してください。

履歴と diff を閲覧する

変更を開いてリポジトリを選ぶと、そのコミット履歴が表示されます。一覧はそのまま操作でき、編集モードに切り替える必要はありません。

操作 方法
コミットを選ぶ クリックする
範囲を選ぶ 行をまたいでドラッグする、または Shift キーを押しながらクリックする
コミットの diff を開く コミットをダブルクリックする
コミットの操作を表示する コミットまたは選択範囲を右クリックする
別のブランチを閲覧する ブランチフィルターを使う
大きな表示で開く 展開アイコンをクリックする

ブランチフィルターを使うと、チェックアウトせずに別のブランチを閲覧できます。展開アイコンを押すと、同じ履歴を同じ操作のまま大きなタブで開きます。複数リポジトリの概要では、各リポジトリの横にある履歴アイコンからその大きな表示を直接開けます。

⇧⌘L で履歴を開けます。リポジトリが 1 つのワークスペースでは履歴が直接開きます。複数ある場合はリポジトリの概要が開くので、先にリポジトリを選びます。

注意 このページのショートカットは macOS のキーで表記しています。Windows ではアプリのショートカットの ⌘ を Ctrl+Shift と読み替えるので、⇧⌘ は Ctrl+Shift+Alt になります。

コミットメッセージを修正する

  1. 現在のブランチのコミットを右クリックします。
  2. メッセージを修正を選びます。
  3. 確認ダイアログでメッセージを編集し、適用します。

コミットをすでにプッシュしている場合は、リモートの履歴も更新する必要があります。続ける前に、ダイアログの警告を確認してください。

コミットをスカッシュする

  1. コミットの行をまたいでドラッグするか、Shift キーを押しながらクリックして範囲を選びます。
  2. 選択範囲の操作またはコンテキストメニューからスカッシュを選びます。
  3. 対象のブランチとコミットを確認し、まとめたメッセージを編集します。
  4. 共有履歴に関する警告があれば確認し、確定します。

スカッシュできるのは、現在のブランチのうち、対応している直線的な区間にある連続したコミットです。

ヒント Option キーを押しながらのドラッグ（Windows では Alt キー）は別の操作として扱われ、範囲を選ぶ代わりにコミットを並べ替えます。

別のブランチからチェリーピックする

  1. 履歴フィルターで取り込み元のブランチを選びます。
  2. 取り込みたいコミットを選びます。
  3. チェリーピックを選びます。

Kiln は選んだ変更を、現在のブランチに新しいコミットとして適用します。フィルターで変わるのは閲覧対象だけで、取り込み元のブランチがチェックアウトされることはありません。

コミットを削除する

コミットを 1 つ以上選び、コミットを削除を選びます。Kiln は履歴を書き換えて、それらの変更を現在のブランチから取り除きます。新しいコミットを追加する revert とは異なります。確定する前に、影響を受ける範囲を確認してください。

共有履歴と復旧

スカッシュ、削除、チェリーピックには、共通の安全策があります。

  • 事前チェック。実行前に、Kiln は worktree、ブランチ、HEAD、リモートの状態を確認します。
  • バックアップ ref。 Kiln は元の HEAD をバックアップ ref に保存します。バックアップの情報は結果の詳細で確認できます。
  • 共有履歴の警告。影響を受けるコミットがリモートのデフォルトブランチに含まれている場合や、Kiln が判断できない場合は、確認画面で警告が表示されます。
  • 保護されたプッシュ。プッシュ済みのコミットをスカッシュまたは削除すると、Kiln は期待する状態を明示した --force-with-lease での自動プッシュを提案します。その間にリモートが変更されていた場合、プッシュは上書きせずに拒否されます。
  • サーバーのルールは引き続き適用されます。サーバー側のブランチ保護は有効なままです。Kiln がそれを回避することはありません。

コンフリクト

コンフリクトが起きると操作は停止し、続行、スキップ、中止を選べるようになります。操作が停止している間は何もプッシュされません。

プッシュの失敗

ローカルでの書き換えは完了したもののプッシュに失敗した場合、Kiln は 2 つの結果を分けて表示し、ローカルの書き換えは完了したこと、リモートの更新は完了していないことがわかるようにします。バックアップの情報は結果の詳細で引き続き確認できます。

プルリクエスト

インスペクターで GitHub を開くと、ワークスペースを離れずに選択中のリポジトリのプルリクエストを確認できます。Git の履歴と同様に、複数リポジトリのワークスペースではリポジトリセレクターを使います。

文档工具

Git 与 GitHub

在所选仓库中浏览提交历史、打开 diff，并压缩、拣选、删除提交或修改提交信息。

Kiln 把提交历史、diff 和拉取请求放在工作区检查器中，紧挨着终端。每个 Git 操作都只针对你选中的仓库，即使工作区横跨多个仓库，改写历史也很安全。

非活动工作区会暂停自动检查仓库状态。上次的结果仍会保留显示，返回该工作区后会恢复检查。

打开 Git 工具

右侧的工作区检查器包含更改和 GitHub。也可以从标题栏的工具菜单打开源代码管理和 GitHub，它们会在当前工作旁边打开，不会替换终端任务。

GitHub 功能依赖 GitHub CLI。使用前请先安装 gh 并登录。详见安装与更新。

选择仓库

工作区可以指向单个仓库，也可以指向包含多个仓库的父文件夹，例如 ~/dev/projects。在多仓库工作区中，请用 Git 和 GitHub 工具里的仓库选择器指定要操作的仓库。

选择仓库只改变 Git 操作的作用对象。任务的工作目录仍是工作区文件夹，代理也不会被移到你正在查看的仓库里。详见工作区与任务。

警告 在多仓库工作区中改写历史之前，请先确认选中的仓库。

浏览历史和 diff

打开更改并选择一个仓库，即可查看它的提交历史。列表打开后就能直接操作，没有单独的编辑模式。

操作 方法
选择提交 点击提交
选择范围 在多行上拖动，或按住 Shift 点击
打开提交的 diff 双击提交
显示提交操作 右键点击提交或选中的内容
浏览其他分支 使用分支筛选器
打开更大的视图 点击展开图标

用分支筛选器可以浏览其他分支，无需签出。展开图标会在更大的标签页中打开同一份历史，操作方式不变。在多仓库概览中，点击仓库旁的历史图标可直接打开这个大视图。

按 ⇧⌘L 打开历史。单仓库工作区会直接打开历史；有多个仓库时，会先打开仓库概览，让你选择一个。

注意 本页快捷键以 macOS 按键表示。在 Windows 上，应用快捷键中的 ⌘ 对应 Ctrl+Shift，因此 ⇧⌘ 对应 Ctrl+Shift+Alt。

修改提交信息

  1. 右键点击当前分支上的某个提交。
  2. 选择修改信息。
  3. 在确认对话框中编辑信息并应用。

如果该提交已经发布，远程历史也需要更新。继续之前，请先阅读对话框中的警告。

压缩提交

  1. 在提交行上拖动，或按住 Shift 点击，选中一个范围。
  2. 从选中内容的操作或右键菜单中选择压缩。
  3. 核对目标分支和提交，然后编辑合并后的提交信息。
  4. 如有共享历史警告，查看后确认。

压缩适用于当前分支上受支持的线性区段内的连续提交。

提示 按住 Option 拖动（Windows 上按住 Alt 拖动）保持原有行为：重新排列提交顺序，而不是选择范围。

从其他分支拣选

  1. 在历史筛选器中选择源分支。
  2. 选中需要的提交。
  3. 选择拣选。

Kiln 会把选中的更改作为新提交应用到当前分支。筛选器只改变你浏览的内容，绝不会签出源分支。

删除提交

选中一个或多个提交，然后选择删除提交。Kiln 通过改写历史，从当前分支中移除这些提交的更改。这和 revert 不同，revert 会新增一个提交。确认前请检查受影响的范围。

共享历史与恢复

压缩、删除和拣选都遵循同样的安全步骤。

  • 先检查。执行前，Kiln 会检查 worktree、分支、HEAD 和远程状态。
  • 备份引用。 Kiln 把原始的 HEAD 保存到一个备份引用中，备份信息可以在结果详情中找到。
  • 共享历史警告。受影响的提交属于远程默认分支，或者 Kiln 无法判断时，审阅界面会发出警告。
  • 受保护的推送。压缩或删除已发布的提交时，Kiln 会提供自动推送，使用带明确预期值的 --force-with-lease。如果远程在此期间有变化，推送会拒绝覆盖。
  • 服务器规则照常生效。服务器上的分支保护规则仍然有效，Kiln 不会绕过。

冲突

遇到冲突时操作会停下，并提供继续、跳过或中止选项。操作停止期间不会推送任何内容。

推送失败

如果本地改写已完成，但随后推送失败，Kiln 会分别显示两个结果：本地改写已完成，远程更新未完成。备份信息仍可在结果详情中找到。

拉取请求

在检查器中打开 GitHub，不离开工作区就能审阅所选仓库的拉取请求。与 Git 历史一样，多仓库工作区中请使用仓库选择器。
