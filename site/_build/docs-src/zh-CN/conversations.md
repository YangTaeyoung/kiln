---
title: 对话与更新
description: 在 Claude Code 和 Codex 之间接续对话，把 Antigravity 对话同步到这两者，并在更新代理 CLI 时保留进度。
---

Kiln 可以在 Claude Code 和 Codex 之间复制工作区的对话，用 `/resume` 就能从另一个代理停下的地方接着做。它还会把每个面板绑定到对应的对话，CLI 更新或重启后都能回到原处。

## 关联工作区 {#link-a-workspace}

1. 在**设置 → 账户**中登录一个 Claude Code 账户和一个 Codex 账户。详见[账户](accounts.html)。
2. 在侧边栏中右键点击工作区，选择**关联对话**。
3. 在对话框中，把**最近对话数量**设为要保持同步的对话数。默认值为 **20**，可设范围为 1 到 4096。

同步需要按工作区逐个开启，并在 Kiln 打开期间运行。工作区文件夹内任何位置的对话都在同步范围内，包括你在 Kiln 之外发起的对话。

上限按工作区中最近活跃的对话计算。恢复一个较早的对话，它就会重新进入同步范围。调低上限后，超出部分不再同步，但已有的副本仍然可用。

要停止同步，从同一菜单中选择**取消对话关联**。已生成的副本仍可在 `/resume` 中使用。关闭工作区会暂停该工作区的同步。

关联绑定在状态对话框中显示的那一对账户上，之后即使切换账户也不变。

## 在另一个 CLI 中继续 {#continue-in-the-other-cli}

在另一个 CLI 中打开同一项目，用 `/resume` 选择对话。每个已关联的对话在每个 CLI 的恢复列表中都只出现一次，标题相同；无论是在普通终端还是 Kiln 的账户面板中都是如此。

之前的消息会出现在 CLI 常规的对话视图中，并作为下一次模型请求的一部分发送。Kiln 本身不会发起任何模型请求。

### 同步的内容 {#what-carries-over}

| 内容 | 结果 |
| --- | --- |
| 你的请求和代理的回答 | 原样复制，保留措辞、换行和代码块。 |
| 对话名称 | 所有副本共用。在任一 CLI 中重命名都会同步到各处，以最近一次重命名为准。 |
| Shell 命令和文件编辑 | 另一个 CLI 有对应工具时，显示为该 CLI 自己的工具记录；否则显示为可读文本。 |
| 图片 | 保留。 |
| 推理过程、提供方指令、加密记录 | 不复制。 |

历史中的工具调用绝不会再次执行。如果对话中有 Kiln 无法复制的内容（例如文档或音频），同步会明确显示失败，而不会在缺失内容的情况下标记为完成。

### 同步时机 {#when-sync-runs}

工作区中只要有代理 CLI 在运行（包括等待输入时），该工作区的自动同步就会暂停。CLI 退回 Shell 或终端关闭后约一秒，Kiln 会再次同步。每次检查结束 60 秒后，后台会再检查一次。

只复制已完成的回复。仍在写入的对话，要在 10 秒内没有变化后才会被读取。

## Antigravity 对话 {#antigravity-conversations}

已关联文件夹中的 Antigravity（`agy`）对话会复制到 Claude Code 和 Codex，在任一 CLI 中用 `/resume` 都能继续。复制是单向的：Kiln 只读取 Antigravity 的文件，从不写入。

- 请求、回答和工具调用会被复制，Antigravity 的推理过程留在 Antigravity 中。
- 每个回合在 Antigravity 回答后出现。Antigravity 始终没有回答的请求（例如配额用完后）会在五分钟内无变化后出现，后面附一条说明，指出 Antigravity 在回答前就已停止。
- 在 Claude Code 或 Codex 中继续的回合不会同步回 Antigravity。
- 在 macOS 上，[Antigravity 账户](accounts.html#antigravity-accounts)的对话也包括在内。

## 两边都继续了对话 {#when-both-sides-continue}

如果在 Kiln 同步之前，同一对话已在两个 CLI 中分别继续，最近使用的一方会成为主历史。另一方的后续内容保留为归档分支，并从该 CLI 的恢复列表中移除。在状态对话框中选择**恢复**，可将该分支变为每个 CLI 中的独立对话。

如果 Antigravity 对话的副本成为主历史，原对话在 Antigravity 中保持不变，Kiln 也不再跟踪它。

### 在 Kiln 中打开已关联的对话 {#opening-a-linked-conversation-inside-kiln}

在新的 Kiln 面板中打开一个已关联的对话时，如果另一个 Kiln 面板正占用这个对话，Kiln 会停止之前的 CLI，等它退出，同步最终状态，然后只保留新面板。如果 CLI 没有退出，新面板会等待并显示当前状态。Kiln 绝不会强制退出 CLI。

> **注意：**外部终端和其他应用不参与这次交接。在 Kiln 中继续对话之前，请先关闭它们。

## 查看同步状态 {#check-sync-status}

点击工作区的同步图标，或者从工作区的右键菜单中选择**查看对话同步状态**。图标和对话框会显示等待中、处理中、需要处理、已暂停；所有已完成的对话都同步后，显示绿色对勾。

每一行显示对话标题、保存该对话的 CLI，以及在哪里用 `/resume` 继续。在**对话详情**中可以复制每个对话的 ID，以及失败项的诊断信息。

只有你能自行解决的问题才会显示警告：

| 警告 | 操作 |
| --- | --- |
| 已连接的账户文件夹缺失 | **打开账户设置** |
| 存储空间已满或无法写入 | **重试** |
| 未安装 Codex CLI | 安装 Codex，以便为 `/resume` 注册对话 |

**忽略**会让该警告从徽标上隐藏，直到出现其他问题；它仍会列在 *显示已忽略的警告* 下。不需要你处理的情况以灰色显示。**重新检查**会立即重新检查一次。

## CLI 更新 {#cli-updates}

打开**设置 → 账户 → CLI 更新**，可以查看每个 CLI 已安装的可执行文件和版本，以及能获取时的最新发布版本。

| CLI | Kiln 的更新方式 |
| --- | --- |
| Claude Code | `claude update`，保留你配置的更新渠道。 |
| Codex | 使用安装时所用的 Homebrew 或 npm 安装程序。自定义安装会提示需要使用其自己的安装程序。 |
| Antigravity | `agy update`。Antigravity 自行检查最新版本，因此 Kiln 不显示最新版本。 |

可以在此页面更新 CLI，也可以开启**自动更新 Codex、Claude Code 和 Antigravity**（默认关闭），让 Kiln 在打开期间每六小时检查一次。Kiln 从不使用 sudo。

## 在同一对话中重启 {#restart-in-the-same-conversation}

在面板上选择 **… → 在同一对话中重启**，即可在当前对话中重新打开该面板。要在每次更新后都自动这样做，开启**更新后立即在同一对话中重启会话**（默认关闭）。更新安装完成、CLI 报告新版本后，它会中断面板当前的回复。重启会保留面板、布局、工作目录和账户，不会重新发送你的上一条请求，也不会重复执行工具调用。

Kiln 用 CLI 常规的 `Ctrl-C` 序列停止 CLI。如果 CLI 拒绝停止，Kiln 会让它继续运行并显示错误。如果重新启动后无法确认原来的对话，Kiln 会发出警告并提供重试。

### 可以重启的面板 {#which-panels-can-restart}

Kiln 会跟踪它新开的每个 Claude Code 和 Codex 面板的对话，即使两个面板共用一个文件夹也一样。打开面板菜单可以查看 CLI 版本和对话 ID。开始跟踪之前就已存在的面板，以及在普通 Shell 中手动运行的 CLI 都不会被跟踪，请新开一个代理面板。

> **提示：** Codex 会要求你信任新的钩子。如果跟踪一直处于待定状态，请在 Codex 中打开 `/hooks`，信任 Kiln 的钩子，然后发送下一条消息。钩子被禁用时，无法使用自动重启。

Antigravity 面板无需钩子即可被跟踪。在 Windows 上，Antigravity 面板没有记录的对话，因此不会自动重启。

如果任务的终端消失了，Kiln 会恢复记录的对话，而不是重新发送原始请求。
