Kiln 在工作区面板中运行 Claude Code、Codex 和 Google 的 Antigravity CLI（`agy`）。写好请求、选好代理，每个任务的状态都能在侧边栏看到，不必在一个个终端之间翻找。

## 开始之前 {#before-you-start}

这些代理都是外部工具。请为要用的每个代理安装官方 CLI 并登录。Kiln 不含其中任何一个的订阅。

- **Claude Code** 和 **Codex**：安装 CLI，然后在**设置 → 账户**中添加账户。详见[账户](accounts.html)。
- **Antigravity**：用 Google 提供的安装程序安装 `agy`。在 macOS 上，从**设置 → 账户 → Antigravity** 登录；在 Windows 上，在终端中运行 `agy` 登录。Kiln 会在 `PATH`、`~/.local/bin`、`/opt/homebrew/bin` 和 `/usr/local/bin` 中查找 `agy`。

在 Windows 上，Claude Code 和 Codex 以原生 Windows 程序运行，主目录分别是 `%USERPROFILE%\.codex` 和 `%USERPROFILE%\.claude`。

## 启动任务 {#start-a-task}

选择**新建任务**，输入请求，选择代理并启动。代理选择器（Claude Code、Codex 或 Antigravity）固定在请求输入框正下方。仓库上下文单独滚动，摘要再长也不会把启动按钮挤出视野。

Antigravity 还有以下入口：

| 操作 | 作用 |
| --- | --- |
| **新建任务 → Antigravity** | 在当前工作区中启动 `agy`。 |
| **新建任务 → 在文件夹中打开 → Antigravity** | 先选择文件夹，再在该文件夹中启动 `agy`。 |
| **新建 Antigravity 任务**（命令面板，`⌘K`） | 启动一个 Antigravity 任务。 |

在请求下方选择 Antigravity 时，Kiln 会把请求和仓库摘要作为初始提示词传给 `agy`。`antigravity` 命令打开的是 Antigravity 编辑器，因此 Kiln 不把它当作代理。

未发送的请求随工作区一起保存，Kiln 重新打开时会恢复。关闭工作区时，丢弃这些请求前会先询问。

点击面板顶部的向右或向下拆分按钮，可以选择在新面板中打开终端或代理。拆分快捷键仍直接打开终端。

## 对话界面或终端 {#conversation-gui}

在**新建任务**和向右/向下拆分菜单中，先选择**对话 GUI** 或**终端**，再选择代理。新代理默认使用对话 GUI，可在**设置 → 行为 → 新代理显示方式**中更改。普通终端、SSH 和现有终端任务保持当前显示方式。

对话界面显示流式 Markdown、可展开的工具输入输出和文件差异。可直接回答权限请求和问题，允许和拒绝均可使用。标题固定显示启动时的账户以及已确认生效的模型和模式。输入栏只显示提供商公布的模型和模式，现有 MCP 与权限设置保持不变。

按 **Enter** 或**发送**提交，按 **Shift+Enter** 换行。输入法组合与确认输入不会提交。使用**附加图片**一次选择多个文件，或在消息输入框获得焦点时粘贴图片，也可以将文件拖放到目标对话面板。每份草稿最多可附加 8 张图片（PNG、JPEG、GIF、WebP，每张 20 MiB）。粘贴文本仍会正常输入文字。通过缩略图检查图片，并使用每张图片的 **×** 按钮在发送前移除。恢复的附件缺失或无效时，请先移除再发送。**停止**会中断当前轮次。

关闭 Kiln 会保存草稿，守护进程继续保持工作进程。关闭面板会结束会话，并在丢弃草稿前确认。本地排队发送会等待日志确认，重新打开不会重发。发送未确认时可**恢复为草稿**，有意再次发送前请检查记录。失败或断开时保留记录，并可**重启同一对话**。较早/最新消息控件只移动显示范围，不会删除记录。

批准卡片以本地化标题显示命令、工作目录、目标路径、原因和请求权限，不显示传输 ID 或架构。完整恢复记录后，如果原请求既不在日志也不在发送队列中，即使代理已就绪，也可明确选择恢复为草稿，且不会自动重发。

Claude 批准卡片会显示实际的 MCP 和工具参数，包括业务标识符。较长的预览会注明仅显示部分内容，Codex 传输参数和架构仍会过滤。草稿恢复还会等待确认队列观测已包含旧客户端可能完成的最后一次写入。

### 切换同一对话的显示方式 {#switch-presentation}

工作进行中也可请求切换到TUI。当前工作继续在GUI中运行，回复、审批和排队工作结束并通过所有权检查后自动切换。选择GUI可取消切换请求。这不是将正在执行的模型请求立即移至另一个进程。原生TUI返回GUI时，CLI仍须正常退出后才会启动GUI执行方；选择TUI可取消返回请求。

窗口标题和自动任务名称使用首次已发送请求的简短内容。手动命名的任务保留原名，编辑草稿不会改变已有对话标题。

每个代理窗口内容区域的右上角、关闭按钮下方都有连在一起的 **GUI | TUI** 标签。回复的代理名称旁会显示对应图标。展开工具详情后，可查看易读的滚动代码区域，支持已识别文件语言和 shell 命令的语法高亮，并可复制内容。无法识别的输出保持纯文本。

使用代理面板的 **GUI | TUI** 标签，在原账户和工作文件夹中继续同一个已确认的对话。新建的 Claude Code 对话也可以在发送第一条消息前打开终端，不会尝试恢复尚不存在的历史文件。工作进行中可请求切换，实际切换将在响应、审批和排队任务完成后执行。如果仍有后台任务，或 Kiln 无法验证进程归属，就会拒绝切换并保留这些任务运行。只有前一个代理退出完成后才会打开终端；无法切换时会说明原因。

原生 CLI 仍打开时，选择对话 GUI 只会记录返回请求，不会关闭 CLI 或替你输入退出命令。请使用 CLI 自身的退出操作正常退出。确认进程退出后，Kiln 才导入新增的用户和助手文本并重新连接 GUI。导入记录中的图片显示为附件提示，不会重建原生工具卡片。如果之前的原生记录发生变化，Kiln 会保留已有 GUI 记录并显示不匹配信息。

通过 Kiln 注册的 shell 函数启动的交互式 `claude`、`codex` 和 `agy` 命令，也可以使用相同的 **GUI | TUI** 标签。Kiln 只会在确认该终端对应的准确、仍在运行的主机绑定后连接面板。原 PTY、父 shell、命令参数和所选账户配置均会保留。此功能适用于 Kiln 的 zsh 或 PowerShell 集成所提供的函数，注册的命令因 shell 而异。

从 TUI 切换到 GUI 时，请先选择 **GUI**，再正常退出原生 CLI。如果该 CLI 支持，可以使用 `/exit` 或 **Ctrl+D**。Kiln 会等待自然退出，不会终止当前任务，也不会注入猜测的退出命令。如果未请求 GUI 就退出首次打开的 TUI，会将原生退出状态返回给原 shell。

管理、仅输出和远程命令、管道、输入输出重定向，以及绕过 Kiln 集成的用户别名或自定义函数，仍沿用原生执行方式。Bash 和 fish 不会自动注册代理包装函数。Kiln 外部终端中执行的命令不会被自动跟踪。

对于以前从终端启动的代理，只有准确跟踪到原生对话后才能导入 GUI。请先退出该 CLI。终端守护进程确认原进程已退出后，Kiln 才使用记录的账户环境和工作文件夹打开同一对话。终端断开或无法识别对话，并不能作为开始导入的依据。

## 跨多个仓库工作 {#work-across-several-repositories}

如果前端、后端和共享库分属不同的 Git 仓库，就打开它们的父文件夹，例如 `~/dev/projects`。Kiln 把这个文件夹作为代理的工作根目录，还可以把扫描到的仓库结构随请求一起附上，一个请求就能覆盖所有仓库。

在 Git 或 GitHub 工具中查看某个仓库，不会改变任务的工作目录。要让 Git 操作针对某个仓库，请使用这些工具中的仓库选择器。详见[工作区与任务](workspaces.html)和 [Git 与 GitHub](git.html)。

## 跟踪任务状态 {#follow-task-state}

侧边栏中的每一行任务都显示其代理上报的状态。

| 状态 | 含义 |
| --- | --- |
| 处理中 | 代理正在工作。 |
| 等待输入 | 代理需要你输入。 |
| 已完成 | 代理已完成。 |
| 失败 | 代理上报失败。 |
| 会话已打开 | 没有上报任何状态。Kiln 只把会话显示为打开，不做猜测。 |

运行中的工作排在最前，其次是等待输入的请求，再往后是较早的失败。点击任务即可跳到它所在的工作区、标签页和拆分视图，即使该面板因缩放而被隐藏。

### Kiln 如何获知状态 {#how-kiln-knows-the-state}

代理必须上报自己的状态，或者显示 Kiln 能识别的运行中标题，Kiln 才能准确显示状态。

- Kiln 能识别 Claude Code 和 Codex 终端标题中的活动标记，无需额外设置就能显示运行中的活动。
- Claude Code 的 `✳` 标记不算作完成，因为对话框打开时它也会出现。
- 显式的等待和失败信号优先于标题标记。
- 空闲的终端绝不会被当作已完成的任务；启动命令尚未结束，也不会让空闲的代理显示为运行中。

脚本和其他工具可以用 `kiln activity running`、`waiting`、`done` 或 `failed` 上报状态。活动上报和通知详见[终端](terminal.html)。

### 指示器颜色 {#indicator-colors}

| 代理 | 指示器 |
| --- | --- |
| Claude Code | 橙色 |
| Codex | 蓝色 |
| Antigravity | 标签页、任务列表和侧边栏中显示 Antigravity 标志 |

指示器出现在侧边栏、标签页和面板标题栏中。在有拆分视图的标签页里，各状态优先级相同时，以获得焦点的面板为准。警告始终优先。

## 通知与用量限制 {#notifications-and-usage-limits}

通知中心保留最近的通知，每条通知都关联到对应的会话。读过通知后，该会话的待处理状态随即清除。在 Windows 上，代理通知以 Windows 弹窗通知的形式出现。

Antigravity 上报配额已用完时，Kiln 会显示一条用量限制通知，并注明重置时间。对于 Claude Code 和 Codex，面板始终使用打开时的账户。某个账户达到用量限制后，请在**设置 → 账户**中切换到其他账户，再新开一个面板。详见[账户](accounts.html#choose-which-account-to-use)。

## Codex 容量恢复 {#codex-capacity-recovery}

Kiln 打开期间，如果 Codex 因服务器过载而结束了某个回合，由 Kiln 管理的 Codex 面板会重试该回合。只有这一种 Codex 错误会触发重试。用量限制、登录失败、流错误、已取消的回合和成功的回合都不会处理。

- 重试间隔依次为 15、30、60、120 和 240 秒。面板上会显示倒计时和**取消自动重试**按钮。
- 失败后在面板中输入任何内容，都会取消待执行的重试，输入到一半的提示词也算。
- 你自己提交新请求时，会重新开始一轮重试。
- 重试沿用同一个账户和模型。

如果 Codex CLI 仍然开着，Kiln 会在同一对话中发送一条继续提示词。如果 CLI 已经退出，Kiln 会用原来的账户和工作目录恢复同一对话，再发送这条提示词。提示词会要求 Codex 先检查当前状态，再决定是否重复已完成的操作。它不会重放你的原始请求，失败回合中做出的更改也不会回滚。

重试只适用于用已保存账户打开、且 Kiln 已确认其对话的 Codex 面板。Kiln 开始监视运行中的 CLI 之前发生的失败，需要你自行处理。

## Codex 后台服务器设置 {#codex-background-server-settings}

Kiln 新开的 Codex 面板以 `--no-daemon` 运行，与 Codex 自己的共享后台服务器相互独立。如果某个 Codex 会话提示 **Background server has incompatible feature settings**，说明该会话的功能标志与服务器保存的不一致。可以选择：

| 选项 | 效果 |
| --- | --- |
| **Run without daemon this time** | 不重启共享的 Codex 服务器，直接启动本次会话。对应的 CLI 命令是 `codex --no-daemon`。 |
| **Restart with these settings** | 更改共享设置。这可能会中断其他客户端正在进行或排队的工作，请先确认。 |

在新打开的 Kiln Zsh 终端中，直接输入的 `codex`、`codex resume …` 和 `codex fork …` 也使用 `--no-daemon`。即使共享服务器返回 **Server is draining; retry after reconnecting**，这些命令仍可独立启动。显式 `--remote` 连接、已有别名或函数、其他命令形式和其他 shell 保持原有行为。使用 `command codex …` 可绕过包装函数，也可以自行添加 `--no-daemon` 来启动本地会话。已有 shell 需要重新打开才能加载此集成。Kiln 不会重启共享服务器或更改其更新设置。

## 原生会话设置与命令 {#native-session-settings}

回复进行中也可通过发送按钮或Enter发送后续消息，停止按钮保持独立。Claude接收流式后续输入，Codex向当前轮次追加输入。Antigravity会保存一条后续消息，直到当前请求结束。发送确认等待与已接收状态分开显示，不会自动重发。

回复进行中仍可选择模型、推理强度和模式。Claude按原生应用时机更新；Codex输入区的选择用于下一轮，明确的当前轮设置操作可修改当前轮支持的设置。设置仍需等待原生确认。工作区活动列表显示对话标题而不是提供方名称，并保留自定义页面标题。

在对话 GUI 中，使用**会话设置**搜索提供方设置，使用**命令与技能**查找原生命令。紧凑的两行输入框下方是一行工具栏，可附加图片、选择模型和模式、打开**推理设置**，并使用圆形发送或停止按钮。较窄的面板只保留模型和**对话选项**，其余控件收在对话选项中。模型名称便于阅读，模式和推理强度使用应用语言显示，同时保留传给提供方的实际值。尚未收到的目录与空目录也会明确区分。

在推理设置或窄面板的对话选项中，您可以阅读各步骤的说明并选择推理强度。Claude的Ultracode是一个独立开关，开启时会显示为紫色。标题栏会显示已确认适用的模型和模式。

Claude Code、Codex 和 Antigravity 的设置及基本选项会以应用语言显示名称和操作说明。在韩语中，授权策略也会显示为“在需要时请求授权”等形式。新对话设置、当前回合设置、沙盒以及详细授权项目均采用相同标准。提供方或用户设定的专属名称及实际传输值将予以保留。

模型比较功能会先显示当前模型，并将模型名称、特点、基本推理强度及支持的输入以卡片形式整理呈现。用户可通过“使用此模型”直接进行选择，选择结果将在提供商确认后生效。在详细信息中，可查看支持阶段及提供商的原文说明。

更改设置后，请求值和原生值分开显示。等待原生确认时，发送和有冲突的设置操作会暂停，停止按钮仍可使用。传输确认不代表设置已经生效。被拒绝或未确认的更改保持可见，不会自动重试。

命令与技能提供搜索图标、清空搜索操作和限制高度的滚动列表。名称左对齐，展开一行可阅读完整说明和详细信息。可搜索名称、说明和别名，仅限终端的项目以及无法在 GUI 中调用的技能不会显示。选择项目只会插入可编辑草稿，并保留已有文字和图片。Codex 技能的原生输入也会保留到明确发送时。

输入 `/` 可打开带简短说明的补全列表；Codex 技能也可从 `$` 补全。用上下方向键选择，按 Tab 或 Enter 插入，按 Esc 关闭。补全不会发送消息。已识别的命令和技能与普通文字分别显示。原生技能变化后请刷新目录。

会话设置只显示可在 GUI 中实际修改的项目，并按回复、工作方式、上下文和权限分组。只读列表和不可用设置不再显示。更改记录、恢复默认值和参考信息可从详情中查看。需要 CLI 界面时，请从**新建任务**打开单独的终端。

**新对话设置**使用当前选定账户和明确指定的启动选项打开独立对话。当前会话与草稿保持不变，也不会重放提示。审查、目标和排队任务等原生操作只会通过明确的执行按钮启动。当前轮次设置作用于已确认的运行中轮次的后续工作，不会更改已开始的工作。

包括提问和已知 MCP 操作在内的工具标题使用应用语言。展开卡片或将鼠标悬停在标题上可查看原始工具名；参数、输出、问题和差异内容保持原文。切换语言也会更新已有历史记录的标题。未知操作显示为外部工具。扩展准备或保留旧缓存的状态不代表已完成原生加载。

在消息中输入 `@`，即可搜索当前工作目录中的文件和文件夹。使用方向键选择、Tab 浏览文件夹、Enter 插入、Esc 关闭。包含空格或中文的路径也会用引号保留。选择只会修改草稿，发送仍需明确操作。Claude 保留原生 `@` 引用格式，Codex 使用与正式 TUI 相同的路径文本，Antigravity 接收所选完整路径。提供方的权限与上下文处理规则仍然适用。

## 各提供方的功能范围 {#provider-coverage}

## 个人扩展与账户范围 {#personal-extensions}

新启动时，会为所选私有配置准备受支持的个人 Claude·Codex 技能及自包含插件资源。Claude 还支持可移植的旧版命令、智能体、回复样式及工作流包。项目优先级遵循原生规则；共享 Codex HOME 技能与 Antigravity 资源仍由原生管理。现有账户登录·初始化行为保持不变。原始作者文件不会被修改，后续导入仍保留私有配置中的编辑·删除。状态轮询和恢复工作进程不会重新导入这些资源。

**扩展已准备**表示导入准备成功；**已保留现有扩展**表示为仍在使用的进程保留了旧缓存版本。它们都不表示已启用、已加载或已执行，原生发现和执行需要各自的结果。受支持的可移植插件声明能保留包内 hooks·MCP·LSP 配置，准备过程不会运行它们。含凭据的配置、账户关联连接器、不支持的格式、外部路径、例程及调度器状态需要原生设置，或显示诊断。Kiln 不会复制整个配置或账户历史。请参阅[原生插件加载](https://code.claude.com/docs/en/plugins/loading.md)。
