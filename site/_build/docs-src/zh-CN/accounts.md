title: 账户
description: 保存多个 Claude Code、Codex 和 Antigravity 账户，通过浏览器登录，在账户之间切换，并让用量信息保持最新。

Kiln 为你使用的每个代理账户各保存一份配置，在个人订阅和工作订阅之间切换时无需退出登录。打开**设置 → 账户**，即可管理 Claude Code 和 Codex 的订阅账户，以及 macOS 上 Antigravity 使用的 Google 账户。

请先为每个代理安装官方 CLI。Kiln 通过该 CLI 登录，从不自行实现 OAuth 提供方，也不会绕过提供方的账户政策。

## 添加账户 {#add-an-account}

1. 在代理卡片上选择**添加账户**。
2. 为配置命名，例如**个人**或**工作**。
3. 选择**通过浏览器登录**，在浏览器中完成身份验证。

Kiln 在后台等待，CLI 一报告登录成功就保存这份配置。不需要打开终端，也不需要运行登录命令。账户设置打开期间，可以查看进度、重新打开登录页面或取消登录。每次登录尝试五分钟后失效。

如果浏览器回调不可用，Claude Code 可能会改为显示登录代码。这时 Kiln 会显示一个掩码输入框，把代码粘贴进去即可。

> **警告：**这个输入框只用来粘贴登录代码，切勿在其中输入密码或 API 密钥。

已经用官方 CLI 登录过？选择**保存当前登录账户**，即可把这次登录导入为一份配置。

## 选择要用的账户 {#choose-which-account-to-use}

登录只会保存配置，不会改动现有 CLI 会话正在使用的账户。

- 在新登录的配置旁选择**应用**，新会话就会使用它。
- 在已有配置上选择**切换**，将其设为当前账户。
- 在配置所在行的菜单中可以重命名配置。

对于 Kiln 打开的面板，每个已保存的账户都有各自独立的配置，因此所有账户可以同时保持登录。正在运行的代理会话继续使用启动时的账户；切换后，新开一个代理面板才会用上新账户。在普通 Shell 中手动运行的 CLI 继续使用该 Shell 的配置，Kiln 绝不会重启它，也不会替换它的凭据。

运行中的面板达到用量限制时，Kiln 不会把它轮换到其他账户。请在这里改选其他账户，再新开一个面板。

## 重新登录 {#sign-in-again}

某份配置的登录需要修复时，用这个功能即可保留配置，不必删掉重建。

1. 打开该账户行的菜单，选择**重新登录**。
2. 核对显示的账户名称和电子邮件，然后选择**通过浏览器登录**。
3. 用同一个账户登录，完成后选择**应用**。

Kiln 会保留配置的名称、在列表中的位置和对话历史，也不会重启正在运行的终端。如果在浏览器中选了其他账户，本次尝试会被拒绝。取消或失败的尝试同样不会影响这份配置。

新凭据要等你选择**应用**后才生效，因此浏览器登录绝不会在你不知情时替换会话正在使用的登录信息。正在运行的 CLI 如果缓存了旧的登录信息，应用新登录后可能需要恢复会话。

### 需要重新登录 {#sign-in-required}

本地凭据存储确认某份配置的凭据已经不存在时，该行会显示**需要重新登录**，并提供**重新登录**按钮。账户设置打开期间以及你手动刷新时，Kiln 会在后台做这项检查。

这只是本地检查，不能证明账户在线上仍然有效。网络故障和访问令牌过期都不算退出登录，因为 CLI 会自行刷新令牌。如果提供方拒绝了登录，而本地凭据仍在，请从该行菜单中选择**重新登录**。

## 用量更新 {#usage-updates}

应用启动时，以及之后每隔五分钟，Kiln 会在后台检查每个已保存的 Claude Code 和 Codex 账户，未在使用的配置也包括在内。只要 Kiln 保持打开即可，账户设置不必一直显示。

- 每张卡片显示上次成功检查的时间；检查失败时，保留上次已知的用量条。
- 刷新按钮会请求再检查一次，但受提供方速率限制约束。
- 只有上报的时长恰好是五小时或七天时，Codex 的用量窗口才会显示对应标签。

这些检查是只读的。Kiln 不会发送模型提示词，也不会消耗重置额度。

| 情况 | Kiln 的处理 |
| --- | --- |
| 提供方限速 | 按提供方要求的时长等待（一分钟到一天之间）；提供方未说明时等待五分钟。手动检查也会顺延。 |
| 凭据被拒绝（401） | 暂停检查该凭据一小时。刚刷新的令牌可以立即检查，无需等待。 |
| 其他失败 | 在下一个周期重试，也可以手动重试。 |
| 无法识别的响应 | 将用量显示为不可用，不会编造数值。 |

令牌过期或被撤销时，用量检查可能无法进行，但正在运行的 CLI 仍能正常工作。如果一直失败，请在该配置的菜单中选择**重新登录**。

## Antigravity 账户 {#antigravity-accounts}

> **注意：** Antigravity 账户是 Kiln 0.2.12 新增的功能，仅限 macOS。在 Windows 上，请在终端中运行 `agy` 登录。

可以为 Antigravity CLI（`agy`）保存多个 Google 账户，并选择新任务使用哪一个。

1. 打开**设置 → 账户 → Antigravity**，选择**添加账户**。Kiln 会在一个临时的私有终端中启动已安装 CLI 的 Google 登录流程。
2. 在浏览器中登录。如果显示代码，请将其粘贴到**登录代码**，然后选择**确认**或按 Enter。复制时混入的换行和空格会被移除。验证时会显示**正在验证登录代码**，并阻止重复提交。代码被拒绝或过期时，本次尝试会结束并显示错误；请重新开始登录以获取新代码。认证成功后，选择**应用**。
3. 对其他账户重复以上步骤，再选择**切换**，让新任务使用该账户。

正在运行的任务继续使用原来的账户。行菜单提供重命名、删除，以及用同一个 Google 账户重新登录。**保存当前登录账户**会导入普通 CLI 的 Google 登录。

每个账户都有自己的私有主目录和 macOS 钥匙串，Antigravity 的偏好设置、设置和对话也都按账户分开保存。Kiln 绝不会替换普通 CLI 的登录，也不会改动你的默认钥匙串。账户主目录里没有你平时主目录中的文件，例如 Shell、Git 或 SSH 配置，但工作区文件仍然可以访问。

已应用的账户会显示官方 CLI 返回的各模型组已用比例和重置时间。应用启动时及之后每五分钟检查，也可手动刷新。这种只读检查需要 agy 1.1.11 或更高版本，不会启动代理回合或消耗模型配额。过期或失败的结果不会显示百分比。不提供自动切换。达到配额时，Kiln 会通知重置时间。登录使用 Google OAuth，不会自动设置 Google Cloud 项目。

在新的 Kiln zsh 终端中输入 `agy` 也会使用所选账户，并保留参数和当前目录。更新后请打开新终端。使用自定义 shell 时，请选择**新建任务 → Antigravity**。

这些账户的对话同样参与对话同步，在同一对话中重启时也会沿用原来的账户。详见[对话与更新](conversations.html)。

## 凭据存储位置 {#where-credentials-are-stored}

在 macOS 上，Kiln 把已保存的凭据存放在钥匙串中，绝不会重置或替换钥匙串。在 Windows 上，已保存的凭据是私有文件，由你的 Windows 用户密钥保护。账户列表只包含配置名称和元数据，从不包含访问令牌或刷新令牌。登录链接和代码不会写入设置或日志。

## 故障排除 {#troubleshooting}

- **登录失败：**检查浏览器和网络连接，然后重试。
- **找不到 CLI：**账户卡片上会提示缺少 CLI。请为该代理安装官方 CLI。

要更新 CLI 本身，详见[对话与更新](conversations.html#cli-updates)。
