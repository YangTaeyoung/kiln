Kiln の作業はすべて、ローカルデーモンが管理する本物のターミナルセッションで実行されます。シェル連携によってコマンドの追跡、アクティビティの報告、補完が加わり、ウィンドウを閉じてもセッションは動き続けます。

## シェル連携 {#shell-integration}

既定の zsh で開いた新しいセッションには、シェル連携が自動で適用されます。コマンドの区切りと作業ディレクトリを追跡し、`.zshrc` は変更しません。

引数を付けたカスタム起動や、bash、fish には、自動連携は適用されません。すでに開いているシェルに新しい連携の動作を反映するには、セッションを開き直す必要がある場合があります。連携をオフにするには `KILN_SHELL_INTEGRATION=0` を設定します。

### 既存の zsh セッションを連携させる {#attach-an-existing-zsh-session}

1. 設定で既定のシェルに `/bin/zsh` を選び、Kiln の新しいターミナルを開きます。これで連携用のファイルが準備されます。
2. 既存の zsh でフォアグラウンドの処理が終わるのを待ち、アイドル状態のプロンプトで次のコマンドを実行します。

```zsh
source ~/.local/share/kiln/shell-integration-v1/integration.zsh
```

既存のターミナルの中で `zsh` を起動しただけでは、Kiln の新規セッション用のセットアップは実行されません。

## アクティビティと通知 {#activity-and-notifications}

Kiln は、ターミナルの通知（OSC エスケープシーケンス）と明示的なアクティビティ報告を読み取ります。どちらもローカルのターミナルエスケープシーケンスで、プロンプトが外部のサービスに送られることはありません。

スクリプトやエージェントのフックからは `kiln activity` でアクティビティを報告します。

```sh
kiln activity running
kiln activity waiting
kiln activity done
kiln activity failed
```

通知を送るには `kiln notify` を使います。インストールされているバージョンの構文は `kiln activity --help` と `kiln notify --help` で確認してください。シェル連携では `kiln-agent-status running|waiting|done|failed|unknown` 関数も使えます。Kiln がアクティビティを受け取るには、フックの出力が Kiln のターミナルに届く必要があります。

Kiln は、Claude Code と Codex がターミナルのタイトルに出すアクティビティマーカーも認識します。そのため、フックを設定しなくても実行中であることが表示されます。入力待ちと失敗を明示的に報告した場合は、そちらが優先されます。何も報告しない通常のシェルやエージェントは、完了ではなく、開いているセッションとして表示されます。インジケーターと色については[エージェント](agents.html)を参照してください。

通知センターには最近の通知が残り、各通知は対応するセッションにひも付いています。通知を読むと、そのセッションの要確認状態が解除されます。

## コマンド履歴 {#command-history}

デーモンは最近のコマンドをメモリに保持しているので、コマンドとその出力をあとから確認できます。

| 制限 | 値 |
| --- | --- |
| 保持するコマンド数 | 最新の 40 件 |
| コマンドごとに保持する出力 | 先頭の 128 KiB |
| デーモンの再起動やアップグレード後も残るか | いいえ |

履歴は、各コマンドの出力を再構成したテキスト表示です。生のターミナルログではなく、フルスクリーン TUI の途中の画面をすべて記録するものでもありません。コマンドの区切りを追跡する連携がない場合、確認できるのは現在表示されている出力だけです。

履歴のコマンドを編集しても、実行されるのは実行操作を明示的に選んだときだけです。その場合は新しいターミナルで実行されます。

## シェル補完 {#shell-completion}

シェル連携が有効な状態で新しく開いた zsh ターミナルでは、入力するとカーソルの横に候補メニューが自動で表示され、カーソルに合わせて移動します。コマンド、サブコマンド、オプション、対応するローカルの引数が候補になります。

| キー | 操作 |
| --- | --- |
| `Tab` | ハイライトされた候補を挿入する |
| `Down` | メニューを選択し、その後は矢印キーで候補を移動する |
| `Enter` | メニューを選択済みなら挿入し、それ以外は入力したコマンドを実行する |
| `Esc` | メニューを閉じる |
| `Ctrl+Space` | メニューを開くか再び開いて選択する、またはインストール済みのコマンド名を検索する |

候補を挿入すると、コマンドラインの内容が変わります。実行するには、もう一度 `Enter` を押します。自動表示されたメニューを選択する前に `Enter` を押すと、元の入力どおりにコマンドを実行します。メニューが閉じているときは、zsh 本来の `Tab` 補完が通常どおり動作します。

入力したコマンドと引数に応じて、次の候補が表示されます。

- `cd` は、ターミナルの現在のディレクトリからフォルダーを候補として表示します。フォルダーを選んだ後、次の階層のパスを続けて補完できます。
- ファイルを指定する引数にはローカルのパスが表示されます。`docker --config` と `docker compose --project-directory` はフォルダー、`docker compose --file` はファイルが候補になります。
- Git のコマンドでは、現在のリポジトリのローカルブランチを候補にできます。
- `npm run`、`pnpm run`、`yarn run`、`bun run` では、プロジェクトの `package.json` に定義されたスクリプト名が候補になります。

Kiln は、対応するインストール済み CLI のローカルヘルプからコマンド、サブコマンド、オプションの情報を自動で読み取り、結果をキャッシュします。オフラインでも使える同梱の候補データには、Docker Engine、Buildx、Compose も含まれます。コマンドのヘルプに対応していない場合や取得できない場合は、そのコマンドで利用できるローカルまたは同梱の候補を使います。

ヘルプの取得は、入力した引数の値を渡さず、分離した一時環境で実行します。補完に AI は使わず、シェルの履歴ファイルを読んだり、補完データをクラウドサービスへ送ったりすることもありません。

候補を自動で表示しないようにするには、**設定 → ターミナル**で**コマンド入力候補**をオフにします。この場合も `Ctrl+Space` は使えます。シェル側でもプレビュー用のデータを生成しないようにするには、シェルで `KILN_COMPLETION_PREVIEW=0` を設定します。

補完に対応しているのは zsh だけです。更新された連携を読み込むには、新しいターミナルを開いてください。既存のターミナルは現在のシェル設定を保持します。Bash、fish、SSH セッション、エージェントとのチャット、フルスクリーンのアプリケーション、その他のシェルでは、入力の動作は通常どおりです。連携のヘルプはターミナルのコンテキストメニューにあります。

## 接続の復旧 {#connection-recovery}

Kiln は、ターミナルの接続と、その中で動くシェルやエージェントを分けて管理しています。パネルの接続が切れたり応答しなくなったりすると、Kiln は接続を修復して画面を再描画し、CLI にも再描画を求めます。エージェントの再起動、プロンプトの送信、`/resume` の代行は行いません。

| パネルの表示 | 意味 |
| --- | --- |
| **再接続中** | Kiln が接続を修復しています（最大 3 回試行）。 |
| **接続停止** | 修復に失敗しました。**再接続**を選ぶと、もう一度試せます。 |

**再接続**は、実行中のすべてのターミナルパネルの **…** メニューにもあり、接続が正常に見えるときでも使えます。選ぶと、そのパネルの再試行回数がリセットされます。思考中や入力待ちで出力が止まっているだけのエージェントは、停止とは見なしません。

復旧中もセッションとそのプロセスは動き続け、それまでのテキストも画面に残ります。入力は一時的に受け付けなくなるので、切れた接続に入力がたまることはありません。

> **注意:** 接続が正常なまま、CLI の内部で処理が止まることがあります。その場合は**再接続**では直せません。別のパネルを開いて、CLI 自身の再開（resume）機能を使ってください。

## ウィンドウを閉じても続くセッション {#sessions-that-outlive-the-window}

ターミナルはウィンドウではなく、セッションデーモンに属しています。Kiln を閉じてもシェルとエージェントは動き続け、開き直せばそのセッションに戻れます。アップデートしても、実行中のターミナルは維持されます。システムの再起動やデーモンの明示的な停止では、セッションが終了する場合があります。

- **macOS:** メニューバーのアイコンのメニューには、**設定…** と**バックグラウンドセッションを終了…** があります。バックグラウンドセッションを終了しようとすると、稼働中のセッションの一覧と確認画面が表示されます。既定のボタンは**キャンセル**です。開いているワークスペースのセッションも対象になるため、未保存のシェルやエージェントの作業が失われることがあります。
- **Windows:** 通知領域のアイコンにはセッションの概要が表示され、対応が必要なものや未読の通知があると赤い点が付きます。メニューには **Kiln を開く**、**設定**、**バックグラウンドセッションを終了…** があります。

> **警告:** `kiln status` はセッションデーモンの状態を表示します。ウィンドウを再読み込みする目的で `shutdown-daemon` を使わないでください。セッションが終了してしまいます。

## macOS のローカルネットワークアクセス {#local-network-access-on-macos}

macOS 15 以降では、ローカルネットワークへの接続に許可が必要です。サーバーがローカルネットワーク上にあると、`kubectl get nodes` などのターミナルコマンド、SSH、データベース接続、リモートファイルが影響を受けることがあります。

1. **Kiln → 設定 → 動作**を開きます。
2. **プライバシー → ローカルネットワーク**で**アクセスをリクエスト**を選びます。
3. macOS の確認画面が表示されたら Kiln を許可し、コマンドを再実行します。

歯車ボタンから**システム設定 → プライバシーとセキュリティ**を開き、**ローカルネットワーク**で Kiln の状態を確認できます。Kiln からは、システム側の許可状態を読み取ることも変更することもできません。また、すでに許可または拒否を選んでいる場合、macOS は確認画面を再表示しないことがあります。

> **ヒント:** アップデート前に開いたパネルは、古いプロセス設定のまま動いています。そこでローカルネットワークを使うコマンドが失敗した場合は、新しいターミナルパネルを開いて再実行してください。

## Windows のシェル {#windows-shells}

ターミナルは、PowerShell 7 がインストールされていれば PowerShell 7 で、なければ Windows PowerShell で起動します。`cmd.exe`、Git Bash、WSL ディストリビューションは**設定 → ターミナル**で選べます。

- PowerShell と cmd は、コマンド、終了コード、現在の場所を Kiln に報告します。カスタムプロンプトからも直前のコマンドの状態を参照できます。
- PowerShell では PSReadLine の補完（`Tab`、`Ctrl+Space`）がそのまま使えます。Kiln の補完メニューは zsh 専用です。
- ターミナルを閉じると、そこで動いているコンソールプログラムは終了します。ブラウザーなど、ターミナルから起動したウィンドウアプリケーションは動き続けます。
- パネルの名前には、シェルで実行中の最も新しいコンソールプログラムの名前が使われます。Git Bash から起動したプログラムは追跡されません。
- ターミナルとエディターで韓国語 IME の入力が使えます。
