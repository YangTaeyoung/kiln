Kiln は、Claude Code、Codex、Google の Antigravity CLI（`agy`）をワークスペースのパネルで実行します。リクエストを書いてエージェントを選ぶだけで、ターミナルを探し回らなくても、すべての作業の状態をサイドバーで確認できます。

## 始める前に {#before-you-start}

エージェントは外部のツールです。使うエージェントごとに公式の CLI をインストールし、ログインしておいてください。Kiln にはどのエージェントのサブスクリプションも含まれていません。

- **Claude Code** と **Codex**: CLI をインストールしてから、**設定 → アカウント**でアカウントを追加します。詳しくは[アカウント](accounts.html)を参照してください。
- **Antigravity**: Google のインストーラーで `agy` をインストールします。macOS では**設定 → アカウント → Antigravity** からログインします。Windows では、ターミナルで `agy` を実行してログインします。Kiln は `agy` を `PATH`、`~/.local/bin`、`/opt/homebrew/bin`、`/usr/local/bin` から探します。

Windows では、Claude Code と Codex はネイティブの Windows プログラムとして動作し、ホームディレクトリは `%USERPROFILE%\.codex` と `%USERPROFILE%\.claude` です。

## 作業を開始する {#start-a-task}

**新しい作業**を選んでリクエストを入力し、エージェントを選んで開始します。エージェントの選択欄（Claude Code、Codex、Antigravity）は、常にリクエスト入力欄のすぐ下にあります。リポジトリのコンテキストは別にスクロールするので、概要が長くても開始ボタンが画面の外に押し出されることはありません。

Antigravity では、次の方法も使えます。

| 操作 | 内容 |
| --- | --- |
| **新しい作業 → Antigravity** | 現在のワークスペースで `agy` を起動します。 |
| **新しい作業 → フォルダーで開く → Antigravity** | 先にフォルダーを選ぶよう求め、そのフォルダーで `agy` を起動します。 |
| **Antigravity の新規タスク**（コマンドパレット、`⌘K`） | Antigravity の作業を開始します。 |

リクエストの下で Antigravity を選ぶと、Kiln はリクエストとリポジトリの概要を最初のプロンプトとして `agy` に渡します。`antigravity` コマンドは Antigravity のエディターを開くものなので、Kiln はエージェントとして扱いません。

未送信のリクエストはワークスペースと一緒に保存され、Kiln を再び開くと復元されます。ワークスペースを閉じるときは、破棄する前に確認が表示されます。

パネル上部の右分割・下分割ボタンから、新しいパネルで開くターミナルやエージェントを選べます。分割のショートカットはターミナルを直接開きます。

## 会話画面またはターミナル {#conversation-gui}

**新規タスク**と右/下分割メニューで、エージェントを選ぶ前に **会話 GUI** または **ターミナル**を選択します。新しいエージェントは会話 GUI が既定です。**設定 → 動作 → 新規エージェントの表示**で変更できます。通常のターミナル、SSH、既存のターミナルタスクは現在の表示を維持します。

会話画面にはストリーミング Markdown、展開できるツール入出力とファイル diff が表示されます。権限要求や質問に画面内で回答でき、許可と拒否の両方を選べます。ヘッダーは起動時のアカウントを固定し、適用が確認されたモデルとモードを示します。入力欄にはプロバイダーが公開したモデルとモードだけが表示され、既存の MCP と権限設定は維持されます。

**Enter** または **送信** で送信し、**Shift+Enter** で改行します。IME の変換中や確定操作では送信されません。**画像を添付** で複数のファイルを一度に選ぶか、メッセージ入力欄にフォーカスを置いて画像を貼り付けるか、添付先の会話ペインにファイルをドロップしてください。下書きごとに最大 8 枚（PNG、JPEG、GIF、WebP、各 20 MiB）を添付できます。テキストの貼り付けは通常どおり入力されます。サムネイルで画像を確認し、各画像の **×** ボタンで送信前に削除できます。復元された添付が見つからない場合や無効な場合は、削除してから送信してください。**停止** は現在のターンを中断します。

Kiln を閉じると下書きが保存され、デーモンはワーカーを維持します。パネルを閉じるとセッションが終了し、下書きの破棄前に確認します。ローカル送信はジャーナルの確認を待ち、再表示しても再送しません。未確認の送信は **下書きに戻す**で復元できます。意図的に再送する前に履歴を確認してください。失敗や切断時も履歴は残り、**同じ会話で再起動**できます。以前/最新のメッセージ操作は履歴を削除せず、表示範囲を移動します。

承認カードには翻訳済みの見出しとコマンド、作業フォルダー、対象パス、理由、要求権限を表示し、通信 ID やスキーマは表示しません。履歴の読み込み後、ジャーナルと送信待ち一覧に存在しない以前の送信は、ワーカーが準備完了でも明示的に下書きへ戻せます。自動再送はしません。

Claude の承認カードには業務 ID を含む実際の MCP・ツール引数を表示します。長い入力は一部のみの表示と明示し、Codex の通信パラメーターやスキーマは引き続き表示しません。下書きの復元は、以前のクライアントによる最後の送信書き込みを反映した確認を待ちます。

入力欄の上の状態表示で、応答作成・ツール実行・入力待ち・応答完了を区別できます。過去のメッセージを読んでいる間も表示されます。Claude が報告したシェル・Monitor・その他のバックグラウンドタスクの説明、状態、進捗、提供された実行時間を確認でき、各タスクを開くと詳細が表示されます。常駐の監視タスクは、応答作成中とは区別して一覧に残ります。他の AI でも報告された実行中のツールを表示します。上へスクロールしたときや過去の履歴を開いたときは、**↓ 最新メッセージへ**で下書きを保ったまま最新の履歴へ戻れます。

シェル・Monitor の詳細の **出力を表示 · 更新** は、AI に新しい要求を送らずに最新の出力を読み取ります。末尾のみの表示、出力なし、取得不可を区別します。

### 同じ会話の表示を切り替える {#switch-presentation}

ネイティブ端末の作業一覧でも、保存済みの「Claude Code」などの既定名で実際の会話タイトルを隠しません。意味のあるカスタムタブ名とセッション名を優先します。

待機中の GUI→TUI 切り替えでは、会話に保存された環境変数と作業フォルダーで MCP コマンドを確認します。MCP 固有の `PATH` 設定も反映します。MCP サービスの接続自体は、モデルの処理中を意味しません。

作業中もTUIへの切り替えを要求できます。現在の作業はGUIで続行し、応答・承認・待機作業が終わり所有権の確認に成功すると自動で切り替えます。GUIを選ぶと予約を取り消せます。実行中のモデル要求を別プロセスに即座に移す方式ではありません。ネイティブTUIからGUIに戻る場合は、GUIの実行主体を開始する前にCLIの正常終了が必要です。TUIを選ぶと復帰要求を取り消せます。

パネルのタイトルと自動作業名には、最初に送信したリクエストを短く表示します。手動で付けた名前は維持され、下書きの編集で既存の会話名は変わりません。

各エージェントの表示領域の右上、閉じるボタンの下にある一体型の **GUI | TUI** タブで切り替えます。返信には名前とエージェントのアイコンを表示します。ツールの詳細を開くと、判別できるファイル言語とシェルコマンドの構文強調、読みやすいスクロール領域、コピー機能を利用できます。判別できない出力は通常のテキストで表示します。

エージェントペインの **GUI | TUI** タブで、元のアカウントと作業フォルダーを保ちながら同じ確認済みの会話を続けられます。新しい Claude Code の会話は最初のメッセージを送る前でもターミナルで開けます。まだ存在しない履歴ファイルを再開しようとはしません。切り替え要求は作業中も受け付け、応答・承認・送信待ちが終了してから実行します。バックグラウンドタスクが残っている場合やプロセスの所有権を確認できない場合は、切り替えを拒否してその処理を維持します。前のエージェントの終了を確認してからターミナルを開き、切り替えられない場合は理由を表示します。

対応する Claude Code の mod が接続されていれば、**GUI** を選ぶと、ネイティブ入力欄が待機中で空になった時点で自動復帰します。実行中の処理、承認、入力中の下書き、報告された shell/Monitor の表示がある間は復帰を保留します。**TUI** で予約を取り消せます。Claude 自身の正常終了機能を使い、終了を確認してから同じ会話を再接続します。追加されたユーザーとアシスタントのテキストを取り込み、画像は添付の案内として表示します。以前の履歴に不一致があれば GUI 履歴を保持して通知します。

Kiln が登録したシェル関数から起動した対話型の `claude`、`codex`、`agy` コマンドでも、同じ **GUI | TUI** タブを使えます。Kiln は、そのターミナルに対応する稼働中ホストの正確な関連付けを確認してからペインを接続します。元の PTY、親シェル、コマンド引数、選択したアカウントプロファイルを維持します。Kiln の zsh または PowerShell 連携が提供する関数が対象で、登録されるコマンドはシェルによって異なります。

macOS では、すでに動作中の追跡対象 Claude ターミナルや古い GUI ワーカーのネイティブ画面にも、**GUI** の選択で互換 mod を接続できます。正確なプロセス・会話・元のアカウントを確認してから再読み込みを要求します。作業と未送信の下書きは正常復帰までターミナルに維持します。**TUI** を選ぶと取り消しの確認を待ちます。終了がすでに確定していた場合は、同じ会話を接続した後、要求したターミナル表示に戻ります。

macOS では、Kiln の GUI から開いた Codex の会話で **GUI** を選ぶと、現在の作業が完了し、TUI の入力が空になった時点で自動的に戻ります。作業や入力中の下書きがある間は CLI を維持します。それ以外の既存セッション、Antigravity、Claude mod の未対応・無効化、独自ショートカットの競合、入力の所有権を確認できない古い Windows ワーカーでは、**GUI** を選んでから CLI を正常終了してください。対応していれば `/exit` または **Ctrl+D** を使えます。案内は接続準備・作業待機・下書き・手動復帰を区別します。更新は既存のプロセスを維持し、既存セッションの接続で動作中の CLI を置き換えません。最初の TUI で GUI を要求せず終了すると元のシェルに戻ります。

管理用・出力専用・リモートのコマンド、パイプライン、入出力のリダイレクト、Kiln 連携を経由しないユーザーのエイリアスや関数は、通常のネイティブ実行を続けます。Bash と fish にはエージェントのラッパーを自動登録しません。Kiln 外のターミナルで実行したコマンドは自動追跡しません。

ターミナルから始めたエージェントは、正確なネイティブ会話が追跡されている場合に限り GUI に取り込めます。macOS の互換 Claude ターミナルは上記の方法で自動復帰できます。それ以外は先に CLI を終了してください。デーモンが元のプロセスの終了を確認した後にのみ、記録されたアカウント環境と作業フォルダーで GUI の実行主体を起動します。接続切れや会話を特定できないことだけでは終了と判断しません。

## 複数のリポジトリにまたがって作業する {#work-across-several-repositories}

フロントエンド、バックエンド、共有ライブラリが別々の Git リポジトリにある場合は、`~/dev/projects` のような親フォルダーを開きます。Kiln はそのフォルダーをエージェントの作業ルートとして保ち、検出したリポジトリ構成をリクエストに含めることができるため、1 つのリクエストですべてのリポジトリを扱えます。

Git や GitHub のツールでリポジトリを確認しても、作業ディレクトリは変わりません。Git 操作の対象を 1 つのリポジトリにするには、それらのツールにあるリポジトリセレクターを使います。詳しくは[ワークスペースと作業](workspaces.html)と [Git と GitHub](git.html) を参照してください。

## 作業の状態を確認する {#follow-task-state}

サイドバーの各作業の行には、エージェントが報告した状態が表示されます。

| 状態 | 意味 |
| --- | --- |
| 作業中 | エージェントが作業しています。 |
| 入力待ち | エージェントが入力を求めています。 |
| 完了 | エージェントが作業を終えました。 |
| 失敗 | エージェントが失敗を報告しました。 |
| セッション開始済み | 状態が報告されていません。Kiln は推測せず、開いているセッションとして表示します。 |

並び順は、実行中の作業、入力待ちのリクエスト、以前に失敗した作業の順です。作業をクリックすると、そのワークスペース、タブ、分割に移動します。拡大表示で隠れているパネルも表示されます。

### Kiln が状態を知る仕組み {#how-kiln-knows-the-state}

Kiln が状態を正確に表示するには、エージェントが状態を報告するか、Kiln が認識できる実行中のタイトルを表示する必要があります。

- Kiln は Claude Code と Codex のターミナルタイトルにあるアクティビティマーカーを認識するため、追加の設定なしで実行中のアクティビティが表示されます。
- Claude Code の `✳` マーカーはダイアログが開いている間にも表示されるため、完了とは見なしません。
- 明示的な入力待ちと失敗のシグナルは、タイトルのマーカーより優先されます。
- アイドル状態のターミナルが完了した作業として扱われることはなく、終了していない起動コマンドによって、アイドル状態のエージェントが実行中と表示されることもありません。

スクリプトやその他のツールは、`kiln activity running`、`waiting`、`done`、`failed` で状態を報告できます。アクティビティの報告と通知については[ターミナル](terminal.html)を参照してください。

### インジケーターの色 {#indicator-colors}

| エージェント | インジケーター |
| --- | --- |
| Claude Code | オレンジ |
| Codex | 青 |
| Antigravity | タブ、作業一覧、サイドバーに Antigravity のマーク |
| 識別できないセッション | 無彩色 |

インジケーターは、サイドバー、タブ、パネルヘッダーに表示されます。分割したタブで状態の優先度が同じときは、フォーカスのあるパネルの状態が表示されます。警告は常に優先されます。

## 通知と使用量の上限 {#notifications-and-usage-limits}

通知センターには最近の通知が残り、各通知は対応するセッションにひも付いています。通知を読むと、そのセッションの要確認状態が解除されます。Windows では、エージェントの通知が Windows のトースト通知として表示されます。

Antigravity がクォータの上限に達したと報告すると、Kiln はリセット時刻を添えて使用量上限の通知を表示します。Claude Code と Codex では、パネルは開いたときのアカウントを使い続けます。アカウントが使用量の上限に達したら、**設定 → アカウント**で別のアカウントに切り替え、新しいパネルを開いてください。詳しくは[アカウント](accounts.html#choose-which-account-to-use)を参照してください。

## Codex の混雑時の自動復旧 {#codex-capacity-recovery}

Kiln が開いている間、Kiln が管理する Codex のパネルでは、サーバーの混雑が原因で Codex が終了したターンを再試行します。再試行が始まるのは、この特定の Codex エラーのときだけです。使用量の上限、ログインの失敗、ストリームのエラー、キャンセルされたターン、成功したターンは再試行の対象外です。

- 再試行までの待ち時間は 15、30、60、120、240 秒です。パネルにはカウントダウンと**自動再試行をキャンセル**ボタンが表示されます。
- 失敗の後にパネルで何か入力すると、入力途中のプロンプトであっても、保留中の再試行はキャンセルされます。
- 自分で新しいリクエストを送信した場合、再試行は改めて 1 回目から数えられます。
- 再試行では同じアカウントとモデルを使います。

Codex CLI がまだ開いている場合、Kiln は同じ会話に続行用のプロンプトを 1 回送ります。CLI が終了している場合は、元のアカウントと作業ディレクトリで同じ会話を再開してから、そのプロンプトを送ります。このプロンプトは、完了済みの操作を繰り返す前に現在の状態を確認するよう Codex に求めるものです。元のリクエストを再送することはなく、失敗したターンの間に行われた変更が元に戻されることもありません。

再試行の対象は、保存済みのアカウントで開いた Codex のパネルのうち、Kiln が会話を確認できたものです。実行中の CLI を Kiln が監視し始める前に起きた失敗は、自分で対処してください。

## Codex のバックグラウンドサーバーの設定 {#codex-background-server-settings}

Kiln が新しく開く Codex のパネルは `--no-daemon` で実行されるので、Codex 本体の共有バックグラウンドサーバーからは独立しています。Codex のセッションが **Background server has incompatible feature settings**（バックグラウンドサーバーの機能設定に互換性がありません）と報告した場合は、そのセッションの機能フラグが、サーバーに保存されている設定と食い違っています。次のいずれかを選べます。

| オプション | 効果 |
| --- | --- |
| **Run without daemon this time**（今回はデーモンなしで実行） | 共有の Codex サーバーを再起動せずに、このセッションを開始します。CLI では `codex --no-daemon` に相当します。 |
| **Restart with these settings**（この設定で再起動） | 共有の設定を変更します。ほかのクライアントの実行中または待機中の処理が中断される場合があるため、先に確認してください。 |

新しく開いた Kiln の Zsh ターミナルでは、直接入力する `codex`、`codex resume …`、`codex fork …` にも `--no-daemon` が適用されます。共有サーバーが **Server is draining; retry after reconnecting** を返しても、これらのコマンドは独立して起動します。明示的な `--remote` 接続、既存のエイリアスや関数、その他のコマンド形式とシェルは従来どおりに動作します。ラッパーを使わない場合は `command codex …` を、ローカルセッションを直接実行する場合は `--no-daemon` を使用してください。既存のシェルには開き直した後で適用されます。Kiln は共有サーバーを再起動したり、更新設定を変更したりしません。

## ネイティブの会話設定とコマンド {#native-session-settings}

応答中も送信ボタンまたはEnterで追加メッセージを送信できます。停止ボタンは別に表示されます。Claudeはストリーミング追加入力を受け取り、Codexは現在のターンに入力を追加します。Codexでは会話設定の確認待ちでも、確認済みの現在のターンに追加メッセージを送信できます。Antigravityは現在の要求が完了するまで追加メッセージを1件保持します。受領確認待ちと受領済みを区別し、自動再送しません。

応答中もモデル・推論強度・モードを選択できます。Claudeはネイティブの適用タイミングで変更します。Codexの入力欄の選択は次のターンに適用され、明示的な現在のターン設定アクションは対応する設定を現在のターンに適用します。設定はネイティブの確認を待ちます。ワークスペースの履歴にはプロバイダー名ではなく会話タイトルを表示し、独自のページタイトルは保持します。

会話 GUI の **セッション設定**でプロバイダーの設定を検索し、**コマンドとスキル**でネイティブのコマンドを探せます。コンパクトな 2 行の入力欄の下に、画像添付、モデル・モード、**推論設定**、丸い送信・停止ボタンを 1 行にまとめています。狭いパネルではモデルと **会話オプション**を表示し、残りの設定を会話オプションにまとめます。モデル名は読みやすく、モードと推論の強度はアプリの言語で表示し、プロバイダーへ送る値は保持します。未取得の一覧と空の一覧も区別します。

推論設定や狭いパネルの対話オプションで、各ステップの説明を読み、推論の強さを選択できます。ClaudeのUltracodeは独立したスイッチであり、オンにすると紫色で表示されます。ヘッダーには、適用が確認されたモデルとモードが表示されます。

Claude Code、Codex、Antigravityの設定およびデフォルトの選択肢では、アプリの言語で名前と動作の説明が併記されます。韓国語では、承認ポリシーも「必要なときに承認をリクエスト」のように表示されます。新しいダイアログ設定、現在のターン設定、サンドボックス、および詳細な承認項目にも、同じ基準が適用されます。プロバイダーやユーザーが設定した固有の名前と実際の送信値は維持されます。

モデルの比較では、まず現在のモデルが表示され、モデル名・特徴・基本推論強度・対応入力がカード形式でまとめられています。「このモデルを使用」を選択するとすぐに利用でき、選択結果はプロバイダーの確認後に適用されます。詳細情報では、対応レベルとプロバイダーの説明原文を確認できます。

ネイティブ UI にサンプル一覧を表示した画像です。実際のアカウントのモデル応答ではありません。

設定を変更すると、要求した値とネイティブ値を別々に表示します。ネイティブの確認待ちの間は送信と競合する設定変更を止め、停止は引き続き使えます。送信の受理だけでは設定の適用を確定しません。拒否・未確認の変更は表示を維持し、自動で再試行しません。

コマンドとスキルには検索アイコン、検索のクリア、高さを制限したスクロール一覧があります。名前は左揃えで、行を展開すると説明全文と詳細を読めます。名前・説明・別名を検索し、CLI 画面を使うコマンドには CLI コマンドのラベルが付きます。GUI から実行できないスキルは表示しません。選択すると既存の本文と画像を保持して、編集可能な下書きにだけ挿入します。Codex スキルのネイティブ入力も、明示的に送信するまで保持します。

`/` を入力すると短い説明付きの補完一覧が開き、Codex スキルは `$` からも補完できます。上下キーで選択、Tab または Enter で挿入、Esc で閉じます。Tab または候補の選択で下書きを編集します。コマンド名を最後まで入力したら、Enter または送信ボタンで実行します。認識したコマンド・スキルは通常の文章と区別して表示します。ネイティブスキルを変更したら一覧を更新してください。

セッション設定には GUI で実際に変更できる項目だけを、応答・作業方法・コンテキスト・権限別に表示します。読み取り専用の一覧と利用できない設定は表示しません。変更履歴・初期値への復元・参考情報は詳細から確認できます。CLI が必要な場合は **新しいタスク**から別のターミナルを開いてください。

`/mcp` を送信すると、現在の会話の CLI とアカウントの MCP サーバーを表示します。Codex と Claude Code では、セッションの状態と CLI が報告したツール名を表示します。Antigravity では、グローバルとワークスペースのサーバー設定と有効・無効を表示します。プラグインのサーバーと接続状況は CLI コマンドパネルで確認できます。スラッシュ一覧には、プロバイダーの公式コマンドと別名、実行中の CLI が報告したコマンドが表示されます。Codex の `/rename`、`/diff`、`/mention` などは Kiln の画面で開きます。CLI 画面を使うコマンドを送信すると、同じペインに CLI が開きます。入力欄が表示されたら **CLI の入力欄に挿入**を選び、Enter で実行します。利用できるコマンドとダイアログは、インストール済みのバージョン、アカウント、プラットフォームに応じてプロバイダーが決定します。

**新しい会話の設定**は、現在選択中のアカウントと明示した起動オプションで別の会話を開きます。現在のセッションと下書きを保持し、プロンプトを再実行しません。レビュー・目標・待機タスクなどのネイティブ操作は実行ボタンから開始します。Codex ではレビュー・目標・会話の圧縮をスラッシュコマンドでも実行できます。現在のターン設定は、確認された実行中ターンの以降の処理に適用し、開始済みの処理は変更しません。

質問や既知の MCP 操作を含むツールの見出しはアプリの言語で表示します。カードを展開するか見出しにポインターを合わせると元のツール名を確認でき、引数・出力・質問・差分は原文のままです。言語変更は既存の履歴の見出しにも反映されます。不明な操作は外部ツールとして表示します。拡張の準備や古いキャッシュの保持は、ネイティブの読み込み完了を意味しません。

メッセージに `@` を入力すると、現在の作業フォルダーのファイルとフォルダーを検索できます。矢印キーで選び、Tab でフォルダーを参照し、Enter で挿入、Esc で閉じます。空白や日本語を含むパスも引用符で保持します。選択は下書きだけを変更し、送信は明示操作です。Claude はネイティブの `@` 参照形式、Codex は正式 TUI と同じパステキスト、Antigravity は選択したフルパスを受け取ります。プロバイダーの権限とコンテキスト処理ルールは引き続き適用されます。

Codex パネルでは、OpenAI の Chrome プラグインがインストールされ有効になっていると、`@Chrome` で選択できます。先に ChatGPT デスクトップアプリで ChatGPT Chrome 拡張機能を設定します。管理対象の Codex アカウントでは、プロファイルで Chrome プラグインが有効な場合、既定の Codex に同梱されているマーケットプレイスを利用できます。サイトへのアクセスと承認は Chrome と OpenAI の設定に従います。

### 次の入力候補 {#prompt-suggestions}

Claude Code が次の入力候補を送ると、GUI の空の入力欄に薄い文字で表示します。**Tab** で下書きに取り込み、**Enter** または送信で送ります。**Esc** でその候補を隠します。入力済みの内容、添付、IME の変換を優先します。候補は Claude の設定と提供状況に従い、毎回表示されるとは限りません。Kiln が代わりの候補を作ることはありません。

## 個人の拡張とアカウントの範囲 {#personal-extensions}

新規起動時に、対応する個人の Claude・Codex スキルと自己完結したプラグイン資産を、選択した非公開プロファイルに準備します。Claude は移植可能な従来のコマンド、エージェント、応答スタイル、ワークフローバンドルにも対応します。プロジェクトの優先順位はネイティブ規則に従い、共有 Codex HOME スキルと Antigravity 資産はネイティブで管理します。既存のログイン・初期設定動作は維持されます。元の作成ファイルは変更せず、後のインポートでも非公開プロファイルの編集・削除を保持します。状態照会やワーカーの再開では再インポートしません。

**拡張を準備済み**はインポート準備の成功、**既存の拡張を保持**は利用中のプロセスのために以前のキャッシュ版を残したことを示します。有効化・読み込み・実行の成功ではなく、ネイティブの検出・実行結果は別途必要です。対応する移植可能なプラグイン宣言は、準備中に実行せず、バンドル内の hooks・MCP・LSP 設定を保持できます。認証情報を含む設定、アカウント連携コネクター、未対応形式、外部パス、ルーチン・スケジューラー状態はネイティブ設定が必要か、診断が表示されます。設定全体やアカウント履歴はコピーしません。[ネイティブのプラグイン読み込み](https://code.claude.com/docs/en/plugins/loading.md)をご覧ください。

ターミナルでは、スキップした拡張ごとのエラーを出力せず、要約を1行表示します。個別の理由を確認するには、起動前に `KILN_EXTENSION_DIAGNOSTICS=1` を設定してください。
