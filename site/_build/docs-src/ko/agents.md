Kiln은 Claude Code, Codex, Google의 Antigravity CLI(`agy`)를 워크스페이스 패널 안에서 실행합니다. 요청을 쓰고 에이전트를 고르면, 터미널을 일일이 뒤질 필요 없이 사이드바에서 모든 작업의 상태를 확인할 수 있습니다.

## 시작하기 전에 {#before-you-start}

에이전트는 외부 도구입니다. 사용할 에이전트마다 공식 CLI를 설치하고 로그인하세요. Kiln에는 어떤 에이전트의 구독도 포함되어 있지 않습니다.

- **Claude Code**와 **Codex**: CLI를 설치한 뒤 **설정 → 계정**에서 계정을 추가합니다. [계정](accounts.html)을 참고하세요.
- **Antigravity**: Google 설치 프로그램으로 `agy`를 설치합니다. macOS에서는 **설정 → 계정 → Antigravity**에서, Windows에서는 터미널에서 `agy`를 실행해 로그인합니다. Kiln은 `PATH`, `~/.local/bin`, `/opt/homebrew/bin`, `/usr/local/bin`에서 `agy`를 찾습니다.

Windows에서 Claude Code와 Codex는 네이티브 Windows 프로그램으로 실행되며, 홈 디렉터리는 각각 `%USERPROFILE%\.codex`와 `%USERPROFILE%\.claude`입니다.

## 작업 시작하기 {#start-a-task}

**새 작업**을 선택하고 요청을 입력한 뒤 에이전트를 골라 시작합니다. 에이전트 선택기(Claude Code, Codex, Antigravity)는 요청 입력란 바로 아래에 고정되어 있습니다. 저장소 컨텍스트는 따로 스크롤되므로, 요약이 길어도 시작 버튼이 화면 밖으로 밀려나지 않습니다.

Antigravity는 다음 방법으로도 시작할 수 있습니다.

| 동작 | 하는 일 |
| --- | --- |
| **새 작업 → Antigravity** | 현재 워크스페이스에서 `agy`를 시작합니다. |
| **새 작업 → 폴더에서 열기 → Antigravity** | 먼저 폴더를 고르게 한 뒤 그 폴더에서 `agy`를 시작합니다. |
| **Antigravity로 새 작업** (명령 팔레트, `⌘K`) | Antigravity 작업을 시작합니다. |

요청 아래에서 Antigravity를 고르면 Kiln은 요청과 저장소 요약을 `agy`의 첫 프롬프트로 넘깁니다. `antigravity` 명령은 Antigravity 편집기를 여는 명령이므로 Kiln은 이를 에이전트로 다루지 않습니다.

보내지 않은 요청은 워크스페이스와 함께 저장되고, Kiln을 다시 열면 복원됩니다. 워크스페이스를 닫을 때는 요청을 버리기 전에 확인을 받습니다.

패널 상단의 오른쪽·아래쪽 분할 버튼에서 새 패널에 열 터미널이나 에이전트를 고를 수 있습니다. 분할 단축키는 터미널을 바로 엽니다.

## 대화 화면 또는 터미널 {#conversation-gui}

**새 작업**과 오른쪽/아래 분할 메뉴에서 에이전트를 고르기 전에 **대화 GUI** 또는 **터미널**을 선택하세요. 새 에이전트는 대화 GUI로 시작합니다. **설정 → 동작 → 새 에이전트 표시 방식**에서 기본값을 바꿀 수 있습니다. 일반 터미널, SSH, 기존 터미널 작업은 현재 표시 방식을 유지합니다.

대화 화면에서 스트리밍 Markdown, 펼칠 수 있는 도구 입력·출력과 파일 diff를 확인하세요. 권한 요청과 질문에 화면 안에서 답할 수 있으며 허용과 거부가 모두 가능합니다. 머리글에는 시작 당시 계정과 실제 적용이 확인된 모델·모드가 표시됩니다. 입력창에는 제공자가 알린 모델·모드만 나타나며 기존 MCP와 권한 설정을 유지합니다.

**Enter** 또는 **보내기**로 전송하고 **Shift+Enter**로 줄바꿈하세요. 한글 조합과 확정 입력은 전송하지 않습니다. **이미지 첨부**에서 여러 파일을 한 번에 선택하거나, 메시지 입력창에 커서를 둔 상태에서 이미지를 붙여넣거나, 첨부할 대화 패널에 파일을 놓으세요. 초안 하나에 최대 8개(PNG, JPEG, GIF, WebP, 각각 20 MiB)를 첨부할 수 있습니다. 텍스트를 붙여넣으면 그대로 입력됩니다. 썸네일로 이미지를 확인하고 각 이미지의 **×** 버튼으로 전송 전에 제거할 수 있습니다. 복원된 첨부가 없거나 잘못되었다면 제거 후 전송하세요. **중지**는 현재 작업을 중단합니다.

Kiln을 닫으면 초안을 저장하고 데몬이 작업 프로세스를 유지합니다. 패널을 닫으면 세션이 끝나며 초안을 버리기 전에 확인합니다. 로컬 전송 대기는 저널 확인 전까지 보관하고 다시 열어도 재전송하지 않습니다. 전송 미확인 시 **초안으로 복구**할 수 있으며 다시 보내기 전에 기록을 확인하세요. 실패·연결 끊김 상태에서도 기록을 유지하고 **같은 대화로 재시작**할 수 있습니다. 이전·최근 메시지 버튼은 기록을 삭제하지 않고 표시 범위만 이동합니다.

승인 카드에는 번역된 제목과 함께 명령·작업 폴더·대상 경로·이유·요청 권한을 표시하고 전송 ID와 스키마는 노출하지 않습니다. 기록 복원이 완료된 뒤에도 저널과 전송함에 없는 이전 요청은 에이전트가 준비 상태여도 직접 초안으로 복구할 수 있으며 자동 재전송하지 않습니다.

Claude 승인 카드에는 업무 식별자를 포함한 실제 MCP·도구 인수를 표시합니다. 긴 입력은 일부만 표시한다고 안내하며 Codex 전송 매개변수와 스키마는 계속 숨깁니다. 초안 복구는 이전 클라이언트의 마지막 전송 기록까지 반영한 관찰값이 확인된 뒤에만 가능합니다.

입력창 위 상태 표시에서 응답 작성·도구 실행·입력 대기·응답 완료를 구분할 수 있습니다. 위쪽 기록을 읽는 동안에도 계속 표시됩니다. Claude가 보고한 셸·Monitor·기타 백그라운드 작업의 설명과 상태, 진행 요약, 제공된 실행 시간을 확인하고 각 작업을 펼쳐 상세 내역을 볼 수 있습니다. 상시 감시 작업은 목록에 유지하되 응답이 계속 작성 중인 것으로 표시하지 않습니다. 다른 AI도 보고된 실행 중 도구를 보여 줍니다. 위로 스크롤하거나 이전 기록을 열면 **↓ 최신 메시지로 이동**으로 초안을 유지하며 최신 내역으로 돌아올 수 있습니다.

셸·Monitor 상세의 **출력 보기 · 새로고침**은 AI에게 새 요청을 보내지 않고 최근 출력을 읽습니다. 출력 일부만 표시되는 경우, 아직 출력이 없는 경우, CLI가 출력을 제공하지 않는 경우를 구분합니다.

### 같은 대화에서 화면 전환하기 {#switch-presentation}

네이티브 터미널 작업 목록에서도 저장된 “Claude Code” 같은 기본 제공자 이름이 실제 대화 제목을 덮어쓰지 않도록 합니다. 직접 지정한 의미 있는 탭·세션 이름은 우선합니다.

유휴 상태의 GUI→TUI 전환 검사에서는 대화에 저장된 환경 변수와 작업 폴더로 MCP 실행 파일을 확인합니다. MCP별 `PATH` 재정의도 반영합니다. MCP 서비스가 연결되어 있다는 사실만으로 AI가 작업 중인 것은 아닙니다.

창 제목과 자동 작업 탭 이름은 처음 전송한 요청을 짧게 표시합니다. 직접 지정한 작업 이름은 유지되며, 초안을 편집해도 기존 대화 제목은 바뀌지 않습니다.

각 에이전트 창 안의 우측 상단, 닫기 버튼 아래에 붙어 있는 **GUI | TUI** 탭으로 전환합니다. 응답 작성자 이름 옆에는 에이전트 아이콘이 표시됩니다. 도구 내역을 펼치면 파일 언어와 셸 명령어에 맞는 구문 강조, 읽기 편한 스크롤 영역과 복사 기능을 사용할 수 있습니다. 언어를 식별하지 못한 출력은 일반 텍스트로 표시합니다.

에이전트 패널의 **GUI | TUI** 탭으로 기존 계정과 작업 폴더를 유지하며 같은 대화를 이어갈 수 있습니다. 새 Claude Code 대화는 첫 메시지를 보내기 전에도 터미널로 열 수 있으며, 아직 없는 기록 파일을 재개하려 하지 않습니다. 작업 중에도 TUI 전환을 요청할 수 있습니다. 현재 작업은 GUI에서 계속 실행되고 응답·승인·대기 작업이 끝나고 소유권 확인을 통과하면 자동으로 전환합니다. GUI를 선택하면 전환 예약을 취소합니다. 실행 중인 모델 요청을 다른 프로세스로 즉시 이동하는 방식은 아닙니다. 네이티브 TUI에서 GUI로 돌아올 때는 GUI 실행 주체를 시작하기 전에 CLI가 정상 종료되어야 하며, TUI를 선택하면 복귀 요청을 취소합니다. 백그라운드 작업이 남아 있거나 프로세스 소유권을 확인할 수 없으면 전환을 거부하고 해당 작업을 계속 실행합니다. 이전 에이전트의 종료가 끝난 뒤에만 터미널을 열며, 전환이 막힌 이유를 안내합니다.

지원되는 Claude Code 모드가 연결되어 있으면 **GUI**를 선택하는 것만으로 입력창이 유휴 상태이고 비어 있을 때 자동 복귀합니다. 실행 중 작업·승인·작성 중인 초안·보고된 셸/Monitor 작업 표시가 있으면 복귀를 보류합니다. **TUI**를 선택하면 예약을 취소합니다. Claude 자체의 정상 종료 기능을 사용하며 종료를 확인한 뒤 같은 대화를 다시 연결합니다. 추가된 사용자·에이전트 텍스트를 가져오고 이미지는 첨부 안내로 표시합니다. 이전 기록이 달라졌다면 보관한 GUI 기록을 유지하고 불일치를 알립니다.

Kiln에 등록된 셸 함수로 실행한 대화형 `claude`, `codex`, `agy` 명령에서도 같은 **GUI | TUI** 탭을 사용할 수 있습니다. Kiln은 해당 터미널에 연결된 실행 중 호스트가 정확히 확인된 뒤에만 패널을 연결합니다. 원래 PTY와 부모 셸, 명령 인수, 선택한 계정 프로필을 유지합니다. Kiln의 zsh 또는 PowerShell 연동이 제공하는 함수에 적용되며, 등록되는 명령은 셸에 따라 다릅니다.

macOS에서는 이미 실행 중인 추적된 Claude 터미널과 이전 GUI 작업자의 네이티브 화면에도 **GUI** 선택 시 호환되는 모드를 연결합니다. 정확한 프로세스·대화·원래 계정 프로필을 확인한 뒤 다시 불러오기를 요청합니다. 작업과 미전송 초안은 정상 복귀할 수 있을 때까지 터미널에 유지합니다. **TUI**를 선택하면 취소 확인을 기다립니다. 네이티브 종료가 이미 확정됐다면 같은 대화를 연결한 뒤 요청한 터미널 화면으로 돌아갑니다.

macOS에서 Kiln의 GUI로 연 Codex 대화는 **GUI**를 선택하면 현재 작업이 끝나고 TUI 입력이 비었을 때 자동으로 돌아옵니다. 작업이나 작성 중인 입력이 있으면 CLI를 유지합니다. 그 밖의 기존 세션, Antigravity, Claude 모드 미지원/비활성화, 사용자 단축키 충돌, 입력 소유권을 확인할 수 없는 이전 Windows 작업자는 **GUI**를 선택한 뒤 CLI를 정상 종료하세요. 해당 CLI가 지원하면 `/exit` 또는 **Ctrl+D**를 사용할 수 있습니다. 안내 문구는 연결 준비·작업 대기·초안·수동 복귀 상태를 구분합니다. 앱 업데이트는 기존 프로세스를 유지하며, 기존 세션 연결은 실행 중인 CLI를 교체하지 않습니다. 처음 연 TUI에서 GUI를 요청하지 않고 종료하면 원래 셸로 돌아갑니다.

관리·출력 전용·원격 명령, 파이프라인, 입력·출력 리다이렉션, Kiln 연동을 거치지 않는 사용자 별칭이나 함수는 기존 네이티브 실행 경로를 유지합니다. Bash와 fish에는 에이전트 래퍼를 자동 등록하지 않습니다. Kiln 밖의 터미널에서 실행한 명령은 자동 추적하지 않습니다.

터미널로 시작한 에이전트는 정확한 네이티브 대화가 추적된 경우에만 GUI로 가져올 수 있습니다. macOS의 호환되는 기존 Claude 터미널은 위와 같이 자동 복귀합니다. 그 외에는 먼저 CLI를 종료하세요. 데몬이 기존 프로세스의 종료를 확인한 뒤에만 기록된 계정 환경과 작업 폴더로 GUI 실행 주체를 시작합니다. 연결이 끊겼거나 대화를 식별하지 못했다는 사실만으로 종료를 판단하지 않습니다.

## 여러 저장소 함께 다루기 {#work-across-several-repositories}

프론트엔드, 백엔드, 공유 라이브러리가 각각 다른 Git 저장소에 있다면 `~/dev/projects` 같은 상위 폴더를 여세요. Kiln은 이 폴더를 에이전트의 작업 루트로 유지하고 찾아낸 저장소 구성을 요청에 함께 넣을 수 있으므로, 요청 하나로 모든 저장소를 다룰 수 있습니다.

Git이나 GitHub 도구에서 저장소를 살펴봐도 작업이 실행되는 디렉터리는 바뀌지 않습니다. Git 작업을 적용할 저장소는 해당 도구의 저장소 선택기에서 고릅니다. [워크스페이스와 작업](workspaces.html)과 [Git과 GitHub](git.html)를 참고하세요.

## 작업 상태 확인하기 {#follow-task-state}

사이드바의 각 작업 행에는 에이전트가 보고한 상태가 표시됩니다.

| 상태 | 의미 |
| --- | --- |
| 작업 중 | 에이전트가 작업하고 있습니다. |
| 입력 대기 | 에이전트가 내 입력을 기다립니다. |
| 완료 | 에이전트가 작업을 마쳤습니다. |
| 실패 | 에이전트가 실패를 보고했습니다. |
| 세션 열림 | 보고된 상태가 없습니다. Kiln은 짐작하지 않고 세션이 열려 있다고만 표시합니다. |

실행 중인 작업이 맨 위에 오고, 입력을 기다리는 요청, 이전에 실패한 작업 순으로 이어집니다. 작업을 클릭하면 해당 워크스페이스, 탭, 분할 화면으로 이동하며, 확대 때문에 가려진 패널도 다시 보입니다.

### Kiln이 상태를 파악하는 방법 {#how-kiln-knows-the-state}

Kiln이 상태를 정확히 표시하려면 에이전트가 상태를 보고하거나 Kiln이 인식하는 실행 중 제목을 띄워야 합니다.

- Kiln은 Claude Code와 Codex의 터미널 제목에 나오는 활동 표시를 인식하므로, 따로 설정하지 않아도 실행 중 활동이 표시됩니다.
- Claude Code의 `✳` 표시는 대화상자가 열려 있을 때도 나타나므로 완료로 보지 않습니다.
- 명시적인 대기·실패 신호가 있으면 제목 표시보다 우선합니다.
- 유휴 상태의 터미널을 완료된 작업으로 보는 일은 없으며, 끝나지 않은 실행 명령 때문에 유휴 에이전트가 실행 중으로 표시되지도 않습니다.

스크립트나 다른 도구는 `kiln activity running`, `waiting`, `done`, `failed`로 상태를 보고할 수 있습니다. 활동 보고와 알림은 [터미널](terminal.html)을 참고하세요.

### 표시 색상 {#indicator-colors}

| 에이전트 | 표시 |
| --- | --- |
| Claude Code | 주황색 |
| Codex | 파란색 |
| Antigravity | 탭, 작업 목록, 사이드바에 Antigravity 마크 |
| 식별되지 않은 세션 | 중립색 |

표시는 사이드바, 탭, 패널 헤더에 나타납니다. 분할된 탭에서 상태의 우선순위가 같으면 포커스된 패널의 상태를 따릅니다. 경고는 언제나 우선합니다.

## 알림과 사용량 한도 {#notifications-and-usage-limits}

알림 센터는 최근 알림을 보관하고 각 알림을 해당 세션과 연결해 둡니다. 알림을 읽으면 그 세션의 확인 필요 상태가 풀립니다. Windows에서는 에이전트 알림이 Windows 토스트로 뜹니다.

Antigravity가 할당량에 도달했다고 보고하면 Kiln은 초기화 시각과 함께 사용량 한도 알림을 띄웁니다. Claude Code와 Codex 패널은 처음 열 때 쓴 계정을 계속 씁니다. 계정이 사용량 한도에 도달하면 **설정 → 계정**에서 다른 계정으로 전환하고 새 패널을 여세요. [계정](accounts.html#choose-which-account-to-use)을 참고하세요.

## Codex 용량 초과 복구 {#codex-capacity-recovery}

Kiln이 열려 있는 동안, Kiln이 관리하는 Codex 패널은 서버 과부하로 Codex가 중단한 턴을 다시 시도합니다. 재시도는 이 Codex 오류에서만 시작되며, 사용량 한도, 로그인 실패, 스트림 오류, 취소된 턴, 성공한 턴에는 관여하지 않습니다.

- 재시도 간격은 15, 30, 60, 120, 240초입니다. 패널에는 카운트다운과 **자동 재시도 취소** 버튼이 표시됩니다.
- 실패한 뒤 패널에 입력하면 대기 중인 재시도가 취소됩니다. 프롬프트를 일부만 입력해도 마찬가지입니다.
- 직접 새 요청을 보내면 재시도가 처음부터 다시 시작됩니다.
- 재시도할 때도 같은 계정과 모델을 씁니다.

Codex CLI가 아직 열려 있으면 Kiln은 같은 대화에 이어 가기 프롬프트를 한 번 보냅니다. CLI가 이미 종료되었다면 원래 계정과 작업 디렉터리로 같은 대화를 재개한 뒤 프롬프트를 보냅니다. 이 프롬프트는 이미 끝낸 동작을 반복하기 전에 현재 상태부터 확인하라고 Codex에 요청합니다. 원래 요청을 다시 보내지 않으며, 실패한 턴에서 생긴 변경도 되돌리지 않습니다.

재시도는 저장된 계정으로 연 Codex 패널 가운데 Kiln이 대화를 확인한 패널에만 적용됩니다. Kiln이 실행 중인 CLI를 지켜보기 전에 일어난 실패는 직접 처리해야 합니다.

## Codex 백그라운드 서버 설정 {#codex-background-server-settings}

Kiln이 여는 새 Codex 패널은 `--no-daemon`으로 실행되므로 Codex 자체의 공유 백그라운드 서버와 별개로 동작합니다. Codex 세션에 **Background server has incompatible feature settings**가 표시되면, 그 세션의 기능 플래그가 서버에 저장된 값과 다르다는 뜻입니다. 이때는 다음 중 하나를 고를 수 있습니다.

| 옵션 | 효과 |
| --- | --- |
| **Run without daemon this time** | 공유 Codex 서버를 재시작하지 않고 이 세션을 시작합니다. CLI의 `codex --no-daemon`과 같습니다. |
| **Restart with these settings** | 공유 설정을 바꿉니다. 다른 클라이언트에서 진행 중이거나 대기 중인 작업이 중단될 수 있으니 먼저 확인하세요. |

새로 연 Kiln Zsh 터미널에서 직접 입력하는 `codex`, `codex resume …`, `codex fork …`에도 `--no-daemon`이 적용됩니다. 따라서 공유 서버가 **Server is draining; retry after reconnecting**을 반환해도 이 명령들은 독립적으로 시작합니다. 명시적인 `--remote` 연결, 기존 별칭·함수, 그 밖의 명령 형식과 다른 셸은 기존 방식대로 동작합니다. 래퍼를 건너뛰려면 `command codex …`를 사용하고, 로컬 세션을 직접 실행할 때는 `--no-daemon`을 붙이세요. 기존 셸은 다시 열어야 적용됩니다. Kiln은 공유 서버를 재시작하거나 업데이트 설정을 바꾸지 않습니다.

## 네이티브 대화 설정과 명령 {#native-session-settings}

응답 처리 중에도 보내기 버튼이나 Enter로 후속 메시지를 보낼 수 있으며, 중지 버튼은 별도로 유지됩니다. Claude는 스트리밍 후속 입력을 받고 Codex는 현재 턴에 입력을 추가합니다. Codex에서는 대화 설정 변경의 확인을 기다리는 동안에도 확인된 현재 작업에 후속 메시지를 보낼 수 있습니다. Antigravity는 현재 요청이 끝날 때까지 후속 메시지 하나를 보관합니다. 전송 확인 대기와 수신 완료를 구분하며 자동으로 다시 보내지 않습니다.

응답 처리 중에도 모델·추론 강도·모드를 선택할 수 있습니다. Claude는 네이티브 적용 시점에 변경하고, Codex 입력창의 선택은 다음 턴에 적용합니다. Codex의 명시적인 현재 턴 설정 작업은 지원되는 설정을 현재 턴에 적용합니다. 설정은 네이티브 확인을 기다립니다. 워크스페이스 내역은 제공자 이름 대신 대화 제목을 표시하며 사용자가 지정한 페이지 제목을 유지합니다.

대화 GUI의 **대화 설정**에서 공급자별 설정을 검색하고 **명령 및 스킬**에서 네이티브 명령을 찾으세요. 두 줄 입력창 아래 한 줄 도구 모음에서 이미지를 첨부하고 모델·모드를 고르며 **사고 설정**을 열거나 원형 보내기·중지 버튼을 사용할 수 있습니다. 좁은 패널에는 모델과 **대화 옵션**을 표시하고 나머지 설정은 대화 옵션에 담습니다. 모델 이름은 읽기 쉽게, 모드·추론 강도는 앱 언어로 표시하되 공급자에게 전달하는 값은 유지합니다. 아직 받지 못한 목록과 빈 목록도 구분합니다.

사고 설정이나 좁은 패널의 대화 옵션에서 각 단계의 설명을 읽고 추론 강도를 선택할 수 있습니다. Claude의 Ultracode는 독립된 스위치이며, 켜지면 보라색으로 표시합니다. 헤더는 적용이 확인된 모델과 모드를 보여 줍니다.

Claude Code, Codex, Antigravity의 설정과 기본 선택지는 앱 언어로 이름과 동작 설명을 함께 표시합니다. 한국어에서는 승인 정책도 ‘필요할 때 승인 요청’처럼 표시합니다. 새 대화 설정, 현재 턴 설정, 샌드박스와 세부 승인 항목에도 같은 기준을 적용합니다. 제공자나 사용자가 정한 고유 이름과 실제 전송 값은 유지됩니다.

모델 비교는 현재 모델을 먼저 보여 주고, 모델 이름·특징·기본 추론 강도·지원 입력을 카드로 정리합니다. ‘이 모델 사용’으로 바로 선택할 수 있으며, 선택 결과는 제공자 확인 후 적용됩니다. 상세 정보에서 지원 단계와 제공자 설명 원문을 확인할 수 있습니다.

네이티브 UI에 예시 목록을 넣어 렌더링한 화면입니다. 실제 계정의 모델 응답이 아닙니다.

설정을 변경하면 요청값과 네이티브 값을 따로 표시합니다. 네이티브 확인을 기다리는 동안 전송과 충돌하는 설정 변경을 막고 중지는 계속 사용할 수 있습니다. 전송 수락만으로 설정 적용을 확정하지 않습니다. 거부되거나 미확인된 변경은 표시하며 자동 재시도하지 않습니다.

명령 및 스킬에는 검색 아이콘, 검색 초기화와 높이가 제한된 스크롤 목록이 있습니다. 이름을 왼쪽에 정렬하며 행을 펼치면 전체 설명과 세부 정보를 읽을 수 있습니다. 이름·설명·별칭을 검색하고, GUI에서 실행할 수 없는 터미널 전용 항목과 스킬은 숨깁니다. 항목을 선택하면 기존 내용과 이미지를 유지한 채 편집 가능한 초안에만 삽입합니다. Codex 스킬의 네이티브 입력도 명시적으로 보낼 때까지 보관합니다.

`/`를 입력하면 짧은 설명이 있는 자동완성 목록이 열립니다. Codex 스킬은 `$`로도 완성할 수 있습니다. 위·아래 방향키로 고르고 Tab이나 Enter로 삽입하며 Esc로 닫습니다. 자동완성으로 메시지가 전송되지는 않습니다. 인식된 명령·스킬은 일반 문장과 구분해 표시합니다. 네이티브 스킬이 바뀌면 목록을 새로 고치세요.

대화 설정에는 GUI에서 실제로 바꿀 수 있는 항목을 응답·작업 방식·컨텍스트·권한별로 묶어 표시합니다. 읽기 전용 목록과 사용할 수 없는 설정은 노출하지 않습니다. 변경 기록·기본값 복원·참고 정보는 세부 정보에서 확인합니다. CLI 화면이 필요하면 **새 작업**에서 별도 터미널을 여세요.

**새 대화 설정**은 현재 선택한 계정과 지정한 시작 옵션으로 별도 대화를 엽니다. 현재 세션과 초안은 유지되며 프롬프트를 재실행하지 않습니다. 검토·목표·대기 작업 같은 네이티브 작업은 명시적인 실행 버튼으로만 시작합니다. 현재 턴 설정은 확인된 실행 중 턴의 이후 작업에 적용되며 이미 시작한 작업을 바꾸지 않습니다.

질문과 알려진 MCP 작업을 포함한 도구 제목은 앱 언어를 따릅니다. 카드를 펼치거나 제목에 마우스를 올리면 원래 도구 이름을 확인할 수 있으며 인수·출력·질문·변경 내용은 원문을 유지합니다. 언어 변경은 이전 기록의 제목에도 반영됩니다. 알 수 없는 작업은 외부 도구로 표시합니다. 확장 준비나 이전 캐시 보존 상태는 네이티브 로드 완료를 뜻하지 않습니다.

메시지에서 `@`를 입력하면 현재 작업 폴더의 파일과 폴더를 검색합니다. 방향키로 고르고 Tab으로 폴더를 탐색하며 Enter로 삽입하고 Esc로 닫습니다. 공백이나 한글이 있는 경로도 따옴표로 보존합니다. 선택은 초안만 바꾸며 전송은 별도 동작입니다. Claude에는 네이티브 `@` 참조 형식, Codex에는 정식 TUI와 같은 경로 텍스트, Antigravity에는 선택한 전체 경로를 전달합니다. 공급자의 권한과 컨텍스트 처리 규칙은 그대로 적용됩니다.

### 다음 입력 추천 {#prompt-suggestions}

Claude Code가 다음 입력을 추천하면 GUI의 빈 메시지 입력창에 흐린 글씨로 표시됩니다. **Tab**으로 초안에 채우고 **Enter**나 보내기로 전송합니다. **Esc**로 해당 추천을 숨깁니다. 직접 입력한 내용·첨부·한글 등 입력기 조합이 우선합니다. 추천은 Claude의 설정과 제공 여부를 따르며 모든 응답 뒤에 표시되지는 않습니다. Kiln이 임의로 추천 문구를 만들지 않습니다.

## 제공자별 기능 범위 {#provider-coverage}

이 제어 기능을 구현할 때 확인한 기준 버전은 Claude Code 2.1.325(SDK 0.3.325), Codex CLI 0.167.2, Antigravity CLI 1.5.9입니다. 최소 요구 버전이나 이후 모든 버전의 동일한 동작을 보장하는 목록이 아닙니다. 설치된 CLI, 모델, 계정과 조직 정책에 따라 사용 가능 여부가 결정됩니다. 제어 항목이 보이거나 확장이 준비되었다는 사실만으로 로그인한 계정의 모델 작업이 성공했다고 판단하지 않습니다.

**대화 설정**에는 실제로 변경할 수 있는 GUI 설정만 표시합니다. 네이티브 설정·메서드 참고 목록의 모든 항목을 설정 화면에 노출하지 않습니다. 개발 중인 플러그인 API는 호출하지 않습니다. 이 어댑터는 Antigravity MCP 연결 상태를 보고하지 않으며, 빈 클라이언트 서버 목록도 연결 상태 결과가 아닙니다.

권한 카드에는 네이티브가 제공한 선택지를 유지합니다. Codex에서는 요청된 파일 시스템·네트워크 권한의 일부를 골라 턴·세션 범위와 엄격한 검토 여부를 정할 수 있습니다. Kiln이 권한 우회 정책을 자동 선택하지 않습니다. 네이티브 정책·이용 자격·기능 오류는 그대로 표시됩니다. 현재 턴 변경은 보고된 실행 턴의 설정에 적용되며 제공자가 이미 처리에 사용한 추론까지 바꾸지는 않습니다. 실행 효과의 확인값이 없는 설정 접수는 실제 적용 확인과 구분해 표시합니다.

네이티브 [Claude 모델 참고 문서](https://code.claude.com/docs/en/model-config.md), [Codex App Server 참고 문서](https://learn.chatgpt.com/docs/app-server), [ACP 설정 규약](https://agentclientprotocol.com/protocol/v1/session-config-options)을 참고하세요. 계정과 모델마다 목록이 달라지며, 사용 불가·일부 결과를 전체 목록으로 보지 마세요.

## 개인 확장과 계정 범위 {#personal-extensions}

새 실행은 지원되는 개인 Claude·Codex 스킬과 자체 완결된 플러그인 자산을 선택한 비공개 프로필에 준비합니다. Claude는 이식 가능한 이전 명령·에이전트·응답 스타일·워크플로 묶음도 지원합니다. 프로젝트 우선순위는 네이티브 규칙을 따르며, 공유 Codex HOME 스킬과 Antigravity 자산은 네이티브에서 관리합니다. 기존 계정 로그인·초기 설정 동작은 유지됩니다. 원본 작성 파일은 변경하지 않으며, 이후 가져오기에서도 비공개 프로필의 편집·삭제를 보존합니다. 상태 조회와 작업 프로세스 재개는 이 항목들을 새로 가져오지 않습니다.

**확장 준비됨**은 가져오기 준비 성공을, **기존 확장 보존됨**은 이전 캐시 버전이 사용 중인 프로세스를 위해 남았음을 뜻합니다. 활성화·로드·실행 성공을 뜻하지 않으며 네이티브 발견·실행 결과는 별도로 확인해야 합니다. 지원되는 이식 가능한 플러그인 선언은 준비 중 실행하지 않고 묶음의 hooks·MCP·LSP 설정을 보존할 수 있습니다. 인증 정보가 든 설정, 계정 연결형 커넥터, 미지원 형식, 외부 경로, 루틴·스케줄러 상태는 네이티브 설정이 필요하거나 진단이 표시됩니다. 전체 설정이나 계정 기록을 복사하지 않습니다. [네이티브 플러그인 로드](https://code.claude.com/docs/en/plugins/loading.md)를 참고하세요.

터미널에는 건너뛴 확장마다 오류를 출력하는 대신 요약 한 줄을 표시합니다. 개별 사유는 실행 전에 `KILN_EXTENSION_DIAGNOSTICS=1`을 설정하면 확인할 수 있습니다.
