Kiln의 모든 작업은 로컬 데몬이 소유한 실제 터미널 세션에서 실행됩니다. 여기에 셸 통합이 명령 추적, 활동 보고, 자동 완성을 더하며, 창을 닫아도 세션은 계속 실행됩니다.

## 셸 통합 {#shell-integration}

새로 여는 기본 zsh 세션에는 셸 통합이 자동으로 적용됩니다. 셸 통합은 명령의 시작과 끝, 작업 디렉터리를 추적하며 `.zshrc`는 수정하지 않습니다.

인수를 붙인 사용자 지정 실행이나 bash, fish에는 자동 통합이 적용되지 않습니다. 이미 열려 있던 셸에 새 통합 동작을 적용하려면 새 세션을 열어야 할 수 있습니다. 통합을 끄려면 `KILN_SHELL_INTEGRATION=0`을 설정하세요.

### 기존 zsh 세션 연결하기 {#attach-an-existing-zsh-session}

1. 설정에서 기본 셸을 `/bin/zsh`로 지정하고 새 Kiln 터미널을 엽니다. 이때 통합 파일이 만들어집니다.
2. 기존 zsh에서 포그라운드 작업이 끝나기를 기다렸다가, 아무것도 실행 중이지 않은 프롬프트에서 다음 명령을 실행합니다.

```zsh
source ~/.local/share/kiln/shell-integration-v1/integration.zsh
```

기존 터미널 안에서 `zsh`를 실행하는 것만으로는 Kiln의 새 세션 설정이 적용되지 않습니다.

## 활동과 알림 {#activity-and-notifications}

Kiln은 터미널 알림(OSC 이스케이프 시퀀스)과 명시적인 활동 보고를 읽습니다. 둘 다 로컬 터미널 이스케이프 시퀀스이므로 프롬프트가 다른 서비스로 전송되지 않습니다.

스크립트나 에이전트 훅에서는 `kiln activity`로 활동을 보고합니다.

```sh
kiln activity running
kiln activity waiting
kiln activity done
kiln activity failed
```

알림은 `kiln notify`로 보냅니다. 설치된 버전의 문법은 `kiln activity --help`와 `kiln notify --help`로 확인하세요. 셸 통합은 `kiln-agent-status running|waiting|done|failed|unknown` 함수도 제공합니다. 훅의 출력이 Kiln 터미널까지 전달되어야 Kiln이 활동을 받을 수 있습니다.

Kiln은 Claude Code와 Codex가 터미널 제목에 넣는 활동 표시도 인식하므로, 훅이 없어도 실행 중 활동이 표시됩니다. 명시적인 대기·실패 보고가 있으면 그쪽이 우선합니다. 아무것도 보고하지 않는 일반 셸과 에이전트는 완료로 표시되지 않고 열린 세션으로 나타납니다. 표시와 색상은 [에이전트](agents.html)를 참고하세요.

알림 센터는 최근 알림을 보관하고 각 알림을 해당 세션과 연결해 둡니다. 알림을 읽으면 그 세션의 확인 필요 상태가 풀립니다.

## 명령 기록 {#command-history}

데몬은 최근 명령을 메모리에 보관하므로, 실행한 명령과 출력을 다시 살펴볼 수 있습니다.

| 한도 | 값 |
| --- | --- |
| 보관하는 명령 수 | 최근 40개 |
| 명령당 보관하는 출력 | 앞부분 128 KiB |
| 데몬을 재시작하거나 업그레이드한 뒤에도 유지 | 아니요 |

기록은 각 명령의 출력을 재구성한 텍스트입니다. 원시 터미널 로그가 아니며, 전체 화면 TUI의 중간 화면을 모두 담지도 않습니다. 명령 경계를 추적하는 통합이 없으면 지금 화면에 보이는 출력만 볼 수 있습니다.

기록에서 명령을 편집하면, 명시적으로 실행을 선택해야만 실행되며 새 터미널에서 실행됩니다.

## 셸 자동 완성 {#shell-completion}

셸 통합이 적용된 새 zsh 터미널에서는 입력할 때 커서 옆에 추천 메뉴가 자동으로 나타나고 커서를 따라 움직입니다. 명령, 하위 명령, 옵션과 지원되는 로컬 인수를 추천합니다.

| 키 | 동작 |
| --- | --- |
| `Tab` | 강조된 추천 항목 삽입 |
| `Down` | 메뉴를 선택한 뒤 화살표 키로 추천 항목 이동 |
| `Enter` | 메뉴를 선택한 상태면 삽입, 그 전에는 입력한 명령 실행 |
| `Esc` | 메뉴 닫기 |
| `Ctrl+Space` | 메뉴를 열거나 다시 열어 선택, 또는 설치된 명령 이름 찾기 |

추천 항목을 삽입하면 명령줄만 바뀝니다. 실행하려면 `Enter`를 한 번 더 누릅니다. 자동으로 나타난 메뉴를 선택하기 전에 `Enter`를 누르면 원래 입력한 명령을 실행합니다. 메뉴가 닫혀 있을 때는 zsh 자체의 `Tab` 자동 완성이 평소처럼 동작합니다.

입력한 명령과 인수에 따라 다음 항목을 추천합니다.

- `cd`는 터미널의 현재 디렉터리를 기준으로 폴더를 추천합니다. 폴더를 선택한 뒤 다음 하위 경로를 이어서 완성할 수 있습니다.
- 파일 인수에는 로컬 경로를 추천합니다. `docker --config`와 `docker compose --project-directory`는 폴더를, `docker compose --file`은 파일을 추천합니다.
- Git 명령에는 현재 저장소의 로컬 브랜치를 추천할 수 있습니다.
- `npm run`, `pnpm run`, `yarn run`, `bun run`에는 프로젝트의 `package.json`에 정의된 스크립트 이름을 추천합니다.

Kiln은 설치된 CLI의 로컬 도움말에서 명령, 하위 명령, 옵션 정보를 자동으로 읽고 결과를 캐시합니다. 오프라인에서도 쓸 수 있는 내장 추천 목록에는 Docker Engine, Buildx, Compose도 포함됩니다. 도움말을 해석하거나 불러올 수 없으면 해당 명령에 사용 가능한 로컬 또는 내장 추천을 사용합니다.

도움말 요청은 입력한 인수 값을 전달하지 않고 분리된 임시 환경에서 실행합니다. 자동 완성은 AI를 사용하거나 셸 기록 파일을 읽지 않으며, 자동 완성 데이터를 클라우드 서비스로 보내지 않습니다.

자동 추천을 숨기려면 **설정 → 터미널**에서 **명령어 입력 힌트**를 끄세요. 그래도 `Ctrl+Space`는 계속 동작합니다. 셸이 미리보기 데이터도 만들지 않게 하려면 셸에서 `KILN_COMPLETION_PREVIEW=0`을 설정하세요.

자동 완성은 zsh에서만 동작합니다. 갱신된 통합을 불러오려면 새 터미널을 여세요. 기존 터미널은 현재 셸 설정을 유지합니다. Bash, fish, SSH 세션, 에이전트 채팅, 전체 화면 애플리케이션, 그 밖의 셸에서는 원래 입력 방식이 그대로 유지됩니다. 통합 관련 도움말은 터미널의 컨텍스트 메뉴에 있습니다.

## 연결 복구 {#connection-recovery}

Kiln은 터미널 연결과 그 안에서 실행 중인 셸이나 에이전트를 분리해서 관리합니다. 패널의 연결이 끊기거나 응답이 멈추면 Kiln은 연결을 복구하고, 화면을 다시 그리고, CLI에도 다시 그리기를 요청합니다. 에이전트를 재시작하거나, 프롬프트를 보내거나, `/resume`을 대신 실행하지는 않습니다.

| 패널 표시 | 의미 |
| --- | --- |
| **연결 복구 중** | Kiln이 연결을 복구하고 있습니다. 최대 세 번 시도합니다. |
| **연결 멈춤** | 시도가 모두 실패했습니다. **연결 다시 복구**를 선택해 다시 시도하세요. |

**연결 다시 복구**는 실행 중인 모든 터미널 패널의 **…** 메뉴에 있으며, 연결이 정상으로 보일 때도 쓸 수 있습니다. 이 메뉴를 선택하면 그 패널의 재시도 횟수가 초기화됩니다. 생각 중이거나 입력을 기다리느라 조용한 에이전트는 멈춘 것으로 보지 않습니다.

복구하는 동안에도 세션과 프로세스는 계속 실행되고, 기존 텍스트는 화면에 남아 있습니다. 입력은 잠시 멈추므로, 끊어진 연결 뒤로 입력이 쌓이지 않습니다.

> **참고:** 연결은 정상인데 CLI 내부가 멈출 수도 있습니다. 이때는 **연결 다시 복구**로 해결되지 않습니다. 다른 패널을 열고 CLI 자체의 재개 기능을 사용하세요.

## 창을 닫아도 유지되는 세션 {#sessions-that-outlive-the-window}

터미널은 창이 아니라 세션 데몬에 속합니다. Kiln을 닫아도 셸과 에이전트는 계속 실행되고, 다시 열면 그 세션으로 돌아옵니다. 업데이트할 때도 실행 중인 터미널은 유지됩니다. 시스템을 재부팅하거나 데몬을 명시적으로 중지하면 세션이 종료될 수 있습니다.

- **macOS:** 메뉴 막대 아이콘을 누르면 **설정…**과 **백그라운드 세션 종료…**가 있는 메뉴가 열립니다. 백그라운드 세션을 종료하려고 하면 실행 중인 세션 목록과 함께 확인 창이 뜨며, 기본 선택은 **취소**입니다. 열려 있는 워크스페이스의 세션도 함께 종료되므로, 저장하지 않은 셸이나 에이전트 작업을 잃을 수 있습니다.
- **Windows:** 알림 영역 아이콘에는 세션 요약이 표시되고, 확인이 필요한 항목이나 읽지 않은 알림이 있으면 빨간 점이 붙습니다. 메뉴에는 **Kiln 열기**, **설정**, **백그라운드 세션 종료…**가 있습니다.

> **주의:** `kiln status`는 세션 데몬의 상태를 보여 줍니다. 창을 새로 고치려고 `shutdown-daemon`을 실행하지 마세요. 세션이 종료됩니다.

## macOS의 로컬 네트워크 접근 {#local-network-access-on-macos}

macOS 15 이상에서는 로컬 네트워크에 연결하려면 권한이 필요합니다. 그래서 서버가 로컬 네트워크에 있으면 `kubectl get nodes`, SSH, 데이터베이스 연결, 원격 파일 같은 터미널 명령이 영향을 받을 수 있습니다.

1. **Kiln → 설정 → 동작**을 엽니다.
2. **개인정보 보호 → 로컬 네트워크**에서 **접근 요청**을 선택합니다.
3. macOS가 확인 창을 띄우면 Kiln을 허용하고 명령을 다시 실행합니다.

톱니바퀴 버튼을 누르면 **시스템 설정 → 개인정보 보호 및 보안**이 열리고, **로컬 네트워크** 항목에서 Kiln을 확인할 수 있습니다. Kiln은 시스템에서 내린 결정을 읽거나 바꿀 수 없으며, 이미 허용 여부를 정했다면 macOS가 확인 창을 다시 띄우지 않을 수 있습니다.

> **팁:** 업데이트 전에 연 패널은 이전 프로세스 설정을 그대로 씁니다. 그 패널에서 로컬 네트워크 명령이 실패하면 새 터미널 패널을 열고 다시 실행하세요.

## Windows 셸 {#windows-shells}

터미널은 PowerShell 7이 설치되어 있으면 PowerShell 7로, 없으면 Windows PowerShell로 시작합니다. **설정 → 터미널**에서 `cmd.exe`, Git Bash, WSL 배포판을 고를 수 있습니다.

- PowerShell과 cmd는 명령, 종료 코드, 현재 위치를 Kiln에 보고합니다. 사용자 지정 프롬프트에서도 마지막 명령의 상태를 그대로 받을 수 있습니다.
- PowerShell에서는 PSReadLine의 자동 완성(`Tab`, `Ctrl+Space`)을 그대로 씁니다. Kiln의 자동 완성 메뉴는 zsh 전용입니다.
- 터미널을 닫으면 그 안의 콘솔 프로그램이 종료됩니다. 터미널에서 띄운 브라우저 같은 창 애플리케이션은 계속 실행됩니다.
- 패널 이름은 셸에서 실행 중인 가장 최근 콘솔 프로그램의 이름을 따릅니다. Git Bash에서 시작한 프로그램은 추적하지 않습니다.
- 터미널과 편집기에서 한국어 IME 입력을 쓸 수 있습니다.
