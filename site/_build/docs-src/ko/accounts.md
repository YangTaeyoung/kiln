Kiln은 사용하는 에이전트 계정마다 프로필을 따로 저장하므로, 로그아웃하지 않고도 개인 구독과 회사 구독을 오갈 수 있습니다. **설정 → 계정**에서 Claude Code·Codex 구독 계정과, macOS에서는 Antigravity Google 계정까지 관리합니다.

먼저 에이전트마다 공식 CLI를 설치하세요. Kiln은 그 CLI를 통해 로그인하며, 자체 OAuth 제공자를 구현하거나 제공자의 계정 정책을 우회하지 않습니다.

## 계정 추가하기 {#add-an-account}

1. 에이전트 카드에서 **새 계정 추가**를 선택합니다.
2. **개인**이나 **회사**처럼 프로필 이름을 정합니다.
3. **브라우저에서 로그인**을 선택하고 브라우저에서 인증을 마칩니다.

Kiln은 백그라운드에서 기다리다가 CLI가 로그인 성공을 알리면 바로 프로필을 저장합니다. 터미널을 열거나 로그인 명령을 실행할 필요는 없습니다. 계정 설정을 열어 두면 진행 상황을 보거나, 로그인 페이지를 다시 열거나, 취소할 수 있습니다. 로그인 시도는 5분이 지나면 만료됩니다.

브라우저 콜백을 쓸 수 없으면 Claude Code가 대신 로그인 코드를 보여 줄 수 있습니다. 이때 Kiln에 가려진 입력란이 나타나며, 여기에 코드를 붙여 넣으면 됩니다.

> **주의:** 이 입력란에는 로그인 코드만 붙여 넣으세요. 비밀번호나 API 키는 절대 입력하지 마세요.

공식 CLI로 이미 로그인해 두었다면 **현재 로그인한 계정 저장**을 선택해 그 로그인을 프로필로 가져오세요.

## 사용할 계정 고르기 {#choose-which-account-to-use}

로그인하면 프로필만 저장되고, 기존 CLI 세션이 쓰는 계정은 그대로입니다.

- 새로 로그인한 프로필 옆의 **적용**을 선택하면 새 세션부터 그 프로필을 씁니다.
- 기존 프로필에서 **전환**을 선택하면 그 프로필이 활성 프로필이 됩니다.
- 프로필 이름은 해당 행의 메뉴에서 바꿉니다.

저장된 계정마다 Kiln이 여는 패널용 설정을 따로 두므로, 모든 계정이 동시에 로그인 상태를 유지합니다. 실행 중인 에이전트 세션은 시작할 때의 계정을 계속 씁니다. 전환한 계정을 쓰려면 새 에이전트 패널을 여세요. 일반 셸에서 직접 실행한 CLI는 그 셸의 설정을 계속 쓰며, Kiln은 이 CLI를 재시작하거나 자격 증명을 바꾸지 않습니다.

실행 중인 패널이 사용량 한도에 도달해도 Kiln이 다른 계정으로 바꿔 주지는 않습니다. 이 화면에서 다른 계정을 고르고 새 패널을 여세요.

## 다시 로그인하기 {#sign-in-again}

프로필의 로그인을 복구해야 할 때 씁니다. 프로필을 지우고 다시 만들 필요 없이 그대로 유지됩니다.

1. 계정 행의 메뉴를 열고 **다시 로그인**을 선택합니다.
2. 표시된 계정 이름과 이메일을 확인한 뒤 **브라우저에서 로그인**을 선택합니다.
3. 같은 계정으로 로그인하고, 완료되면 **적용**을 선택합니다.

프로필 이름, 목록에서의 위치, 대화 기록은 그대로 유지되고, 실행 중인 터미널도 재시작되지 않습니다. 브라우저에서 다른 계정을 고르면 로그인 시도가 거부됩니다. 시도를 취소하거나 시도가 실패해도 프로필은 그대로입니다.

새 자격 증명은 **적용**을 선택해야 반영되므로, 브라우저 로그인이 세션에서 쓰는 로그인을 모르는 사이에 바꾸는 일은 없습니다. 실행 중인 CLI가 이전 로그인을 캐시해 두었다면, 새 로그인을 적용한 뒤 그 CLI를 재개해야 할 수 있습니다.

### 로그인 필요 {#sign-in-required}

로컬 자격 증명 저장소에서 프로필의 자격 증명이 사라졌다고 확인되면 해당 행에 **로그인 필요**와 **다시 로그인** 버튼이 표시됩니다. Kiln은 계정 설정이 열려 있는 동안과 새로 고침할 때 백그라운드에서 이를 확인합니다.

이 확인은 로컬에서만 이루어지므로, 계정이 온라인에서도 유효하다는 보장은 아닙니다. 토큰은 CLI가 스스로 갱신하므로, 네트워크 오류나 만료된 액세스 토큰은 로그아웃으로 보지 않습니다. 로컬 자격 증명은 남아 있는데 제공자가 로그인을 거부한다면 행 메뉴에서 **다시 로그인**을 사용하세요.

## 사용량 업데이트 {#usage-updates}

Kiln은 앱이 시작될 때, 그리고 그 뒤로 5분마다 저장된 모든 Claude Code·Codex 계정의 사용량을 백그라운드에서 확인합니다. 비활성 프로필도 포함됩니다. Kiln을 열어 두기만 하면 되고, 계정 설정 화면을 띄워 둘 필요는 없습니다.

- 각 카드에는 마지막으로 확인에 성공한 시각이 표시되며, 확인에 실패하면 마지막으로 받은 막대가 그대로 남습니다.
- 새로 고침 버튼을 누르면 제공자의 요청 한도 안에서 다시 확인합니다.
- Codex 사용량 구간에는 보고된 길이가 5시간이나 7일과 일치할 때만 이름이 붙습니다.

이 확인은 읽기 전용입니다. Kiln은 모델 프롬프트를 보내지 않고 초기화 크레딧도 쓰지 않습니다.

| 상황 | Kiln의 동작 |
| --- | --- |
| 제공자의 요청 한도 제한 | 제공자가 요청한 시간(1분~1일)만큼, 따로 알려 주지 않으면 5분 동안 기다립니다. 직접 확인할 때도 이만큼 늦어집니다. |
| 자격 증명 거부(401) | 해당 자격 증명의 확인을 1시간 동안 멈춥니다. 새로 갱신된 토큰은 기다리지 않고 확인할 수 있습니다. |
| 그 밖의 실패 | 다음 주기에 다시 시도합니다. 직접 다시 시도할 수도 있습니다. |
| 인식할 수 없는 응답 | 값을 지어내지 않고 사용량을 확인할 수 없다고 표시합니다. |

토큰이 만료되거나 취소되면, 실행 중인 CLI는 여전히 잘 동작하는데 사용량 확인만 막힐 수 있습니다. 실패가 계속되면 해당 프로필 메뉴에서 **다시 로그인**을 선택하세요.

## Antigravity 계정 {#antigravity-accounts}

> **참고:** Antigravity 계정은 Kiln 0.2.12에서 새로 추가되었으며 macOS에서만 쓸 수 있습니다. Windows에서는 터미널에서 `agy`를 실행해 로그인하세요.

Antigravity CLI(`agy`)용 Google 계정을 여러 개 저장해 두고, 새 작업에 쓸 계정을 고를 수 있습니다.

1. **설정 → 계정 → Antigravity**를 열고 **새 계정 추가**를 선택합니다. Kiln이 임시 비공개 터미널에서, 설치된 CLI의 Google 로그인을 시작합니다.
2. 브라우저에서 로그인을 마친 뒤 **적용**을 선택합니다.
3. 다른 계정도 같은 방법으로 추가하고, 새 작업에서 그 계정을 쓰려면 **전환**을 선택합니다.

실행 중인 작업은 원래 계정을 계속 씁니다. 행 메뉴에서 이름 변경, 삭제, 같은 Google 계정으로 다시 로그인을 할 수 있습니다. **현재 로그인한 계정 저장**을 선택하면 일반 CLI의 Google 로그인을 가져옵니다.

계정마다 비공개 홈과 macOS 키체인이 따로 있으므로, Antigravity 환경설정, 설정, 대화도 계정별로 분리됩니다. Kiln은 일반 CLI의 로그인을 바꾸거나 기본 키체인을 변경하지 않습니다. 계정 홈에는 셸, Git, SSH 설정처럼 평소 홈 디렉터리에 있는 파일이 들어 있지 않습니다. 워크스페이스 파일은 그대로 쓸 수 있습니다.

Antigravity 계정에는 사용량 막대가 표시되지 않고, 자동으로 전환되지도 않습니다. `agy`가 할당량에 도달했다고 보고하면 Kiln이 초기화 시각과 함께 알림을 띄웁니다. 로그인에는 Google OAuth를 쓰며, Google Cloud 프로젝트 설정은 자동으로 해 주지 않습니다.

이 계정들의 대화도 대화 동기화에 포함되며, 같은 대화로 재시작해도 원래 계정이 유지됩니다. [대화와 업데이트](conversations.html)를 참고하세요.

## 자격 증명 저장 위치 {#where-credentials-are-stored}

macOS에서 Kiln은 저장된 자격 증명을 키체인에 보관하며, 키체인을 초기화하거나 교체하지 않습니다. Windows에서는 저장된 자격 증명을 Windows 사용자 키로 보호되는 비공개 파일에 보관합니다. 계정 목록에는 프로필 이름과 메타데이터만 들어 있고, 액세스 토큰이나 리프레시 토큰은 들어 있지 않습니다. 로그인 링크와 코드는 설정이나 로그에 남기지 않습니다.

## 문제 해결 {#troubleshooting}

- **로그인이 실패할 때:** 브라우저와 네트워크 연결을 확인한 뒤 다시 시도하세요.
- **CLI를 찾을 수 없을 때:** CLI가 없으면 계정 카드에 표시됩니다. 해당 에이전트의 공식 CLI를 설치하세요.

CLI 자체를 업데이트하는 방법은 [대화와 업데이트](conversations.html#cli-updates)를 참고하세요.
