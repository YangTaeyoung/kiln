# Kiln Remote API v1

The authoritative TypeScript wire contract is [v1.ts](v1.ts). JSON fixtures in
[fixtures](fixtures/) are inert examples; they establish no inference or tool execution.
The optional host is version **0.1.0**. Native Kiln source/CLI remains **0.3.0**.

## Connection and boundary

Every data route requires `Authorization: Bearer <per-launch token>`. Token lifetime
is at most eight hours. The pairing file is private and must never become a log,
URL parameter, checked-in fixture, analytics event, or default persistent app storage.
Disconnect clears the app's in-memory capability. Graceful host exit removes its
pairing file and disconnects readers; it leaves native daemon/workers running.
An abrupt process kill can leave an inert pairing file: remove it explicitly before
restarting. Its token cannot authenticate another launch.

The listener rejects non-loopback addresses. `Host` must equal the selected loopback
address/port, `localhost:port`, `127.0.0.1:port`, or Android emulator
`10.0.2.2:port`. An owner-operated HTTPS proxy must rewrite upstream Host to the
actual loopback authority. Origins are exactly `capacitor://localhost`,
`https://localhost`, and `http://localhost`, plus one optional explicit loopback
HTTP `--dev-origin`. There is no credential wildcard. Native apps may omit Origin.
OPTIONS performs Host/Origin checks and returns CORS metadata without touching
projects/sessions; actual GET/POST always authenticates.

POST content type is `application/json` (optional charset). Bodies are bounded
before deserialization: 128 KiB, or 28 MiB + 4 KiB for the separate base64-image
route. Each authenticated request has a five-second deadline including body read.
There are at most 32 concurrent requests, 16 active native conversation readers,
four preparations, 200 entries per snapshot, and 2 MiB per snapshot. Images must
have a matching PNG/JPEG/GIF/WebP signature/MIME, with at most 20 MiB decoded bytes.
Text is at most 120,000 UTF-8 bytes. Snapshot `coverage.truncated` and approval
`respondable` distinguish safe partial reading from complete approval review.

Errors have the stable form `{"error":{"code":"...","message":"..."}}`. Messages
never contain native diagnostics/configuration/environment. Codes include
`unauthorized` (401), `invalid_origin`/`invalid_host` (403),
`content_type` (415), `body_limit` (413), `request_deadline` (408),
`stale_generation`, `catching_up`, `configuration_pending`, `incomplete_approval`,
`request_id_conflict` (409), `reader_limit`/`request_limit`/`request_cache_full` (429),
and `native_unavailable` (503). Unknown/out-of-scope conversations return the same
`conversation_unavailable` (404). Missing/expired operations return
`operation_expired` (404); this never authorizes replay.

## Mutations and actual settlement

Every POST supplies a unique ASCII alphanumeric/hyphen `request_id` of 1–128 bytes.
IDs are global across mutation routes in this host launch. A route plus canonical
JSON payload fingerprint reserves the ID **before** native work. The same ID and
payload returns the original HTTP status/body; a changed payload or endpoint
returns 409 without dispatch. Pending preparation returns the original operation
receipt even after completion; read its operation URL to obtain the result.
Concurrent duplicates of synchronous commands wait for the same stored response.

At most 1,024 results remain for ten minutes from registration. Pending operations
are never evicted; a full cache refuses new IDs. Every receipt advertises
`retention_seconds: 600`. After expiry/host restart the server cannot recognize an
old mutation ID: the app must show unknown delivery and **must never automatically
retry mutations, recreate a task, or resend a prompt**. Polling GET operation and
snapshot routes is safe. A timed-out HTTP request may still finish as its single
tracked operation; it must not start an untracked replacement.

A command receipt's `delivery: "queued"` and actual `command_id` establish only
native queue registration. Operation `succeeded` for a command has that same narrow
meaning. Follow `snapshot.commands[command_id]` for native
Queued/Dispatched/Accepted/Rejected/Unconfirmed and `uncertain_deliveries` for the
native reader/writer uncertainty overlay. Creation `succeeded` means daemon Create
returned its terminal ID; provider readiness still comes from the snapshot.
`unknown` operations require computer review, never a new automatic command.

Snapshots are reduced from actual native envelopes using Transcript::apply. A
bounded replay may report `replay_ready: false`; do not infer readiness from an old
Ready lifecycle. Generation is mandatory for every command and stale generations
never dispatch. Interrupt uses the **literal string `"Interrupt"`**, and stays
available during ordinary configuration settlement/catching up when a generation
is known. Submit/configuration waits for current replay and native settlement.
`controls.outcomes` retains requested/effective values and
Pending/Applied/Acknowledged/Rejected/Cancelled/Unconfirmed plus `settled`; these
are distinct from transport receipts and must remain distinct in the interface.

## Routes

| Method/path | Request | Response |
| --- | --- | --- |
| GET `/v1/bootstrap` | — | `Bootstrap` |
| GET `/v1/conversations` | — | `ConversationList` (up to 200; no raw paths/config) |
| POST `/v1/conversations` | `CreateConversation` | 202 `PendingReceipt` |
| GET `/v1/operations/{request_id}` | — | `Operation` |
| GET `/v1/conversations/{id}` | — | `Snapshot` |
| POST `/v1/conversations/{id}/commands` | `CommandRequest` | 202 `CommandReceipt`, or stable error |
| POST `/v1/conversations/{id}/attachments` | `Upload` | 202 `UploadReceipt`, or stable error |
| GET `/v1/terminals` | — | `TerminalList` |
| GET `/v1/terminals/{id}` | — | `Terminal` |
| POST `/v1/terminals/{id}/input` | `TerminalInput` | 202 `InputReceipt`, or stable error |

Providers use native lowercase strings: `claude`, `codex`, `antigravity`.
LaunchOptions and Command retain native serde externally tagged enums. For example:

```json
{"request_id":"create-1","workspace_id":"workspace-1","provider":"claude","launch_options":"Inherited"}
```

```json
{"request_id":"send-1","generation":"from-current-snapshot","command":{"Submit":{"text":"Explicit user task","attachments":[],"model":null}}}
```

```json
{"request_id":"allow-1","generation":"from-current-snapshot","command":{"Respond":{"request_id":"live-native-request-id","decision":"Allow","answers":{}}}}
```

Attachment arrays contain only server-issued opaque IDs, never native paths.
Immutable imported native Attachment values stay on the host. Upload accepts only
filename/MIME/base64; slash/backslash/NUL paths are rejected, staging is private and
RAII-cleaned on every outcome. Upload results deduplicate to the same actual image.

A descriptor identifies provider/workspace/account display label. It deliberately
omits cwd, program, environment, provider session identity, credentials, and raw
configuration. Listing does not load AccountManager or poll usage. Enabled workspace
IDs are host-launch-scoped; the app refreshes them on pairing. Creation accepts only
an enabled workspace ID, typed launch options, and no executable or initial prompt.
Additional native launch folders must fall within enabled canonical folders.

## Complete approval and control coverage

Model/tool text, Markdown, HTML-like strings, diffs and arguments are untrusted
**data**. The app renders escaped text or sanitized Markdown; do not run HTML,
remote scripts/fonts, embedded URLs or shell commands. Per-field truncation and
whole-snapshot trimming are explicit. Approval requests retain their entire bounded
native details/questions/options, or set `respondable:false` with a computer-review
reason. Both UI and API refuse every Respond to incomplete details. Even a Deny or
Cancel is refused in this state; Interrupt remains explicit and available.

`ControlOption.available` and `scope` retain native semantics.
`mobile_supported`/`mobile_reason` describe the narrower v1 mobile editor:
Live Select/Boolean/Text/Integer/Strings/Default values are validated against actual
advertised options. Inherited/Managed/NewConversation/Terminal and unsupported,
Sandbox or GranularApproval live controls remain visible and read-only on mobile.
Native Sandbox/GranularApproval values remain typed in the wire schema so the app
can accurately display actual native state.

NativeAction, Restart and structured PermissionGrant are explicitly rejected with
`unsupported_mobile_action` / `unsupported_mobile_decision` in this first API.
They must not appear as working controls. Discovery, existing mode selection,
SubmitWithSkills (exact advertised enabled name/path) and one-time Allow/Deny,
Cancel/questions are supported. Commands/skills discovery inserts a local draft;
it never implicitly submits or executes a command. Native Option decisions must
match a complete advertised request option; the UI must show its exact description
and permission scope before explicit selection.

Terminal IDs come only from existing daemon sessions within enabled folders.
Reading is bounded to 200 history lines/120,000 bytes and exposes `exited`.
Input is explicit text plus an optional Enter; it creates no arbitrary program,
terminal, shutdown, restart or daemon-upgrade route. A queued terminal input receipt
is not command execution completion.

## Retained native storage and work ownership (review fix 1)

The companion opts into the shared native `Client::connect_hardened`; ordinary
desktop `Client::connect` keeps its prior defaults. The opt-in path retains directory
and file identities, performs actual journal/marker/lock/mailbox I/O relative to
those fds with `O_NOFOLLOW|O_NONBLOCK`, rejects changed files/directories, and checks
again before exposing queued envelopes or accepting a command. A replaced journal
is read-only/unavailable; retained readable history stays visible. The controller
reuses the native reducer and command wire rather than reconstructing a runtime.

Conversation list rows include `title: string|null`, `lifecycle: Lifecycle|null`,
and `summary: {partial, unavailable}`. Titles derive from the first retained native
user message (first line, at most 160 characters/640 bytes), never generated names.
A summary reads at most 256 native envelopes/256 KiB without allocating a persistent
conversation reader. Partial/unavailable history has no asserted current lifecycle;
its title is null when the bounded native prefix contains none. The overall listing
still retains at most 200 rows and reports scan truncation. Snapshots remain the
authority for replay readiness, live controls and command settlement.

HTTP request/upload capacity is owned by actual work, including work still running
after the five-second HTTP response deadline. Same-binary local helpers isolate
potentially blocking native account preparation and daemon connect/Hello/request
I/O: preparation has a 30-second wall deadline; a daemon helper has eight seconds.
They exchange bounded private stdin/stdout JSON, inherit the owner's selected
native environment, and expose no program/socket/helper endpoint to the network.
At shutdown only those directly created helper process groups are cancelled/reaped;
the native daemon and reusable inference workers are never terminated by the host.
Shutdown cancels helpers, drains actual work for up to two seconds after HTTP drain,
and bounds runtime teardown. A helper lost after possible Create/Input dispatch is
`unknown` delivery under the original request ID; it is never a definite failed
non-effect and must not be automatically replayed. Queued native Input additionally
uses native Ping to flush that same writer; it still proves no terminal execution.

Startup enabled folders and every requested additional launch directory retain
identity guards. Both the parent after preparation and the daemon helper after
Hello validate them immediately before Create. A changed/symlinked/replaced folder
fails the tracked operation with no Create. The unchanged daemon still accepts a
pathname-based SpawnSpec: replacement *after* that final guard and before the
daemon's OS spawn remains a native handoff boundary. This delivery does not claim
that pathname checks eliminate that final check-to-spawn race or modify the daemon
protocol/protected published CLI to do so.

A transport-level 408 is not a settled mutation result. If the owned work later
settles, GET operation exposes its actual result/unknown delivery and an explicitly
requested duplicate receives that original settled mutation result. The app still
never retries the POST automatically after 408 or a lost connection.
