# Native agent GUI implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development or superpowers:executing-plans to implement task-by-task. Steps use checkbox syntax.

**Goal:** Interactive native conversations for all three installed agents, retaining terminal mode and session survival, validated directly in the native app.

**Architecture:** A persistent daemon-owned PTY anchors a structured-agent worker.
The worker speaks each provider protocol and publishes a shared private journal;
native egui panes tail it with background clients. Existing Term panes retain their
session lifecycle, while a GUI overlay renders agent conversations and persists drafts.

**Tech Stack:** Rust 2024, egui 0.36, existing serde_json/crossbeam channels and CLI harnesses. Reuse Kiln's Markdown renderer; add no Node/Python runtime dependency.

**Spec:** `docs/superpowers/specs/2026-11-15-agent-gui-design.md`

## Global Constraints

- All three providers: Claude streaming CLI control protocol, Codex App Server,
  Antigravity ACP; selected account and inherited MCP settings must be preserved.
- Existing terminal panes stay terminals; GUI exit must not terminate the worker.
- Never auto-submit a restored draft, replay a prompt or reuse stale approval IDs.
- No permission bypass flags, secrets in launch records or real-user captures in git.
- Disk/child I/O and parsing run off the GUI thread; bound buffers and event reads.
- Keep private runtime paths under the configured root, validate IDs and use 0700/0600
  on Unix. Preserve Windows session/Job Object ownership and npm launcher handling.
- Native UI proof is required after implementation, for actual task execution.
- Repository docs English; product guide en/ko/ja/zh-CN; visible work reports Korean.

## Review Focus

1. GUI exits during an active task or approval: process survives and reconnects.
2. Duplicate/stale commands or lost acknowledgements: no duplicated prompt or approval.
3. Partial/coalesced JSON, large outputs and early child exit: bounded explicit state.
4. Account switch, MCP inheritance and gateway secrets: original profile remains pinned.
5. Korean composition, image input and narrow panes: no premature submit or clipped controls.

### Task 1: Durable structured runtime and three provider adapters

**Files:** create `crates/kiln/src/app/agent_gui/{mod,model,journal,client,host}.rs`,
`agent_gui/providers/{mod,claude,codex,antigravity}.rs`; wire one module declaration
in `app/mod.rs` and the hidden CLI entry in `cli.rs`. Tests alongside the modules.

**Interfaces:** Produce all runtime/shared interfaces named in the spec: prepare,
descriptor, serve, Descriptor, Client, Command, Envelope and Transcript. Serialize
public events/commands so protocol fixtures can drive the same implementation.
No UI rendering or product menu changes in this task. Export the types Task 2 needs.

- [ ] Step 1: Write failing reducer/journal tests for exact-once envelopes, stream
  upserts, stale approval rejection, generation reset and restored drafts not sent.
  Assert tool IDs, outputs and provider session IDs survive replay without duplication.
- [ ] Step 2: Implement private descriptor/config/journal/command transport, background
  Client and persistent host under the existing daemon PTY. Add a private host lock,
  explicit EOF/error lifecycle, cancellation and bounded I/O. Keep resolved connection
  environment values only in the final child process; use existing account validation
  and `agent_launch::launcher` when constructing the child.
- [ ] Step 3: Implement Claude, Codex and ACP adapters against their real contracts.
  Read official sources and `/tmp/kiln-agent-gui-references` (Claude Python transport
  and generated installed Codex JSON schemas). Include initialization, model choices,
  turns, text/tool/diff events, approvals/questions, interruption and native resume.
- [ ] Step 4: Add scripted subprocess fixtures for each provider. Assert the fixture
  receives the actual expected response before emitting its successful tool result.
  Test permission denial, unknown requests, split JSON reads, interrupted turns and
  worker reconnect. Never model success from a text substring alone.
- [ ] Step 5: Run focused module tests and `cargo check --locked -p kiln`; inspect the
  diff for credentials and ownership regressions; commit explicit files and report.

### Task 2: Native conversation UI, launch integration and persistence

**Files:** create `agent_gui/{view,view_tests}.rs`; modify app `mod.rs`, `ui.rs`,
`state.rs`, `settings.rs`, and `agent_gui/mod.rs`; expose the existing Markdown
renderer from `kiln-git` with a small public wrapper. Update locales and guide docs.

**Interfaces:** Consume Task 1's Descriptor/Client/Transcript/Command. Produce
AgentPane with from_spec/tick/ui/draft methods, GUI mode selection and optional
draft persistence. Derive pane runtime identity from `KILN_GUI_AGENT`/`KILN_GUI_TOOL`
on saved spawn specs; do not replace PaneKind or the existing PTY lifecycle.

- [ ] Step 1: Write a failing egui test for choosing GUI mode, entering a task,
  receiving streamed text/tool state, responding to approval, and Stop. Include
  Korean preedit/commit, image attachment chips and a 520px viewport.
- [ ] Step 2: Build the native view using the chosen design and existing themes.
  Render cached Markdown, expandable tool cards, file diff, inline typed questions,
  real supported models, pinned account identity, multiline composer and attachments.
  Controls must have accessible names and usable keyboard focus in dark/light themes.
- [ ] Step 3: Add persisted GUI/Terminal mode to New Task/split menus. New agent
  menu launches use the selected mode; existing Action::DirectAgent semantics and
  all saved terminal panes remain terminal. Route workspace task submission through
  GUI prepare when selected. Preserve initial prompt contents and exact-once send.
- [ ] Step 4: Add the agent-view overlay for existing Term pane sessions, restore
  from launch specs and optional drafts, poll hidden panes and handle explicit
  pane close/restart safely. Show real lifecycle/attention without terminal rendering.
- [ ] Step 5: Update four-language locale catalog and product guides, docs/architecture
  and a new agent GUI user guide. Adapt existing terminal-specific menu tests to
  explicitly select Terminal mode and add positive GUI-default launch tests.
- [ ] Step 6: Run focused view/integration tests, localization/site checks and
  `git diff --check`; commit explicit files, excluding generated review captures.
