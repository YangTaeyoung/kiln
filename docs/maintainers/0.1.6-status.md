# Kiln 0.1.6 verification

## Behavior and review

Account settings now use the shared embedded Codex and Claude SVG marks instead
of independent hand-drawn substitutes. Recognized agents retain their mark in
workspace navigation, task tabs and terminal headers; activity is a separate ring
or badge. Ordinary and exited shells retain ordinary status icons.

Applying a saved Kiln theme explicitly selects egui's matching appearance before
applying its palette and typography. Regression coverage checks all four palettes
against opposite startup appearance and subsequent system appearance changes.

Adaptive focus navigation still depends on available logical space and UI zoom,
not a different operating-system build. Its layout actions are compact icon
buttons. Long task titles truncate inside the remaining selector width, with the
full title and layout behavior available on hover. Switching, restoring splits
and arranging a grid preserve pane identities in the real-PTY regression.

Independent hostile designer and developer DX reviews passed after fixes. Visual
review covered light/dark surfaces, both agent marks and narrow layouts; renderer
checks exercised five pixel densities. Synthetic captures and the owner's private
photograph were not committed.

on PATH; no product logic or test timeout was weakened. The lower-level cause of
that local Homebrew Git delay was not established.

## Native observation and remaining boundaries

The signed production bundle launched with an isolated configuration and socket.
Its first screen, common button icons and live terminal were directly observed.
Native input then returned `noWindowsAvailable`; no settings-button interaction
or production Sparkle relaunch is claimed. The isolated GUI and daemon were
stopped and their temporary root removed.

Stop an isolated GUI before its daemon and await process exit: shutting down a
daemon while a GUI is still reconnecting can spawn a replacement test daemon.
One such empty replacement was identified by its exact temporary socket and
terminated during cleanup. No production daemon was stopped.

The installed real app remains **0.1.5** and was not overwritten while in use.
The other Mac's installation and post-update appearance still need owner
observation. Use Settings → About → Check for Updates, then verify version,
appearance, workspace restoration and a fresh session/PID baseline. Local and CI
tests do not replace that installed-device observation.

The previously reported missing menu-bar icon has no confirmed permanent fix;
see [the 0.1.5 follow-up](0.1.5-status.md#follow-up-installed-015-and-missing-menu-icon).
This release retains the icon asset and companion behavior. Do not attribute its
visibility problem to operating-system builds or helper replacement without
further evidence.

Follow the [release runbook](releases.md). Published artifacts and tags remain
immutable; keep the existing update signing key.
