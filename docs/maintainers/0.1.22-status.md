# Kiln 0.1.22 verification

Includes account-specific sign-in recovery, current credential selection,
local authentication presence checks, responsive CLI version cards, visible
ignored explorer entries and terminal input preservation during handover.

## Source verification

- Isolated account tests: **82 passed**. Two Claude accounts use fresh namespaced
  Keychain credentials despite stale private files and legacy metadata.
- Codex optional email, unsupported authentication material and verified legacy
  Keyring namespaces no longer become inferred logout; quota attribution still
  requires a matching saved identity.
- Reauthentication browser controls, fallback codes and feedback stay below the
  selected account. Actual GPU captures fit 420px at 130% scale in four languages.
- App unit tests: **214 passed, 5 pre-existing ignored**. Installed CLI version
  arrives before a held catalog request; partial replies never trigger restart.
- GUI integration: **45 passed, 1 pre-existing ignored**. Direct terminal launch:
  **1 passed**. Git backend and UI regression suite passed.
- Localization: **2,193 messages**, four languages and **2,002** literal keys;
  checker regression tests: **8 passed**.
- Full editor regression: **227 passed, 2 pre-existing ignored**, including
  **150 unit tests and 12 file-tree UI tests**. Ignored files and folders are visible by default, muted and explicitly
  marked. Coverage includes root changes, manual filtering, inherited exclusion,
  lazy loading, exact file-open events and actual narrow-view GPU captures in
  four languages, including nested folders.
  Dark and light snapshot baselines passed without automatic snapshot updates.
- Independent hostile review covered credential selection, legacy Keyring
  launch/resume, account feedback ownership and actual account, CLI and file-explorer UI captures.
- CI exposed a forced-checkpoint cache bypass during discard-and-quit. Forced
  saves now validate the actual state file even when the in-memory snapshot
  matches the cache; the full GUI suite passed, including the existing failed-save
  regression and recovery-after-retry checks.
- Another CI run timed out waiting for `BURST_DONE` after a mixed-PTY upgrade.
  Source inspection identified a real input race: the asynchronous input worker
  could still hold accepted bytes when host input paused and `exec` discarded
  the old queue. The log alone does not prove this was the only CI cause.
  An ordered delivery barrier now precedes host detach within a shared three-second
  budget; failure cancels handover and retains the queue. Terminal-generated
  replies received during detach are checkpointed separately and replayed before
  new output consumers start. Failed handover requeues them before new user input.
- Daemon regressions: **67 passed**, including controlled blocked IO, an actual
  raw PTY OSC query through restore/cancellation, and a host-protocol fixture
  checking saved reply, fresh query reply and following user input exactly once.
  Unreachable hosts retain their checkpoint and replies; adoption uses pending
  output rather than replaying already-answered historical queries.
- Hosted integration: **3 passed**; hosted failure/rollback/control integration:
  **6 passed**. The real mixed native/hosted migration fixture passed without
  adding a wait between input and Upgrade. Published restore bodies and old
  registry records remain readable; new checkpoints use an optional reply trailer.
- The next CI run exposed one older recovery fixture missing the new optional
  registry fields. Its empty-reply initializer now explicitly covers the legacy
  path. Local terminal recovery **4 passed**, native daemon **10 passed** and
  shell completion **1 passed** with the intended native daemon test mode.
- Tests use only owned temporary directories, fake credentials/processes,
  MemoryStore and loopback HTTP. They do not query real provider accounts.

## Distribution boundary

Source CI and signed distribution verification are pending. This document will
record their actual results after completion. Live provider authentication and
usage responses, and the owner’s Sparkle install/relaunch, are not covered by
isolated fixtures. No installed app, live daemon, terminal session or real
account credential is replaced during validation.

The CLI-card latency checks do not establish launch latency improvements: new
managed agent launches still synchronously wait for credential selection. Hostile
review passes above apply to the specified changed flows.
