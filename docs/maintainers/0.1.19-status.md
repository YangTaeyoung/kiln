# Kiln 0.1.19 verification

## Source and account recovery

Saved profiles now expose **Sign in again** in their account menu. A profile
with removed or incomplete local credentials also shows a direct recovery button.
The official CLI runs browser sign-in in a disposable namespace; successful
same-email authentication stages credentials for explicit **Apply**. Names, IDs,
order and history are kept. A different or unidentifiable browser account is
rejected. Applying sign-in does not restart running terminals.

Local credential presence is checked off the render thread. Network errors and
refreshable access-token expiry do not establish logout. A revoked provider
login that still has local credentials can be repaired from the account menu.
This change does not establish online provider validity or promise a running CLI
will discard previously cached tokens without being resumed.

## Verification

- `kiln-accounts --lib`: **67 passed**. Includes two-tool disposable CLI login,
  profile/runtime preservation until Apply, inactive-profile preservation,
  mismatched/unknown identity rejection, cancellation, and missing-credential
  recovery without treating expiry or network failures as logout.
- First runtime creation cannot bypass Apply for a staged login.
- Full account card and recovery/cancel flow fit 420px at 130% UI scale in
  Korean, English, Japanese and Simplified Chinese. Actual renderer captures
  were reviewed privately and are excluded from Git.
- Localization: **2,181 messages**, four languages; `git diff --check` passed.
- Independent adversarial review found the initial-runtime Apply bypass;
  it was repaired with a regression. Re-review found no additional P1/P2 issue.
- No real account sign-in, token revocation, live terminal interruption or
  installed-app replacement was performed for testing.
