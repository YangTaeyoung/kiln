# Kiln 0.1.9 verification

## Scope

Database structure editing and index inspection; consistent file-language detection,
manual language persistence, local completion and LSP edit/response correctness.
See [database tools](../databases.md), [file editor](../editor.md) and the
[release runbook](releases.md).

## Source and functional evidence

- Isolated SQLite plus PostgreSQL 16, MySQL 8.4 and MariaDB 11.4: schema changes,
  index metadata, preserved constraints/data, rollback and stale-plan rejection.
- SQLite GUI flow: preview never executes, explicit reviewed apply, column/default
  and data refresh, index metadata, renamed target, draft restoration, exact-name
  delete gating, deletion result and foreign-key failure preserving original rows.
- SQLite rebuild fixtures: generated columns, hidden rowids and INTEGER PK DESC,
  AUTOINCREMENT high-water mark, named constraints, FK SET NULL/DEFAULT, views,
  triggers, expression/partial indexes, STRICT and WITHOUT ROWID.
- Editor suite and targeted final fixture: language detection/manual selection,
  fallback completion, PATH launcher and nested roots, full textEdit/additional
  edits, undo, stale document/caret responses, IME separation and reload. Two real
  rust-analyzer tests are opt-in; do not count them as exercised semantic servers.
- Source persistence: clean/dirty editor language choices, legacy state and current
  renamed DB target. Explorer epoch invalidation preserves expansion state.
- Four languages, light/dark, 420/720px and 130% form checks; short editor popup,
  schema confirmation accessibility labels. Independent review found and closed
  short-popup selection and extensionless shell detection regressions.
- Independent final design/DX review passed after directly inspecting three wide
  and four 420px/130% final captures and closing the name-alignment finding.
- Detector ran once on changed native Rust UI targets and returned no findings.
  This is not proof of native rendering; source and synthetic captures were reviewed.

## Execution interruption

The local execution service temporarily refused process creation with
`Too many open files (os error 24)`. A later test run exhausted disk space.
Execution recovered and only regenerated incremental compilation caches were
removed. The production application, daemon and sessions were not stopped.

Before the interruption, the isolated server runner passed all 13 schema tests
(10 SQLite and 3 actual PostgreSQL/MySQL/MariaDB cases), 9 server backend tests and
7 SQL completion tests. The GUI schema flow passed in both its targeted run and
the full DB rerun. The full DB rerun's two failures were obsolete Columns-tab
labels; updating those fixtures passed `ui_light` (1) and `ui_smoke` (6).
The editor run passed all other targets, with 2 opt-in rust-analyzer tests omitted;
the final short-popup fixture target passed all 3 tests after its AX-only fix.

A final wide-layout review found centered table/column/index names separating them
from their metadata. Explicit left-aligned widget allocation now keeps names and
details on the same start line. The final wide rendering targets passed 7 tests;
the SQLite GUI schema flow passed again. The 420px/130% long-name inspectors were
rendered again in both themes and their action bounds passed.

Local application checks passed: `cargo check`, 161 unit tests (4 intentionally
ignored), 39 GUI/session tests (1 documentation generator ignored), and Git
integration. Localization validated 1,868 messages in four languages and 1,782
literal UI keys; checker regression tests passed. Unrelated regenerated app
captures containing local shell identity are excluded from the public commit.

## Observation boundary

Real user terminals, daemon and agent sessions were not stopped. Headless UI
interaction is not native installed-app verification. No installed 0.1.9 update
round trip has been claimed. Server version-specific or specialized schema changes
outside the forms remain available through reviewed SQL console operations.
