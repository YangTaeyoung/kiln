Verified on 2026-10-15 (macOS Apple Silicon).

- Source: `d013eb6d8d3ca031e416070943c616784135c101`; [PR #12](https://github.com/YangTaeyoung/kiln/pull/12). Exact-source [CI 38730386294](https://github.com/YangTaeyoung/kiln/actions/runs/38730386294) passed both macOS and database-server jobs. PR #12 merged as `0e9838c7dddc11a607870abb275a85a1efe7f16a` with the identical source tree.
- Shell commands from the other CLI are written as native records: Claude Code receives a `Bash` tool use and result for a command run in Codex, and Codex receives a `CommandExecution` history item for a command run in Claude Code. The canonical history and existing projections are unchanged; parallel calls, a pair without a following answer, a Codex command run outside the session directory (for Claude) and other tool kinds keep the readable text form.
- A fresh-context review reported two Important findings, fixed with tests that failed first: parallel calls paired with another call's result, and a native record read without Kiln's annotation splitting the conversation. A Minor finding was re-graded and fixed (a Codex command's working directory missing in Claude).
- Installed CLIs in isolated homes against loopback model endpoints: Claude Code 2.1.300's resume view showed a Codex command as its Bash record ("Listed 1 directory") and its next request carried the `tool_use` with its matching `tool_result`; Codex 0.162.1's resume view showed a Claude command as a command cell ("Ran ls -la └ first second"). Both CLIs continued and the hub ingested both continuations. Codex 0.162.1 drops a `CommandExecution` item whose working directory is a plain path, so it is written as a file URL, as in Codex's own records.
- Local validation: `cargo test -p kiln --lib conversation_sync` (112 passed) and the CI-equivalent macOS suite (24 steps).
