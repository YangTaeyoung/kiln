# Kiln 0.1.14 verification

This release repairs terminal transport and redraw failures without restarting
running shells or agents. See [terminal recovery](../terminal-recovery.md) for
user-visible states, manual recovery and investigation boundaries.

## Reproduction and implementation

Separate regressions reproduced continuously renewed synchronized redraw markers
hiding output, host IPC loss becoming a false child exit, an input worker ending
on transient transport failure, and a busy emulator blocking another panel's
frame publication. The old implementations failed the targeted tests; the fixes
passed. A real hosted relay also reproduced the ordinary resize lock cycle: a
2 MiB input frame under backpressure reserved the emulator and prevented an
independent client's screen query. Releasing the emulator before control writes
restored screen queries and output consumption.

Reattachment consumes buffered output immediately. Control writes run separately,
with serialized resize/redraw operations and no emulator lock held across I/O.
Unix host writes and Hello have deadlines; output decoding remains blocking to
preserve quiet and partially received frames. Damaged framing cannot receive more
input/control messages. Only an incomplete input frame is retried; successfully
written input is not deliberately repeated. Reconnection and termination validate
the original host/child identity.

Recovery detects actual reader/transport liveness, not output inactivity. It is
limited to three automatic attempts and requires stable reader service before
resetting the budget. A failed connection appears in the panel and workspace list.
The running panel's menu also offers manual recovery while reported healthy.
Manual repair requests a redraw and retains the existing session, process,
screen and selection. Logs contain connection state and liveness metadata, not
terminal text.

Independent hostile review corrected frame-publication locking, handshake
identity, reconnect/input backlog ordering, resize locking, repeated Hello/EOF
budget resets, damaged-frame control writes, cancellation identity and the
Windows termination gate. No remaining introduced source or artifact blocker
was reported.

## Boundaries

The previously frozen panel had already been resumed, so its exact cause is not
established. Similar cmux/Codex reports are comparisons, not proof of the same bug.
No real Codex agent was deliberately frozen or restarted. Internal CLI failures
with a healthy PTY can still require the CLI's own resume flow. An incomplete
in-flight output chunk is not byte-perfect replayed. Native Windows named-pipe
cancellation and another Mac's behavior remain unobserved. The signed archive
smoke exercised CLI/daemon startup; native GUI/Sparkle update/relaunch was not
exercised for this release, including the owner's installed app. Server/database opt-in tests are not evidence
of live production backend access.

## Source CI and distribution

The first source CI run exposed an existing immediate shell-exit test race.
`Client::request` discards unrelated broadcasts while awaiting `Created`; the
fixture now holds its owned shell on an explicit input gate until creation
completes. The exact-session/code-7 assertion is retained. The ten-case native
daemon suite and 20 consecutive targeted repetitions passed locally. The failed
CI log records an event timeout, not the precise message ordering.

The next CI run reported a read timeout in the native upgrade fixture. Its
same-PID/same-binary session check could accept the old daemon before exec, so it
did not establish an upgrade boundary. The original fixture passed 100 local
repetitions; the exact phase of that CI failure remains unconfirmed. Success
fixtures now wait for the original connection to close, fail matching upgrade
errors, and retain all PID/screen/input assertions. Caller locations are retained
in native read failures. No read failure is hidden by a reconnect retry. Native,
image and hosted success cases each passed 30 consecutive repetitions; the
ten-case native suite, three-case hosted suite and mixed migration fixture passed.
Independent review confirmed these changes only strengthen tests.

A final hostile review reproduced late recovery events reappearing after exit,
an older live snapshot reviving the same completed process, and closed-panel
health surviving removal. The old source failed deterministic regressions.
The GUI now clears completed/closed health, ignores late or unknown recovery,
refuses repair for completed panels, and preserves completion only for the same
process identity. A genuinely different child remains eligible. Completed
screen data stays intact. Final affected-source verification passed: application
library **189 passed, five opt-in ignored**, GUI **40 passed, one screenshot
regeneration ignored**, actual terminal recovery **four passed**. The earlier
whole-workspace count above precedes these final guards.

## Cleanup

After public verification, Cargo removed 4,730 release-cache files (1.9 GiB).
Five owned extraction/download/installer fixture directories and the superseded
local 0.1.13 archive were removed. Published older releases remain unchanged.
The final 0.1.14 distribution and pinned dependency downloads are retained.
The before/after filesystem measurement recovered approximately 2.25 GiB in this
final cleanup. A childless host from the isolated archive fixture was stopped
only after verifying its owned executable and private endpoint; no real shell,
agent, session daemon or installed app was terminated or replaced.
