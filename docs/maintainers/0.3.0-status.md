## Korean input boundary

An earlier unmodified `83ffa78` renderer run produced `하` in six of six warmed
composer trials; a standard AppKit NSTextField control also produced `하`.
In a later diagnostic run based on `f683075`, the composer produced raw `ㅎㅏㄴ`.
A standard NSTextField under the same later conditions also produced raw `ㅎㅏㄴ`;
returning to the composer did not restore composition in that run.

The later trace established missing preedit and raw jamo delivery before the
composer, but the matching standard-control failure did not isolate a Kiln-specific
cause. Input-source/session/automation conditions remain unresolved. No upstream
retry fix or heuristic jamo recombination was adopted. These were CUA-driven native
key trials, not a verified hand-typing acceptance run. Earlier successes and later
failures are both retained; **full native/physical Korean IME acceptance is not PASS**.
The existing composition/commit no-Send behavior and its source fixtures are a
separate boundary from successful physical composition in every native condition.
