## Verified behavior boundary

Capacity recovery is available while Kiln is open for hook-confirmed, account-pinned Codex panels. Only a recent completed native turn with `server_overloaded` is eligible. The tests simulate this provider error; they do not induce a live provider outage. An old failure in an already-open TUI predating observation is left for manual action. The capacity continuation is a new explicit user turn asking the agent to inspect existing state before repeating actions; it is not a transactional replay of the failed model request.

Codex 0.162.1 restores thread model settings when no explicit model/provider overrides are supplied; Kiln does not add such overrides during recovery. See [upstream resume configuration](https://github.com/openai/codex/blob/rust-v0.162.1/codex-rs/tui/src/app/config_persistence.rs#L31).
