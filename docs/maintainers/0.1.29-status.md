# 0.1.29 release verification

Verified on 2026-10-15 (macOS Apple Silicon).

- Source: `2cfa4f7feb83e6c92dee0e74bb0a57ab8d744da5`; [PR #7](https://github.com/YangTaeyoung/kiln/pull/7). Exact-source [CI 38657083438](https://github.com/YangTaeyoung/kiln/actions/runs/38657083438) passed both macOS and database-server jobs. PR #7 merged as `45af0a3302edff69789050f95011dd720da7170c` with the identical source tree (`48e9d58b`).
- The first CI run failed because two new sync-worker unit tests used the real Codex metadata registry and therefore depended on a locally installed `codex`. The worker now takes its native metadata provider as a type parameter and the tests use a provider that registers nothing.
- Local validation: the CI-equivalent macOS suite (24 steps) including 300 application tests (13 opt-in probes excluded), 68 daemon tests (`KILN_PTY_HOST=0`) and 48 GUI tests (one documentation screenshot ignored). `tests/agent_workflow.rs`, which is not part of CI, was updated to the current launcher and passed.
- Regressions were reproduced on `d37ebfd` before their fixes: a continued copy re-read on every scan, a prompt blocked by a published link alone, a prompt blocked while the scanner held the conversation lock, Amend enabled with nothing to change, and a synced row left waiting after its original was deleted.

## Performance evidence

- A running 0.1.28 GUI measured 3.2 GB RSS (4.7 GB peak footprint) and a sustained 112% CPU. Sampling attributed it to the conversation-sync scan re-reading a 133 MB continued Claude copy and its 796 MB Codex endpoint on every scan; RSS cycled between 1.5 and 3.1 GB every few seconds and a new `codex app-server` started for each scan.
- Synthetic conflict of a 131 MB source and a 66 MB continued copy: repeated scans took 1.06–1.18 s each on `d37ebfd` and 0.14–0.24 ms with this release; the initial sync took 1.08 s and 0.62 s.
- A static 200×60 terminal frame with mixed Korean text cost 0.603 ms of UI-side work on `d37ebfd` and 0.073 ms with this release (cached text shapes are no longer deep-copied by `Shape::translate`).
- One state checkpoint (unbuffered pretty JSON plus two `F_FULLFSYNC` calls) measured about 12 ms on an idle disk; checkpoints are now written off the UI thread.
- Parsing transcripts into JSON values measured +321 MB for a 254 MB file and +935 MB for a 464 MB file, with hundreds of megabytes left dirty after release; scans now run in the `kiln sync-worker` child process.
