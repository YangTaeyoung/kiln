# Completion reference sources

## Docker offline fallback

`crates/kiln/src/app/terminal_completion/docker.json` is a single `Spec` object
generated by `scripts/update-completion-docker.py`. It supplies documented command
structure, descriptions, and local-path annotations to the offline fallback.
Installed CLI discovery can take precedence for available commands and options;
this snapshot does not attest to which plugins, platform features, or daemon API
versions are installed. Localized descriptions can be overlaid separately.

The generator consumes the official machine-readable YAML references, rather
than parsing Markdown option tables or running Docker. The snapshot contains
Engine CLI, Buildx, and Compose references, with documented aliases. It excludes
commands/options marked `hidden`, `deprecated`, `experimental`, or
`experimentalcli`, and descendants of excluded commands. Other Docker plugins
are outside this snapshot.

### Regeneration

PyYAML is a maintainer-only dependency; the application consumes bundled JSON
with serde and needs neither Python nor an additional runtime dependency.
Create a separate environment once:

```sh
python3 -m venv /tmp/kiln-completion-venv
/tmp/kiln-completion-venv/bin/python -m pip install PyYAML==6.0.3
```

Explicitly populate an external source cache from the fixed public commits:

```sh
/tmp/kiln-completion-venv/bin/python scripts/update-completion-docker.py \
  --cache-dir /tmp/kiln-completion-docker --refresh
```

`--refresh` is the only network path. It downloads only the selected reference
and attribution files, checks their Git blob IDs against the pinned tree, and
then verifies the committed aggregate hashes and input counts. It never moves
the pins to a branch head. Without it, a missing or modified cache is an error;
there is no automatic fetch. The default cache directory is
`${XDG_CACHE_HOME:-~/.cache}/kiln/completion-docker`.

Generation and checking are deterministic and offline with that cache:

```sh
/tmp/kiln-completion-venv/bin/python scripts/update-completion-docker.py \
  --cache-dir /tmp/kiln-completion-docker
/tmp/kiln-completion-venv/bin/python scripts/update-completion-docker.py \
  --cache-dir /tmp/kiln-completion-docker --check
```

The script checks/writes only `docker.json` and its sibling
`LICENSE-docker.txt`. `--output /tmp/review/docker.json` changes both destinations
for isolated review. The generator does not invoke a CLI, read Docker
configuration/authentication, inspect containers, execute examples, or query a
daemon. Descriptions and aliases are data. No source refresh runs in the app.

### Conversion and argument annotations

Every stable visible YAML `command` gets a node, including commands omitted
from an upstream `cname` list. Comma-separated, fully qualified documented
`aliases` add equivalent paths. An exact command's definitions take precedence
on conflicts, including explicit exclusion markers. Other stable definitions of
its documented aliases add missing options. This includes modern Buildx build/bake options on their Engine aliases
while preserving options documented for the legacy builder. The fallback thus
covers the documented variants; discovery of the installed binary remains the
source for its actual option availability. Command/option ordering is stable,
with common Docker and Compose commands placed first.

Boolean options have an empty `hint`. Other options use `<string>` unless an
explicit local-path annotation applies. Generic positional arguments, repeated
service/resource names, key/value lists, container commands, and container paths
have no provider or invented value list. The consuming completion layer should
suppress value suggestions when both `values` and `provider` are absent. This
schema has no positional-index or nargs field.

Local-path annotations include:

- Root `docker --config`: directories. This is the actual client config
  directory flag; there is no root `docker --dir`.
- Compose `--project-directory`: directories; `--file`/`-f` and `--env-file`:
  files. Container `--workdir`/`-w` has no local-path provider, including Compose
  exec/run, Docker create/run/exec, and service create/update.
- Documented input/output files, environment/label files, Dockerfiles, metadata
  files, TLS/CA file flags, and the trust signer's public-key file: files.
- Compose bridge output/templates directories and the actual
  `docker trust key generate --dir`: directories.
- Build context positionals for `docker build`, `docker image build`,
  `docker builder build`, `docker buildx build`, and `docker buildx b`: local
  directories. Their YAML usage explicitly accepts `PATH`; URL and stdin forms
  remain manually enterable and are never fetched for suggestions.

Compound expressions such as Buildx `--output type=local,dest=...`, additional
build contexts, cache specifications, mounts, remote endpoints, and resource IDs
are free strings. A flag is never added merely to provide path completion.

`persistent` is inferred from visible `inherited_options` and the nearest
matching ancestor definition. Docker's public root options are **not** marked
persistent: the CLI [installs client options in root `Flags()`](https://github.com/docker/cli/blob/6d274590f2f63276a54da8adf475a455d21c1fdd/cli/cobra.go#L22-L24)
and [stops global parsing at the first command](https://github.com/docker/cli/blob/6d274590f2f63276a54da8adf475a455d21c1fdd/cli/cobra.go#L141-L158).
Only Compose `--dry-run` and Buildx `--builder`/`--debug` are persistent in this
snapshot. Compose [declares its project flags with `Flags()` and dry-run with
`PersistentFlags()`](https://github.com/docker/compose/blob/e18ab3d8797716b565e47b32f0ddb60e052fbbb6/cmd/compose/compose.go#L576-L611);
its [child YAML](https://github.com/docker/compose/blob/e18ab3d8797716b565e47b32f0ddb60e052fbbb6/docs/reference/docker_compose_up.yaml)
lists dry-run as inherited. Inherited options are stored at their owner; an
alias outside that owner's branch receives a local copy when needed.

`--check` verifies source counts/hashes, output counts, complete source
command/option membership, exclusion markers, command/option shape,
duplicate spellings, representative literal membership (`--config`, `--file`,
`--env-file`, `--project-directory`, `--detach`/`-d`), real versus invented
`--dir`, generic values, inheritance, all container `--workdir` providers, and
byte-for-byte equality of JSON and attribution output. When advancing pins,
review the source changes and license notices, update the source hashes and
reviewed output counts in the script, regenerate, and update this section.

### Installed CLI smoke check

The default discovery tests use disposable executable fixtures. The optional
macOS check also probes `/usr/bin/open` and Docker Desktop when installed:

```sh
cargo test -p kiln --lib installed_macos_open_and_docker_desktop_help -- --ignored --test-threads=1
```

Run it separately from CPU-heavy suites because it exercises the same one-second
probe deadline as the application. A busy or configuration-dependent host CLI
can use the bundled fallback without making normal completion unavailable.
