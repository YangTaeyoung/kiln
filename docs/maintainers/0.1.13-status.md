# Kiln 0.1.13 verification

This release switches newly opened macOS panels to persistent PTY hosts while
preserving previously created native panels. The signed release and stable update
feed are published; source, artifact and independent checks are recorded below.

## Reproduction and implementation

The affected Mac's original retained daemon reproduced the local TCP failure.
Terminal.app worked. A separately signed, registered review app returned node
data from the same cluster through a new hosted panel, both by direct command
and through `/bin/sh`. This is a read-only local-cluster observation, not evidence
of an installed update or behavior on every Mac.

A controlled owner/child experiment showed that responsibility can fall back
when the original GUI exits. New owners claim their own responsibility before
threads or terminal restoration using same-PID SETEXEC and dynamically resolved
`responsibility_spawnattrs_setdisclaim`. This is private SPI, not an Apple
permission-status API. If unavailable, startup logs the error and keeps its
normal path. [Apple TN3179](https://developer.apple.com/documentation/technotes/tn3179-understanding-local-network-privacy)
explains responsible-code attribution; [Chromium's launcher](https://chromium.googlesource.com/chromium/src/+/main/base/process/launch_mac.cc)
is the reference for the SPI's spawn-attribute ABI.

Responsibility alone did not repair the observed native-daemon connection.
The existing hosted architecture passed the actual command checks and is now
the default on macOS. Native sessions remain with their original daemon and
masters. Mixed-session upgrades use a same-PID V3 restore format, retaining
native parenthood and hosted endpoints. All-hosted handover retains its existing
successor-daemon path. V1/V2 state remains readable.

Host input writes have their own queue so a child that stops reading stdin does
not block resize, detach or kill. Upgrades wait for ordered output through the
Detach acknowledgement and cancel after three seconds if readers cannot pause.
Failed upgrades reconnect the existing shared writer, resume state monitoring,
and serialize reader reservations with the next upgrade. Closing a panel cancels
pending recovery and sends termination through a newly attached connection too.
Foreground identity is replayed at attachment even when the job has not changed.
Completed hosted screens survive after their owner exits. An unreachable optional
host cannot abort inherited-native restoration; its registry record is retained
through subsequent updates without signalling an unverified process.

## Local verification

- Application unit tests: 184 passed, five opt-in cases ignored.
- GUI integration with the macOS host default: 40 passed, one screenshot regeneration case ignored.
- Daemon library: 39 passed in native mode; responsibility subprocess checks passed.
- Native daemon integration: 10 passed. Hosted integration: three passed.
- Hosted failure regressions: six passed, covering blocked input, state-write
  failure, executable permission failure and unchanged foreground PID after handover.
  A real socket proxy also held Attach/Hello to verify close during reconnect
  terminates the actual child, and a second upgrade safely cancels while a reader
  reservation is in flight. Removing that reservation guard made the latter
  regression fail; the restored guard passed.
- Independent V2 consumer fixture passed native-to-mixed migration, 2,000 queued
  output lines, resize, shared-writer rollback and native exit-code ownership.
  It also passed completed-host history and missing-host isolation with another
  successful update retaining the recovery record.
- Interrupted synchronized redraw recovery passed in both PTY modes.
- Privacy bundle checks: four Python regressions passed; localization validated
  2,007 messages and 1,899 literal UI keys in all four languages.

A separate private daemon started with the installed 0.1.12 executable and was
upgraded with the exact notarized 0.1.13 app. Its daemon PID, native shell PID and
input survived. New panels used hosts with no environment override. Another
mixed upgrade retained both shell PIDs, input and exit code 42. The final
notarized app also returned cluster nodes through direct and shell-hosted panels;
both commands exited 0. This fixture did not replace or terminate the installed app.

Independent hostile review caught mixed-native loss, optional-host restore
failure, blocked control input, missing foreground replay, monitor shutdown,
reader reservation races and pending-recovery/close races. These were corrected;
the six failure regressions passed. Final source/artifact review is recorded
with distribution evidence below.

## Boundaries

After updating, open a **new panel** to retry an affected command. Existing shells
are preserved but their historical attribution chain is not retroactively repaired.
No production shell/daemon is restarted, no consent store is reset and no privacy
protection is disabled. A displayed permission switch is not an authorization
verdict for every background process. Fresh-account denial remains unobserved.
Native permission behavior on other macOS releases and the owner's installed
Sparkle update/relaunch require separate observation. The source CI runner uses
macOS 14 and cannot establish macOS 15+ native privacy behavior.

## Installer

The one-line installer was exercised against the official 0.1.12 release in an
owned temporary installation directory. Checksum, signer, bundle identity and
Gatekeeper checks passed; a second run retained the existing app unchanged.
After publication the README command installed public 0.1.13 into another owned
directory, and the existing-app path again preserved its bytes.
Independent review reproduced an installation race with the original move
target. Moving into the parent directory with no-clobber avoids nesting an app
inside a concurrently installed app. The README links the official script.

## Cleanup

The release compiler cache was removed after public verification: Cargo reported
4,705 files and 1.8 GiB. The project now measures 266 MiB, including the latest
0.1.13 distribution and pinned dependency downloads. The older local 0.1.12
archive was removed; published releases remain unchanged. Finished diagnostic
apps, temporary downloads and installer copies were removed, while verification
summaries and the final distribution were retained. The installed Kiln app and
its running sessions were not replaced or terminated.
