# 0.2.0 release verification

Verified on 2026-10-18 (macOS Apple Silicon, and a Windows 11 ARM64 virtual machine).

- Source: `9c4e714136fffbd38105fa6be75fab8884e0fcb3`, the merge of [PR #14](https://github.com/YangTaeyoung/kiln/pull/14), whose tree equals the tested head `8c5309dc07a64caa7db52f4c6efa2f7b5190961b`. [CI 39026434703](https://github.com/YangTaeyoung/kiln/actions/runs/39026434703) passed the macOS, database-server, `windows-x64` and `windows-arm64` jobs on that head; the `windows-x64` job was rerun after `object_profile_ui` timed out waiting for a provider option.
- CI on the merge commit ([39033386087](https://github.com/YangTaeyoung/kiln/actions/runs/39033386087)) failed two tests that passed on the same tree: `hosted_state_write_failure_restores_input_and_live_monitoring` on macOS (the foreground `sleep` was not observed within 5 s) and `same_directory_named_workspaces_create_choose_restore_and_close_independently` on `windows-x64` (Git Bash received `rintf` for `printf`). In the VM, Git Bash in a Git repository kept every character typed at once, 300 ms and 1–3 s after start, and with focus reports sent before or with the input.
- Windows parity: terminals in ConPTY under per-terminal hosts, PowerShell and cmd integration, native Codex and Claude Code with hooks and cross-CLI resume, DPAPI-protected account snapshots, Windows OpenSSH SFTP, toasts, the notification-area companion, one GUI per daemon, `install.ps1`, signed `appcast-windows.xml` updates. The [Windows support](../windows-parity.md) page lists the test or VM scenario behind each feature.
- A final review reported seven Important findings, each fixed with a test that failed first: feed versions that are not plain release numbers, PowerShell prompt status and line-reader chaining, npm `.cmd` launchers, window applications closed with a terminal, share and mapped-drive folders, the companion after Explorer restarts, and a second GUI per daemon. The installer now keeps the user `Path` value type and unexpanded entries and picks the archive from `IsWow64Process2`.
- Runner fixes: PowerShell takes 20–60 s to start on `windows-11-arm`, so shell waits allow 120 s on Windows; the runner account is the built-in Administrator (SDDL alias `LA`) and its `TEMP` uses 8.3 names.

## Publication

- [0.2.0](https://github.com/YangTaeyoung/kiln/releases/tag/v0.2.0) was published as the latest stable release (2026-10-18T01:07:52Z) after its six draft assets matched the local files byte-for-byte. The release page links the Windows support page by absolute URL. Anonymous public downloads matched again and passed checksum, Sparkle signature (all three archives), code signature, stapling and Gatekeeper checks; the extracted macOS executable matched the verified build. `releases/latest/download/appcast.xml` and `appcast-windows.xml` served 0.2.0.
- The public macOS installer installed 0.2.0 into an owned empty folder with the verified executable; its second run left all 190 paths, sizes and timestamps unchanged.
- In the VM, the public `install.ps1` installed 0.2.0 ARM64 into `%LOCALAPPDATA%\Programs\Kiln` with `Kiln.exe` matching the archive, kept the user `Path` as `REG_EXPAND_SZ` with its `%USERPROFILE%` entry, added the Start-menu shortcut, and its second run left all 5 paths unchanged. Kiln started from the shortcut, restored the VM's workspaces and ran its daemon from the 0.2.0 binary.
- Not yet observed: the owner's installed Mac app updating through Sparkle, Windows x64 on native hardware (CI and emulation only), and Windows 10. The SignPath Foundation application has not been submitted; the release workflow keeps the signing step ready.
