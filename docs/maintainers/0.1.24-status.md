# Kiln 0.1.24 verification

Fixes conversation discovery for sessions opened before Kiln's lifecycle hooks
existed, and ordinary CLI sessions stored outside a connected account namespace.
Explicitly linked workspace folders and their subfolders define the scope. The initial batch
is the 20 most recently modified conversations per workspace, combining both
tools. Later new/modified conversations continue to synchronize.

## Source and interaction checks

- Application library: 238 passed, 11 opt-in helpers ignored.
  The final synchronization suite has 24 passing tests and six opt-in helpers.
- GUI integration: 46 passed, one ignored. Generated terminal captures were
  excluded from the commit.
- `cargo check --locked -p kiln`, `cargo test -p kiln-git`, localization coverage
  (2241 messages, 2036 literal UI keys), and `git diff --check` passed.
- Regressions cover no-hook discovery of pre-existing sessions, default and
  connected namespaces, exact folder/child boundaries, neighboring folders,
  closing workspaces, fixed initial batches, later edits to older sessions,
  adding another workspace, restart/idempotence, symlinks, subagents, unsupported
  versions, dual-destination partial failure and durable publication recovery.
- Workspace context menus enable linking only after both saved accounts are ready.
  Existing global settings migrate with every workspace unselected. Selection
  persists across restore; another folder stays unlinked. Same-folder workspaces
  share the folder selection. Status icons open a workspace-filtered dialog.
  Canonical workspace assignment keeps aliased working directories visible.
  Cancellation discards stale worker results. Isolated GUI interaction exercises
  disabled menus, link, restore, icon click, status details and unlink. The status
  modal blocks underlying workspace shortcuts and restores terminal focus on close.
- Rendered egui checks distinguish discovery, empty folders, completed batches,
  paused synchronization and failures. Original transcripts stay unchanged.
- Native CLI checks used installed Codex 0.162.1 and Claude Code 2.1.296 with
  synthetic histories, owned temporary roots, dummy keys and loopback inference.
  The production workspace scanner discovered histories without hooks and made
  both continuations. Both CLIs resumed them and sent the exact original user
  and assistant messages (including line breaks/code) in the next request.
  The production parser then read each CLI's newly appended response and synced
  both continuations back, with zero additional copies on the next scan.
- Found and fixed a native Codex indexing gap: an existing picker database could
  omit a newly written JSONL file. After publication the worker uses the native
  `thread/read` metadata API before reporting success. Tests cover bounded IO,
  cancellation, redacted errors, registration failure/retry, and real installed
  Codex metadata registration/listing in an existing isolated database.
- Interactive CLI checks showed the imported history in Claude's native picker
  and ordinary user/assistant display. Codex's picker refreshed after metadata
  registration, and selected transcripts rendered ordinary user/assistant items.

## Boundaries

Transcript adapters and native visible-item rendering are unchanged from
[0.1.23](0.1.23-status.md). This release does not claim live paid-provider inference,
hot replacement of open CLI contexts, image/attachment support, arbitrary old CLI
versions, or a successful migration of every personal transcript. Unsupported
history is shown with its reason, rather than silently dropped or called synced.
