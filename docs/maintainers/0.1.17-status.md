# Kiln 0.1.17 verification

Remote connections now own their folder navigation in the workspace inspector.
Saved rows show the provider mark, connection name, bucket/host and current path.
Connecting or entering a folder preserves the main terminal. Selecting a file
opens an independent main editor keyed by its connection, endpoint snapshot and
exact remote path. See [object storage](../object-storage.md) and
[remote-file verification](remote-files-verification.md).

## Interaction and review

The navigation/editor split follows the linked VS Code Remote SSH and Transmit
interaction references. A folder uses a double-click or its Open Folder action;
a file opens with one click. The fixed full-width filter row keeps the listing
stationary when selection exposes additional actions. Upload, download, rename,
delete and folder creation remain in the inspector.

An independent hostile source review caught cached credentials after connection
removal, overly broad close guards, changed-endpoint queued writes and recovered
operation notices. Those findings were fixed before release. The final rendered
review inspected three regenerated actual-app captures: folder navigation in the
dark theme and two independent file tabs in both themes. It confirmed stable
filter/list geometry, visible provider/bucket/path identity, separate main editors,
and readable selection/edit/save controls. Private captures are not published.
This is not a review of every resolution or real cloud account.

## Local checks

- Remote library: 87 passed, serial execution.
- Application library: 197 passed; five opt-in fixtures remained ignored.
- GUI: 44 passed; one public screenshot-regeneration fixture remained ignored.
- The production-app remote inspector integration passed against an owned,
  synthetic loopback S3-compatible HTTP fixture. It verified folder double-click,
  unchanged terminal layout, selection geometry, independent editor identities,
  an exact-object save and no write to the unrelated file.
- Checkpoint restoration preserved edited text and made no remote write. Explicit
  credential reconnection did not reread or overwrite that restored draft.
- A held upload continued while the inspector was hidden. An unrelated editor
  could close, while workspace close and application quit stayed guarded until
  the transfer completed and the navigator refreshed.
- Localization validated 2,151 messages in four languages and 1,967 literal UI
  keys. The localization checker tests and `git diff --check` passed.

Unit coverage also rejects changed endpoints before queued operations dispatch,
cleans removed idle navigators, retains pending notices across checkpoints, and
migrates older directory tabs into the inspector. Recovery restores navigation
and edited text; it does not replay saved remote operations.

The cloud tests use fixture-only credentials and owned objects. Live AWS/OCI/GCS/R2
accounts, real SSH/FTP hosts, provider ACLs and installed-device update/relaunch
were not exercised for this change. Existing protocol coverage is documented in
the remote-file guide rather than counted again here.
